    Beta. A first public test of Inga in the browser:
    pick a model, chat, run the Standard test (Tests and report), then press "Report on GitHub" there (what works
    and what does not: the beta's guide).
    
    
    An experiment: Inga compiled to WebAssembly, running on this device's CPU (WebAssembly
    SIMD; one thread, or every core when the page is cross-origin isolated), or with its layers on the GPU
    through WebGPU (Settings, Device: experimental). A model larger than the tab's memory runs with part of it
    read from this site's storage at every token. Nothing is sent anywhere: the model runs in this page. Tested in
    headless Chromium on Linux and in Safari on an iPhone 16 Pro.
    
    
    
      
    Model catalog
    
      
    
        About fifty GGUF models on Hugging Face that Inga runs (Llama, Qwen,
        Gemma, Phi, Mistral, DeepSeek R1 distills…), each quantization marked by whether it fits this browser.
        
      
    
    
    
    
    
      
    Test models 
    
      
    A fixed list, for runs that compare: downloaded once from Hugging Face into this site's
      private storage (OPFS); an interrupted download resumes. Where "Get" is blocked (a preview frame), "Save
      file" saves it and option 2 below loads it: a picked file is stored under its own name, which must be the
      list's file name for "stored ✓" to show.

        Answers
        
      
        Preset
        
        
        
        
      
        
        0 always takes the likeliest token (the same answer every time); higher is more varied.
        
      
        
        Draws among the likeliest tokens whose probabilities add up to this (1: all).
        
      
        
        Draws among this many likeliest tokens (0: no limit).
        
      
        
        Leaves out tokens less likely than this fraction of the likeliest one.
        
      
        
        Above 1, tokens of the last 64 are less likely again (1: off).
        
      
        
        Subtracted from every token already in the answer: new topics (0: off).
        
      
        
        Subtracted for each time a token appeared: fewer repetitions (0: off).
        
      
        
        Empty: a new random seed for each answer, so asking again can answer differently. A number: the same seed every time (the same question and settings give the same answer). The seed of each answer is shown under it.
        
      
        
        The longest answer, reasoning included. 1024 by default; left at it, a model that thinks gets at
        least 2048 while Think is on (its reasoning alone often takes more than 1024 tokens); a value you set is used as it is.
        
    
        
    
        
      
        Conversation
        
      
        System prompt
        
        
        
        Given to the model before the conversation, through its chat template.
        
      
        
        How many of the conversation's last messages go with each question (0: all of them, as long as the context holds them).
        
      
        Process ahead
        
        
        While the model is idle, a new or reopened conversation's system prompt and messages are processed before you send the question, so its answer starts with only the question to read. Off by default: not measured yet. Not on the GPU.
        
      
        
    
        
    
        
      
        Model loading
        
      
        
        Tokens the model keeps (the KV cache): the conversation, the question and the answer must fit.
        Empty: Auto, the context the model was trained for (its GGUF's context length), lowered only when its KV
        cache would take more than half of the memory the weights leave (the GPU memory limit on the GPU, else the
        memory limit, at most WebAssembly's 4 GiB), and never below 2048 unless memory forces it; the field then
        shows what Auto chose for the model loaded. A number set here wins.
        Applies when you leave Settings (the model reloads).
        
      
        
        
        
        Applies when you leave Settings (the model reloads).
        How the KV cache stores keys and values: F16 (2 bytes a value), Q8_0 (about half),
        Q4_0 (about a quarter, less exact). Auto: F16 when the model's whole context fits, else Q8_0, and only then a
        shorter context. On the GPU the cache is F16 (its layers have no other); the CPU's layers use the type.
        
      
        
        
        
        
        Applies when you leave Settings (the model reloads).
        Everything the model keeps in memory: its weights, its KV cache for the context, its
        working buffers. What does not fit is read from this site's storage while it runs (the embeddings a row
        per token, the output layer and the last layers whole at every token): much slower, but a model larger
        than the tab's memory runs; one that cannot fit is refused. A longer context leaves less for the
        weights. Auto: 1600 MB on an iPhone or iPad, under the measured ceiling (Safari kept the tab at 1.75 GiB on an iPhone 16 Pro and
        ended it at 2000 MB; a phone with less memory may need less), 3584 MB elsewhere (under the 4 GiB a
        WebAssembly module can address: a model's part in memory is capped near 4 GB, so a larger model always
        reads from storage; WebAssembly Memory64, in Chrome but not yet in Safari, would lift that). Kept in this
        browser.
        
      
        
        
        
        
        
        Applies when you leave Settings (the model reloads).
        
        CPU: WebAssembly SIMD on this device's cores. GPU (experimental): the layers through WebGPU, as
        many as fit "GPU memory", the rest on the CPU (read from this site's storage when the memory limit
        asks); a model whose layers or weight types the GPU does not run stays on the CPU, and the load line
        says why. Auto: the GPU only where it was measured faster than the CPU, and never for a model larger
        than "Memory for the model" (it would be read from storage, and the GPU's share leaves the CPU fewer
        weights); on the iPhone 16 Pro the GPU was not faster (Qwen3 0.6B: 16.3 tok/s on the GPU, 25 on the
        CPU), so Auto picks the CPU for now. In a browser without WebGPU (no navigator.gpu), GPU is not available.
        
      
        
        
        
        
        Applies when you leave Settings (the model reloads).
        What the GPU may hold: its layers' weights and KV cache, its working buffers. Auto:
        1024 MB on an iPhone or iPad (Llama 3.2 1B, 0.9 GiB on the GPU, is the largest model measured to load
        there). Elsewhere it follows the adapter, since WebGPU does not tell a GPU's memory: an Apple GPU
        shares the Mac's memory, so 3/4 of what the browser reports (Chrome reports at most 8 GB: 6144 MB,
        which holds a 7B Q4 model and its KV cache), or the adapter's maxBufferSize when larger; another GPU 4096 MB when its
        maxBufferSize and the device's memory are large, else 3072 MB, which fits a 4 GB card; 16 GB at most
        (set it in MB for yours). The line above says what Auto gives here and why. The layers that do not
        fit run on the CPU, much slower: the load line says how many.
        
      
        
        
        Applies when you leave Settings (the model reloads).
        One limit: the GPU's bytes are counted in "Memory for the model" (added to WebAssembly memory), in case the system counts a tab's
        GPU buffers with its memory, as iOS may; then a model that needs storage keeps fewer weights on the CPU
        and runs slower on the GPU than on the CPU alone (Qwen3-4B on an iPhone 16 Pro: 0.9 against 2.3 tok/s).
        Apart: the limit covers WebAssembly memory only; "Memory for the model" bounds WebAssembly memory and "GPU memory" the GPU's bytes, as on a
        desktop, whose graphics memory is not the tab's. Auto: one limit on an iPhone or iPad (until the test in
        the guide's step 7 shows that iOS does not count GPU buffers), apart elsewhere. The load line says which
        was used.
        
      
        
        
        Applies when you leave Settings (the model reloads).
        A smaller stored model with the same vocabulary (for Qwen3-4B, Qwen3-0.6B; for Llama
        3.2 3B, Llama 3.2 1B) guesses a few tokens, and the model checks them in one pass: a layer read from
        storage is read once for every token the pass accepts. It is held whole, out of the same memory
        limit, so the model keeps less in memory; it turns itself off while it does not make the answers
        faster. Kept in this browser.

        Report
        
      
        Opens GitHub's issue form for this beta with what the page knows filled in: this browser and
      its GPU adapter, the model and how it loaded, the speeds (the last answer, the Standard test, the GPU
      benchmark and kernel times if you ran them), the load log and the errors the page saw. Nothing is sent from
      here: you read it on GitHub, add what you did, and submit it (a GitHub account is needed).
        
      
        
        
        
        
      
        
      
        
        What the report contains
        
        
      
        
    
        
  
        
  
        
    
        
      
        Compare with other browser engines
        
      
        The loaded model on Inga, and the same prompt and output length on the engines you tick, in this
      browser on this GPU: time to first token (TTFT), prefill and decode speed, end-to-end time. Each engine runs once
      to warm up, then the measured runs, averaged. The table says what ran next to the numbers (browser, GPU adapter,
      model files, quantizations): copy it as Markdown, or attach it to the report. WebLLM and Transformers.js run
      their own model files (MLC q4f16, ONNX), not this GGUF file: with different quantizations the comparison is
      indicative. On a GPU without shader-f16 (Pascal, among others) they run their f32 builds (MLC q4f32, ONNX q4
      instead of q4f16), whose f16 kernels would not compile there; the table names what ran. Ticking an engine downloads its module from jsDelivr (a pinned version) and its model files from
      Hugging Face; nothing else leaves the page.

        About Inga
        
    
  
        
  
        Inga is a new local inference engine written in Rust, by Matteo Baccan, to be published soon.
        
  
        This page is its beta, running entirely in your browser (WebAssembly and WebGPU).
        
  
        Nothing leaves this device except the model's download.
