Inbox

Back to the roadmap’s index: TODO.md.

New ideas, news and requests land here, one line each with the date and the source, never straight into a release. They are triaged at the next release’s planning (docs/RELEASING.md, “Cadence”): into the backlog, into a release the maintainer approves, or dropped. A user’s bug report is not an idea: it goes into the next release at once.

  • (2026-10-20, Liyab’s GitHub page, Apache-2.0, C++20; docs/comparison.md, Part 1) What Liyab does that Inga does not: (a) generation paced by the device’s thermal headroom (a 10 s forecast from the OS’s sensors), so a laptop or a phone slows a little before it throttles hard, the state shown in the interface; (b) the prompt processed while the user types, so the answer starts at once (0.38 s on its 35B MoE, its claim) — triaged on 2026-10-20: the system prompt’s part in 0.34.0, the typed message in the backlog (spec 2026-10-20-warm-prompt-design.md); (c) drafts from suffix arrays over earlier conversations, verified as a tree, against Inga’s prompt lookup (a code edit 2.96× on its Mac, its claim); (d) the model parked when the app is hidden (state saved, the expert cache emptied, unloaded after 5 minutes); (e) its 35B MoE at 9–10.5 tokens/s on a Snapdragon 8 Elite phone as the number to measure Inga’s phone builds against. None of it measured here · no spec
  • (2026-10-21, DeepInfer’s GitHub page, Apache-2.0; docs/comparison.md, Part 1) What DeepInfer does that Inga could take: (a) batch-invariant inference and deterministic sampling: the same input gives the same output whatever else is in the batch, and with a fixed seed the same sampled text; for Inga’s tests, the CPU/GPU comparisons, the evals and the mesh; whether Inga’s kernels are batch-invariant today is not known: to check first; (b) a bounded replay of a sliding-window model’s prefill (its V4.1 default keeps 140 tokens), for the prefix cache and the SWA models (Gemma): how it works is not on its page, its code to read; (c) DSpark drafts verified by confidence (how many drafts to check from their confidence), beside the backlog’s DFlash item, which has DSpark; (d) asynchronous scheduling, the CPU preparing the next step while the device computes: the backlog’s GPU-resident sampling part 2 is the same idea; (e) outputs constrained by a regex and an EBNF grammar besides a JSON schema: what Inga’s grammars accept today, to check; (f) DeepSeek-V4.1-Flash (deepseek-ai/DeepSeek-V4.1-Flash-1017): whether its architecture differs from V4’s, which Inga runs on the CPU. Its kernels are for SM100 only: a reference, nothing to take. None of it measured here · no spec
  • (2026-10-23, TurboFieldfare’s GitHub page and its experiment inventory, Apache-2.0, Swift 6.2 + Metal 4; asked by the maintainer) What TurboFieldfare, a Gemma 4 26B-A4B runtime for Macs that streams each token’s experts from the SSD, measured that Inga could take (its numbers, its hardware: 5.1–6.3 tokens/s on an 8 GB M2 MacBook Air, 31–35 on a 24 GB M5 Pro; Inga already reads streamed experts with read_at in parallel, an LRU cache and a prefetch, crates/inga-model/src/experts.rs): (a) an LFU expert cache instead of LRU (CACHE-01: I/O 72.6 → 64.8 ms a token, decode 5.476 → 5.631 tokens/s); (b) a cache of slots per layer (16) instead of one cache for all (DEC-04: I/O 166 → 88 ms, decode 3.313 → 4.261); (c) the routed experts’ reads overlapped with the shared expert’s compute (DEC-05: 62 → 48 ms, decode 4.404 → 4.736); (d) split-KV attention for decode at long contexts (KV-01: about 3.3× on sliding-window layers and 4.1× at 4K, isolated), for Metal, Vulkan and WebGPU; (e) Q, K and V in one fused matrix-vector product (ORCH-04: 6.110 → 6.215) and a persistent MoE kernel over several threadgroups (DEC-03: 239 → 60 ms); (f) an installer that repacks the downloaded byte ranges straight into the final layout, without a full copy of the model staged on disk (for inga pull on small disks). What it measured as no gain, to skip: speculative reads (IO-08), Markov and cross-layer expert prefetch (CACHE-05, CACHE-06), mlock (IO-06), compressed experts (IO-07: zstd 10 %, LZ4 0.06 %), 4-bit packed KV (KV-07, KV-09: slower and worse), a second Metal queue (ORCH-10). A target for Inga’s own streaming and Metal: Gemma 4 26B-A4B on an 8 GB Mac.
  • (2026-10-29, raytone-lab/awesome-local-inference-recipes, code MIT, data CC BY 4.0, data as of 2026-10-29; asked by the maintainer) Models in a dataset of 624 local inference recipes that Inga does not run, checked against their config.json and GGUF headers (each one has an architecture in llama.cpp 0893ec9; Recursive’s Flint is already in 0.40.0, Muse Spark Open in the backlog): (a) LFM3 (LiquidAI/LFM3-1.7B, Lfm3ForCausalLM, GGUF lfm3): LFM2’s short convolutions (shortconv.l_cache 7) between full and sliding-window (256) attention layers, a KV head count per layer, two RoPE bases, sandwich norms; (b) MiniMax-M3.1-Flash (MiniMaxAI/MiniMax-M3.1-Flash, MiniMaxM3SparseForConditionalGeneration, GGUF minimax-m3): 60 layers, 128 experts with 4 used and a shared one, 3 leading dense layers, sparse attention with an indexer (4 heads, top 16 blocks of 128, one local block), partial RoPE, gated attention output, and images; (c) MiniCPM-V 4.7 (openbmb/MiniCPM-V-4.7-35B-A3B): the text model is a qwen35moe GGUF, which Inga runs today (not run on this file); its images need the minicpmv4_7 projector (SigLIP-like, 27 blocks, 448-pixel slices up to 9, scale_factor 4), which Inga does not read; (d) Edge0-8B-A1B-preview (Edge0/Edge0-8B-A1B-preview, BailingMoeV3ForCausalLM, GGUF bailingmoe3 in llama.cpp): latent attention, KDA linear attention, a trained pre-router and a LoRA shipped beside the weights, its own modeling code; no GGUF file on its page; Edge0-35B-A3B-preview is a qwen3_5_moe, which Inga runs. Nanbeige4.3-33B (Nanbeige/Nanbeige4.3-33B) is a LlamaForCausalLM (GGUF llama, RoPE base 1.2e8, 166,912 tokens, SentencePiece): expected to run already, not run (the smallest GGUF file is about 11 GB).
  • (2026-10-29, Contrastive-LM/CLM-v0.1-8B and its code, Apache-2.0; asked by the maintainer) CLM-8B, a contrastive model that scores candidates instead of writing text: two MLP heads (state and action: 4096 → 1536 GELU, one 1536 block with LayerNorm, GELU and a residual, → 512, unit length) over Qwen3-8B’s last-token embeddings; the score of a candidate is exp(logit_scale) (about 100) times the cosine of the two projections, then a softmax over the candidates; the state is the context, a blank line and the question. Checked on 2026-10-29 in this container: inga serve 0.38.1 with Qwen3-8B Q4_K_M and --pooling last gave the embeddings, the heads ran in NumPy (their float32 tensors read from the checkpoint’s zip, the pickle never run): the model card’s two examples rank the same (0.9976 against its 0.993; 0.922 / 0.078 against 0.939 / 0.061, its numbers from vLLM in bf16). For Inga: the heads loaded (the .pt read without unpickling, or converted to safetensors), a scoring path (/v1/rerank, or an endpoint like its clm-serve‘s), and the candidates’ embeddings cached, which is where its speed with about 1,000 candidates comes from (13 times faster than Jev, its claim).
  • (2026-10-29, the engines of raytone-lab/awesome-local-inference-recipes read on their pages; docs/comparison.md, Part 1; asked by the maintainer) What TensorFold, Basalt, Radiance, Halogen, Project Maya, NVIDIA Flare, TandemLLM, janas, Kapitsa, tqLLM, ReVolta and Geezuz do that Inga could take (their claims, not measured against Inga): (a) the hot-expert profile saved and reloaded, so the next start begins warm (Basalt, docs/configuration/index.md, “The adaptive tier”); (b) the GPU / RAM / NVMe expert tiers sized by a calibration at setup (Project Maya’s --calibrate, janas’s O_DIRECT streaming); (c) Flash-Next’s n-gram / PLE table paged from the host or the SSD instead of resident (Halogen’s docs/QUANT.md: 47.7 GiB in FP8; ReVolta: on the SSD 23–25 % slower; Flare: host caching); (d) an MTP head and prompt lookup together, with tests that the output stays byte-identical to plain greedy decoding (Halogen, TensorFold’s “exact decoding”); (e) draft trees with a sized budget (Kapitsa’s docs/kflash.md, TandemLLM’s StairCut); (f) each pass (prompt, drafts, reply) placed on CPU, GPU or NPU by a measurement (janas); (g) prefixes and KV kept on disk across restarts (ReVolta’s docs/kv-offload.md: a 32K prefix back in 1.5 s; Kapitsa’s --disk-cache; TensorFold’s --learn); (h) tensor parallelism with one rank per machine (Flare’s docs/multi-host.md, TensorFold over GB10s; the Inga mesh splits by layers); (i) one file holding the weights, tokenizer, drafter and expert profile (.basalt, .rad); (j) two GPUs over plain PCIe P2P in one megakernel (Geezuz). The dataset’s own fastest recipes use speculation on CUDA (TensorFold, DFlash2), where Inga’s A100 run found every mode slower (issue #963): its exact path is the first to read.
