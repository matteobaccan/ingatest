The configuration file: inga.toml

One file holds Inga’s settings, in TOML. inga config init writes it with every key commented out; inga config show lists each key’s value and where it comes from, inga config get KEY prints one value, inga config path the file in use and inga config check checks it (exit 1 on an unknown key, for CI).

Where it is

Section titled “Where it is”

The first that exists, never merged:

  1. --config FILE (a file that does not exist is an error);
  2. inga.toml in the home: ~/.cache/inga/inga.toml (%USERPROFILE%\.cache\inga on Windows), or in the folder --home DIR names;
  3. the machine’s: /etc/inga/inga.toml (%ProgramData%\Inga\inga.toml on Windows).

Without a file, every value is a default. home = "DIR" in the file moves Inga’s data, not the file. --config, --home and --set are global options, before or after the command (inga --home /data/inga serve), but for merge --config and eval --set, which are those commands’ own. inga service install records them with the service’s command line.

Which value wins

Section titled “Which value wins”

For each key: a flag on the command line (the key’s own flag, or --set KEY=VALUE, repeatable, for any key) wins over the file, which wins over the default. There is no environment layer: no INGA_* variable sets a setting; Inga only honours the standard variables of other programs (below). --set takes the value as TOML (--set run.temp=0.6, --set 'mesh.peers=["10.0.0.2"]') or as bare text (--set gpu.device=vulkan:1, --set mesh.peers=10.0.0.2,10.0.0.3).

A value of the wrong type or out of range stops the command (exit 2), naming FILE:LINE and the key; an unknown key or section is a warning naming the closest known key, so that a file written for a newer Inga still runs an older one.

Secrets

Section titled “Secrets”

The file never holds a secret in clear. A secret key takes { env = "VAR" }, a variable you name (CI, a secrets manager), or { file = "PATH" }, a file holding only the key (Docker and Kubernetes secrets). inga config show shows the form, never the value.

Other programs’ variables Inga reads

Section titled “Other programs’ variables Inga reads”

Every setting of Inga is a key of this file or a flag: no INGA_* environment variable sets one. Inga only reads the standard variables of other programs, which it does not own and other tools set for everyone. inga config show lists the ones set.

Variable What it decides
HF_HOME the Hugging Face cache shared with huggingface_hub (wins over download_dir)
HF_HUB_CACHE the same, the hub’s folder itself
HF_TOKEN the Hugging Face token (gated and private models)
HF_ENDPOINT another Hugging Face server (a mirror)
HF_HUB_OFFLINE no downloads, as –offline
HTTP_PROXY the proxy of the downloads (also HTTPS_PROXY, ALL_PROXY)
HTTPS_PROXY the same, for HTTPS
ALL_PROXY the same, for every protocol
NO_PROXY the hosts reached without the proxy
CUDA_VISIBLE_DEVICES the NVIDIA GPUs the driver shows, before Inga sees any
LMSTUDIO_MODELS LM Studio’s models folder
OLLAMA_MODELS Ollama’s models folder
OTEL_EXPORTER_OTLP_ENDPOINT OpenTelemetry’s collector (serve.otlp_endpoint beside it)
BRAVE_API_KEY Brave Search’s key, when the web UI’s key store has none
TAVILY_API_KEY Tavily’s key, when the web UI’s key store has none

The test suite has switches of its own (which GPU tests run, where the real models are, rewriting golden files): development.md lists them; the inga program never reads them.
