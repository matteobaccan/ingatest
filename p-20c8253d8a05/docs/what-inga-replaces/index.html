What you can uninstall when you use Inga

Inga is one executable. This page lists the programs it can take the place of and the dependencies you no longer need for local AI. It says only what main does today, with no release for what is built (from 0.46.0 on the CHANGELOG has it, before it git and its tags); where Inga does not cover a case yet, the program stays in the “keep it if” column, with the release that will cover it (TODO.md) or the design spec that plans it.

Before you uninstall anything, read the migration notes: some programs delete their downloaded models when they are removed, and Inga can use those models where they are.

Ollama Ollama’s API (/api/pull too), the models Ollama already downloaded, from its folder (inga list --ollama), and Ollama’s library (inga pull ollama://NAME) you need llama.cpp’s tuned Metal kernels on a Mac (Metal M3–M4)
LM Studio (as a server and model manager) LM Studio’s API (/api/v0), its models folder (its MLX models read as stored on the CPU and Metal), a model hub with fit and speed per model you need MLX’s tuned Metal speed (spec), or its desktop app’s own features
llama.cpp’s ROCm and multi-GPU builds CUDA, Vulkan, Metal and ROCm / HIP inside the executable, with only the driver (HIP: AMD’s runtime); several GPUs of one PC split a dense model’s layers (--device cuda:0,vulkan:1) you need tensor parallelism across GPUs, or a mixture of experts over several GPUs (one GPU today; spec)
llama.cpp’s RPC servers, exo (one model over several PCs) inga worker with --nodes, --expert-nodes or --tp-nodes; the Inga mesh (inga satellite, inga serve --mesh), each satellite’s GPU included your PCs are not on the same LAN (the mesh over the internet: spec, planned)

How: every family is on by default, all on one port (8080). To tighten, switch families off with [api] disabled = ["kobold", "azure"] in inga.toml or inga serve --api-disable kobold,azure (enabled = [...] / --api-only for the only ones kept on; a switched-off family answers 404 naming the setting and where it was set, and inga serve prints which families are on when it starts); --no-webui and --no-mcp-server are the same as switching webui and mcp off. To take another server’s port, inga serve --like ollama (or like = ["ollama"] in the file) adds a listener on 11434 beside 8080 answering only Ollama’s families (ollama, openai), and --like lmstudio (1234), kobold (5001), vllm (8000), tgi, tei (3000; the launchers’ default, the Docker examples map 8080) do the same on theirs; --like NAME:PORT picks another port, and a port in use stops the start naming the program that usually holds it. The families not built in this version answer 501 saying they are not available in this version; --like a1111 is refused. For a listener of your own, a [[api.listen]] table in inga.toml gives its port, host and families (or a like server’s defaults). The web UI’s Server settings switch each family on and off and save the choice as [api] disabled in inga.toml (spec, the families). “Clients known to work” names the clients Inga’s guides document; their runs against real clients are in the real-world checks (docs/todo/real-world-checks.md, group B), “to check” otherwise.

You no longer need It was needed for With Inga
Python, pip / conda / uv / virtual environments transformers, vLLM, Open WebUI, faster-whisper, NeMo, ComfyUI, PEFT, proxies not used at all
PyTorch, transformers, accelerate, bitsandbytes, safetensors (Python) running Hugging Face models Inga reads safetensors directories (and AWQ / GPTQ / FP8 weights) itself

Node.js / npm Open WebUI’s frontend build, coding-agent proxies not used by Inga; an MCP server written in JavaScript needs it as any program needs its runtime (why)
ffmpeg for audio decoding audio for Whisper WAV, MP3 and FLAC decoded inside Inga; Ogg, M4A / AAC and WebM / Opus next (spec)
poppler / pdftotext, LibreOffice, pandoc reading PDF and DOCX for chat with documents read by Inga’s own reader (the PDF text layer; scanned pages by a vision model next: spec)
huggingface-cli / huggingface_hub, git-lfs downloading models inga pull hf://…, into the standard Hugging Face cache shared with those tools
git installing skills from a repository inga skill add reads git’s HTTP protocol itself
cron / Task Scheduler running prompts at set times inga schedule
A database (PostgreSQL, SQLite server, Redis) chat apps’ storage chats in the browser, memory and shared chats as files in the home (~/.cache/inga, or --home)
A reverse proxy just to start a server at boot keeping a server running inga service install (systemd, launchd, a Windows service)

What Inga still needs: the operating system (Windows, Linux or macOS on x86-64 or ARM64) and, to use a GPU, its driver (NVIDIA’s for CUDA, any vendor’s Vulkan driver, AMD’s HIP runtime for ROCm).

Before you uninstall

Section titled “Before you uninstall”
  • Ollama: removing Ollama can remove its models folder (~/.ollama/models, or OLLAMA_MODELS). Inga reads models from that folder (inga list --ollama, the web UI’s folders): keep the folder, or copy the GGUF files out first.
  • LM Studio: the same for its models folder (~/.lmstudio/models or the one set in the app): keep it, or move it and add it as a folder in Inga’s web UI.
  • Clients and ports: Inga serves every API on one port (8080 by default). Point Ollama clients at http://localhost:8080 or run inga serve --port 11434; LM Studio clients at /api/v0 on Inga’s port; OpenAI and Anthropic SDKs, Claude Code and Codex at http://localhost:8080 (and /v1). Per server, see Drop-in for other servers.
  • Hugging Face cache: Inga uses the same cache as huggingface_hub, so models already downloaded there are found; uninstalling Python does not remove them.
  • Check one model end to end before removing the old tool: inga info MODEL (where it will run and how fast), then inga run MODEL.
