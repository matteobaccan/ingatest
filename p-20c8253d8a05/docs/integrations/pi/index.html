pi on Inga

pi (the pi coding agent) reads its providers from models.json in its agent directory (~/.pi/agent, or PI_CODING_AGENT_DIR).

1. Start Inga

Section titled “1. Start Inga”

A model trained for tool calls, with a context of 32768 tokens or more (see use-with-coding-agents.md for the choice):

Or let inga connect start it for the tool’s run only, with --serve MODEL (below).

2. Connect it

Section titled “2. Connect it”

--run gives pi a temporary agent directory (PI_CODING_AGENT_DIR) for that run:

  • models.json: a copy of yours, if any, with an inga provider added;
  • every other file and folder of your agent directory (settings, sessions, …) linked, so pi sees them and its sessions are kept;
  • and --provider inga --model MODEL on its command line.

The directory is removed when pi exits; your ~/.pi/agent/models.json is not written. The provider:

apiKey names the variable holding the key, set in pi’s process to the server’s key (or inga). On Windows, links need Developer Mode: without it the files are copied (changes pi makes to them in that run are not kept) and the folders are left out, as Inga says.

By hand: add the inga provider to ~/.pi/agent/models.json (inga connect pi prints it), then pi --provider inga --model qwen3-coder.

Not installed? inga connect pi --run says so before starting anything, with the install command: npm install -g @mariozechner/pi-coding-agent.

3. The context

Section titled “3. The context”

Agents send long system prompts and tool results: serve the model with --ctx 32768 or more (inga connect warns under that). --cache-type q8_0 halves the KV cache’s memory; --parallel 2 answers a second request while the first runs.

4. Check that it works

Section titled “4. Check that it works”

inga connect pi (without --run) prints the same settings and sends one short request through the same route, saying which model answered:

The Server page (http://127.0.0.1:8080/) counts the requests as the tool works.

5. What works

Section titled “5. What works”
  • Chat completions with tools and streaming (openai-completions).
  • Long prompts: PI Agent (Node’s undici) drops a request that sends nothing for 300 s. Inga sends the stream’s headers at once and a keep-alive comment every 15 s of silence while it reads the prompt, so a prompt that takes minutes to read no longer trips that limit (and is no longer sent again behind itself); if PI Agent gives up anyway, the reading stops within about a second.
  • contextWindow is the served model’s context; maxTokens a quarter of it, at most 16384.

Reasoning off

Section titled “Reasoning off”

A thinking model (Qwen3, Qwen3.5, …) reasons before every answer, which takes time and context on long agent sessions (issue #1038). The web UI’s Thinking switch is for the web UI’s chats; for pi’s requests start the server with the reasoning off:

or put it in inga.toml:

It is the default of the requests that do not say it themselves: a request that sets chat_template_kwargs.enable_thinking, reasoning_effort, Ollama’s think or Anthropic’s thinking decides alone. The start banner says it (Reasoning off for API requests that don't ask (serve.think)). A model whose template has no switch (DeepSeek R1, …) always reasons: see use-thinking-models.md.

More: the integrations, use-with-coding-agents.md.
