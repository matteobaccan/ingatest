Everything Inga does

The long tour of Inga, moved here from the main README on 2026-11-06 when the README was cut to the first screen: what Inga replaces, its parts, its highlights, the big models it plans for, what it tells you, what works today, the drop-in servers, the web UI’s pages and the project’s goals. The guides by use case are in use-cases/, every command in cli.md, the questions people ask in faq.md.

One executable replaces …

Section titled “One executable replaces …”
Instead of Inga gives you Try it
An inference engine (llama.cpp, whisper.cpp, stable-diffusion.cpp) its own engine, every llama.cpp quantization, output checked against those projects inga run, inga image
A model runner (Ollama, LM Studio) models from Hugging Face, or the ones Ollama and LM Studio downloaded, loaded on demand and unloaded when idle inga pull, inga list --ollama
GPU builds (llama.cpp’s CUDA, ROCm and multi-GPU builds) CUDA, Vulkan, Metal and ROCm / HIP in one file with only the driver, several GPUs of one PC splitting a dense model --device cuda:0,vulkan:1
An API server the OpenAI, Anthropic, Ollama, LM Studio and KoboldAI APIs, streaming and tool calls, several models and users inga serve --no-webui
A router or gateway (LiteLLM, llama-swap) other servers and providers as API nodes, routes with fallback, named keys with budgets, a cascade from a small model to a larger one inga node add, inga route
A chat web app (Open WebUI) chat with a model hub, the models’ speeds on this computer, web search, documents, a memory, image generation inga serve
Speech tools (faster-whisper, a TTS server) transcription, streamed live, and text to speech; a hands-free voice chat inga transcribe --stream, inga speak
An agent host (an MCP client, a scheduler) MCP servers’ tools, Agent Skills and scheduled prompts, each tool call approved inga mcp, inga skill, inga schedule
A quantizer (llama-quantize) the same GGUF file, byte for byte inga quantize
A LoRA trainer (Python, PyTorch) LoRA fine-tuning of small models on the CPU, adapters for --lora inga finetune
A cluster one model over the PCs of a LAN: layers, experts or slices; a mesh with no copy of the model on the others inga satellite, --mesh

The full list — which programs you can uninstall, which dependencies (Python, PyTorch, the CUDA Toolkit, Node.js, ffmpeg…) you no longer need, and what to keep: what Inga replaces.

Five parts, together or on their own

Section titled “Five parts, together or on their own”

Inga is one file, but its parts are separable: use only the one you need.

Part What it is Use it alone
Engine local inference in the terminal: chat, single prompts, speed and quality measurements, speech to text, image generation inga run MODEL -p "...", inga bench, inga transcribe, inga image: no server, no browser (guide)
API server the OpenAI, Anthropic, Ollama, LM Studio and KoboldAI APIs for apps, agents and editors, headless inga serve MODEL --no-webui (guide, coding agents, OpenClaw)
Web app the chat page and model hub served by inga serve: search, download, load, compare, chat inga serve with no model, then pick one in the browser (guide)
Inga mesh (part 1, LAN) inga satellite on other PCs, found by mDNS (or --peers); the elected master measures them, places layer ranges where a token is fastest and sends each only its layers (cached by hash); a satellite that leaves is replaced and the answer goes on; the web UI’s Mesh page and inga mesh show draw who runs what and why inga serve MODEL --mesh home on one PC, inga satellite --mesh home on the others (guide)
Network of nodes inga worker on other PCs runs layers, experts or tensor slices of a model the main PC loads; API nodes bring whole models of other servers and providers inga worker on each PC, --nodes, --expert-nodes or --tp-nodes on the main one (guide); inga node add or --api-node (guide)

Frontier models on any hardware

Section titled “Frontier models on any hardware”

Inga has no fixed limit on a model’s size. What a model needs is a disk that holds its file; how fast it runs comes from everything Inga uses together: the VRAM, the RAM, the disks’ bandwidth and the other machines of the LAN. The largest open models are mixtures of experts, and each token uses only a few of their experts, so they run on the machine you have, not on the one they were trained for.

¹ Of DeepSeek V4’s layout, which Inga runs (checked on V4-Flash’s). File sizes at about 4.8 bits per weight (Q4_K_M; MXFP4 for Kimi K3’s and gpt-oss’s experts).

Speed to expect: estimates, not measurements. Per token, Inga’s planner counts the bytes read from each place divided by its bandwidth: the attention and shared weights from VRAM or RAM, the routed experts from the RAM cache, the experts the cache misses from the disk (inga info assumes 80 GB/s for VRAM, 20 GB/s for RAM; even routing, so the cache’s hit rate is its share of the experts). Real routing favours some experts, which the cache keeps: these figures are the floor.

Strategy How
Each part where it fits: attention, KV cache and shared experts on the GPU or in RAM, routed experts in a RAM cache, the rest on disk; the RAM plan made again once the GPU took its share by default (--experts-on, --cpu-moe, --mem-limit)

Hot experts pinned in RAM from the use profile --pin-experts N, inga profile

A trained prerouter predicting the next experts inga profile --prerouter, then --prerouter

What you can do with Inga, whatever you used before. What it can replace on your machine, and when to keep another program: docs/what-inga-replaces.md.

When you want to… Inga
Run a model larger than your memory Experts of a mixture, or a dense model’s layers, read from the SSD with a cache in RAM, planned for you: Qwen3-30B-A3B (a 17 GB file) answers in 2 GB of RAM with the same text (performance)

Transparent by design

Section titled “Transparent by design”

Inga tells you what it does and why, with the technical detail, in the terminal, the APIs and the web UI alike:

  • Which device runs which layers, and why a GPU was not used: the placement line printed when inga run / inga serve load a model, /api/inga/status, the web UI’s badges and Server tab; inga devices --test checks every GPU against the CPU. What runs where
  • What sits in VRAM, RAM or on disk, and the expected speed, before loading: inga info MODEL prints the memory plan.
  • Which kernels run: inga bench names the instruction set (CPU (avx512)), --profile the time per operation kind; --set cpu.isa=NAME forces another one.
  • What a conversion costs in quality: inga perplexity --kl-base measures the KL divergence against the original, and lower-precision experts keep theirs next to the suggestion line.
  • What is on your disk: inga data lists every cache and store with its size and deletes them one by one.
  • What a model can do: the web UI’s model cards (text, vision, audio, tools, reasoning, context, recommended sampling, where it runs).

Which programs Inga replaces, and when to keep them: docs/what-inga-replaces.md; its speed against llama.cpp.

💡 Inga needs ideas more than code. Have an idea, a use case, a model you would like to run, something another tool does better? Open an issue and tell us: we take care of implementing it. Nothing is too small or too wild. Write in your language: we answer in it. When Inga stops with an error, its last line (and the web UI’s Report) opens the Error report form with the details already filled in, without your folders, user or host names, shown to you before anything is sent.

🧪 Test Inga on your machine: docs/testers.md says what is most useful for each kind of machine (Macs, AMD / Intel / NVIDIA cards, small PCs, several PCs, the tools you already use) and how to send a Test report. The quickest test: run bench.bat (Windows, downloaded next to inga.exe) or sh bench.sh (from the Linux and macOS archives), which measures Inga against llama.cpp on your machine and writes one file to send back.

🕸️ Inga in the browser: https://matteobaccan.github.io/ingatest/ runs a GGUF model in a browser tab, on the CPU (WebAssembly) or the GPU (WebGPU), nothing installed; Browse models picks one of about fifty from Hugging Face, each marked by whether it fits the device; its Report on GitHub button fills an issue (on the public matteobaccan/ingatest) with the browser, GPU and speeds. What works and what does not: docs/wasm.md; to embed it in your own JavaScript application, Integrate Inga in a JavaScript application.

🍏 Wanted: Apple Silicon Macs (M3, M4 or later) for testing. Inga runs on a Mac’s GPU through Metal, checked for correctness on GitHub’s virtual Mac; its speed work (prefill tiles on simdgroup_matrix, every GGUF weight type on the GPU, generation driven by the GPU) is written, unmeasured on real hardware. If you have an M3 or M4 Mac and can run a few tests and benchmarks, docs/mac-testers.md explains the 30-minute test kit and how to send its report; or get in touch with the maintainer.

Goals

Section titled “Goals”
  • One executable, no runtime dependencies. No DLLs, no Python, no CUDA Toolkit. On NVIDIA GPUs only the driver is needed: kernels ship inside the binary.
  • Models straight from Hugging Face, in the cache other tools already use.
  • Any model size on any amount of RAM: weights placed on a memory hierarchy, VRAM → RAM → disk → remote machines; slower when resources are short, never a failure, with the expected speed shown before starting.
  • A model split across machines on a LAN.
  • Standard formats and drop-in APIs: GGUF and safetensors; OpenAI, Anthropic and Ollama compatible.
  • Windows, Linux and macOS.
