API node presets

The providers and servers inga node add ID knows: their base URL, the API they speak and the environment variable their key is read from, so a node is one command and a key. inga node presets prints them with their URLs (--search TEXT narrows the list, --json gives everything below); the web UI’s Mesh page offers them under API nodes, grouped as here. The list is crates/inga-server/src/api_nodes/presets.rs; a test fails when a preset is missing from this page.

Each entry was checked against the provider’s documentation (the link on its name) on 2026-10-15. Where the provider’s own pages could not be read, the link is the integration guide or provider registry (LiteLLM, Cherry Studio, OpenClaw, Docker, API7, Portkey…) the URL was confirmed with; such entries agree with at least one other source. Providers change their URLs: inga node add ID URL keeps the preset’s API, key variable and cloud tag with another URL, and inga node test ID says what answers.

  • API: openai nodes get /chat/completions (and the rest of OpenAI’s API) under the base URL; anthropic nodes get /v1/messages under the server’s address (the -anthropic presets are the Anthropic-compatible endpoints providers offer for Claude Code); ollama nodes get Ollama’s /api/....
  • *: the provider’s model list does not name the models it serves (or there is none at that address): give them with --models M,... (inga node add deepseek-anthropic --models ID,... with the provider’s model ids), or the Models field of the Mesh page.
  • {NAME} in a URL (Cloudflare, Azure, Bedrock, Databricks, Snowflake): the part that is your own. inga node add reads it from the environment variable NAME (CLOUDFLARE_ACCOUNT_ID, AZURE_RESOURCE_NAME, AWS_REGION…), else asks for it on a terminal; --api-node and the server read the variable; on the Mesh page you type over the placeholder, which the page selects. Or give the whole URL.
  • ‡: the key page is the console’s home (no deeper link could be checked); keys are under its API keys or access tokens section.
  • Other tools’ provider names are accepted as aliases: gemini (google), kimi (moonshot), nvidia_nim (nvidia), open_router (openrouter), mistral_codestral (codestral), llamacpp (llama-server), azure-openai (azure); _ and - are the same in an id.

Using a provider’s API with your key is subject to that provider’s terms.

Coming from free-claude-code

Section titled “Coming from free-claude-code”

free-claude-code (fcc) keeps one key per provider in its .env. inga node import free-claude-code [PATH] (default ./.env) makes an API node of each provider that has a key there (and of LM Studio, llama.cpp and Ollama when their *_BASE_URL is set), named as fcc names it, so the model ids of fcc’s MODEL lines are Inga’s too (nvidia_nim/z-ai/glm-5.1):

fcc provider Key from Preset API
nvidia_nim NVIDIA_NIM_API_KEY nvidia openai
open_router OPENROUTER_API_KEY openrouter openai
gemini GEMINI_API_KEY google openai
deepseek DEEPSEEK_API_KEY deepseek-anthropic anthropic
mistral MISTRAL_API_KEY mistral openai
mistral_codestral CODESTRAL_API_KEY codestral openai
opencode OPENCODE_API_KEY opencode openai
opencode_go OPENCODE_GO_API_KEY, else OPENCODE_API_KEY opencode-go openai
wafer WAFER_API_KEY wafer anthropic
kimi KIMI_API_KEY moonshot openai
cerebras CEREBRAS_API_KEY cerebras openai
groq GROQ_API_KEY groq openai
fireworks FIREWORKS_API_KEY fireworks-anthropic anthropic
zai ZAI_API_KEY zai-anthropic anthropic
lmstudio (LM_STUDIO_BASE_URL) lmstudio lmstudio
llamacpp (LLAMACPP_BASE_URL) llama-server openai
ollama (OLLAMA_BASE_URL) ollama ollama

DeepSeek, Wafer, Fireworks and Z.ai use Anthropic’s Messages API, as fcc does, so Claude Code’s requests pass through as they are; OpenCode Go is imported when a MODEL line uses it or it has its own key. A PROVIDER_BASE_URL in the .env (GROQ_BASE_URL…) replaces the preset’s URL.

  • Keys: copied to the encrypted key store (~/.cache/inga/secrets.json), never printed: the dry run shows nva…abcd. With --keep-env each node reads its key from the .env each time it needs it ("key": {"env": "GROQ_API_KEY", "file": "/…/.env"} in nodes.json), so a key changed there is used at once; move or delete the .env and those nodes stop.
  • On or off: every key is imported, but only the nodes the MODEL lines use are on; the others are imported off (inga node enable NAME, or the switch on the Mesh page). --enable-all turns them all on.
  • MODEL lines become model_map entries, so Claude Code pointed at Inga reaches the same models: MODEL_OPUS → claude-opus-*, MODEL_SONNET → claude-sonnet-*, MODEL_HAIKU → claude-haiku-*, MODEL → claude-* (the fallback, as in fcc). An entry already in nodes.json is kept. For a provider whose model list does not name its models (* above), the MODEL lines’ models are its models.
  • --test checks each key with one cheap call, the provider’s model list (the OpenAI endpoint’s for DeepSeek, Fireworks and Z.ai); a refused key says REJECTED. With --apply the day and the result are kept.
  • Limits: PROVIDER_MAX_CONCURRENCY becomes each node’s max_concurrency, HTTP_READ_TIMEOUT its timeout. PROVIDER_RATE_LIMIT / PROVIDER_RATE_WINDOW have no per-node equivalent, and the per-provider *_PROXY neither (a node is reached directly): the import says so for each one set.
  • A node already saved under the same name is left as it is.

Each node then shows, in inga node list (USED, TESTED) and on its card on the Mesh page, the day (UTC) its key was last used and last tested, whether the test passed, its on/off switch and a link to the issuer’s key page (the presets’ key column above). The days are kept in ~/.cache/inga/node-dates.json, written once a day at most per node.
