Image generation, part 3: after Qwen-Image

Status: proposed for 0.34.0 (decided 2026-10-14). First proposal (voice and media), 2026-10-14. Nothing in this spec is built. The TODO.md item (Extra, from 0.25.0) is “Image generation, part 3”. Its first entry, Qwen-Image, was built in 0.28.0 (2026-10-12-qwen-image-design.md). This spec covers the rest:

  • Qwen-Image’s leftovers (ComfyUI’s FP8 files, diffusers folders, Qwen-Image-Edit);
  • Flux 2 (and FLUX.2 klein), Flux Kontext and Fill, Chroma, Z-Image;
  • the SDXL refiner, Flux and SD 3.x as diffusers folders, and SD 3.5’s skip-layer guidance.

Image-to-image and inpainting for the UNet models, with the VAE encoder, are PR #591 (2026-10-13-image-editing-design.md on feat/image-edit). Kontext, Fill and Qwen-Image-Edit build on that encoder.

Decisions (2026-10-14)

Section titled “Decisions (2026-10-14)”
  1. Order: (A) FP8 files, diffusers folders, SLG, the refiner; (B) Z-Image and Chroma; (C) Kontext, Fill, Qwen-Image-Edit; (D) Flux 2.
  2. Licences: printed at load and on the model card for BFL’s non-commercial models (FLUX.1 Kontext [dev], FLUX.1 Fill [dev], FLUX.2 [dev], FLUX.2 klein 9B), as for other restricted models.
  3. Qwen-Image 2.1: a follow-up of Qwen-Image if its MMDiT is unchanged; its architecture is to be checked when the work starts. Status: open — postponed by the maintainer on 2026-10-14.

1. What the user sees

Section titled “1. What the user sees”
  • inga image MODEL … accepts each new family’s single files, GGUF (city96 / stable-diffusion.cpp conversions) and diffusers folders. The parts are given as today (--diffusion-model, --vae, --clip-l, --t5xxl, --llm).
  • New options:
    • --refiner FILE [--refiner-at 0.8] (SDXL);
    • --slg-scale 2.5 [--skip-layers 7,8,9] [--slg-start 0.01 --slg-end 0.2] (SD 3.5, as stable-diffusion.cpp);
    • --ref-image IMG (repeatable: Kontext, Qwen-Image-Edit, Flux 2);
    • --mask with a Fill model (shared with PR #591’s inpainting).
  • /v1/images/generations takes refiner, slg_scale and skip_layers. /v1/images/edits (PR #591) routes Kontext, Fill and Qwen-Image-Edit models to their own path.
  • The web UI’s image mode shows each family’s sizes, and the reference-image slot when the model takes one.
  • inga search / inga list call the new ComfyUI-GGUF and diffusers files supported (image generation). not_yet.rs loses the entries that now load.

2. Group A: files and guidance

Section titled “2. Group A: files and guidance”

  • ComfyUI FP8 (F8_E4M3, also F8_E5M2) safetensors: today the lone-file reader leaves them untyped.

    • inga_formats::safetensors reads them. At load they are converted to Q8_0 (32-value blocks, one f16 scale), which is about as small as FP8 and accurate to within FP8’s own error. ComfyUI’s “scaled fp8” files carry a scale_weight per tensor, which is applied first.
    • This keeps inga_core::DType unchanged.
    • Qwen-Image, Flux, Chroma, Z-Image and Wan all get it.

  • diffusers folders for Flux, SD 3.x and Qwen-Image, in files.rs beside diffusers_unet / diffusers_vae / diffusers_wan:

    • diffusers_flux (transformer_blocks.N.attn.to_q|to_k|to_v joined into BFL’s fused img_attn.qkv, single_transformer_blocks.N.proj_mlp + attn.to_* into linear1, and the norms renamed);
    • diffusers_sd3;
    • diffusers_qwen_image.

    model_index.json names the classes. The text encoders come from text_encoder*/ (CLIP, T5, Qwen2.5-VL through --llm semantics).

  • SD 3.5 skip-layer guidance: in pipeline.rs::latents, for steps whose progress is between slg_start and slg_end, a third MMDiT pass runs with the listed layers skipped (sd3.rs: Mmdit::forward_skipping(&[usize])). The guidance becomes cond + slg_scale · (cond − skip) on top of CFG, as stable-diffusion.cpp does.

  • SDXL refiner:

    • The refiner checkpoint is a UNet (384 base channels) conditioned by OpenCLIP bigG alone, with an aesthetic-score vector (6.0 / 2.5 for the negative prompt) instead of the target size.
    • Family::SdxlRefiner and unet.rs’s config come from the tensor shapes.
    • The base runs to refiner_at of the schedule, and the refiner continues on the same latents (no VAE round trip). Both stay loaded and the RAM is checked first (heavy.rs).

3. Group B: Z-Image and Chroma

Section titled “3. Group B: Z-Image and Chroma”

  • Chroma (Apache-2.0): Flux.1-schnell’s transformer with the modulation layers replaced by a small “distilled guidance” approximator network.

    • It uses T5-XXL only (no CLIP), with T5’s attention mask kept on the padding, and the Flux VAE.
    • flux.rs gets a Modulation::{PerBlock, Approximator} choice read from the tensor names (distilled_guidance_layer.*).
    • Family::Chroma, with CFG on (no distilled guidance) and default steps 26.

  • Z-Image (Tongyi-MAI, Apache-2.0; Z-Image-Turbo at 8 steps):

    • a 6B single-stream DiT (text and image tokens in one sequence, 3-axis RoPE);
    • Qwen3-4B’s hidden states as text, reusing llm.rs with a model-specific template;
    • the Flux VAE.

    The new module is crates/inga-diffusion/src/zimage.rs, with Family::ZImage. The reference is diffusers’ ZImagePipeline and stable-diffusion.cpp’s implementation, if present when the work starts.

4. Group C: editing with references (needs PR #591’s VAE encoder)

Section titled “4. Group C: editing with references (needs PR #591’s VAE encoder)”
  • Flux Kontext [dev]: the reference image is encoded by the VAE, patchified, and appended to the image tokens with RoPE index 1 (the first axis). Its outputs are dropped after each step. In flux.rs this is Flux::forward(…, refs: &[Fmap]). The guidance is distilled, 2.5 by default. Sizes are chosen from Kontext’s preferred list.
  • Flux Fill [dev]: the input has 384 channels: the noisy latents (64), the masked image latents (64), and the mask packed 8×8 into 256. The guidance is 30. The mask comes from PR #591’s --mask / multipart mask.
  • Qwen-Image-Edit (2509 / 2511):
    • The reference goes two ways. Qwen2.5-VL sees it through its vision encoder (the mmproj passed beside --llm; llm.rs gains images, using inga_model’s image path). It is also VAE-encoded (the Wan VAE’s encoder, new in wan_vae.rs) and appended as tokens.
    • Several references are supported (2509+).
    • diffusers’ QwenImageEditPlusPipeline is the reference.

5. Group D: Flux 2

Section titled “5. Group D: Flux 2”
  • FLUX.2 [dev]: a 32B rectified-flow transformer (double- and single-stream, as Flux with shared modulation), a Mistral Small 3.x language model as text encoder (through llm.rs; Inga runs Mistral), and a new 32-channel VAE (vae.rs with its config read from the shapes). It supports several reference images natively.
  • FLUX.2 klein (4B Apache-2.0, 9B non-commercial): the same transformer at a smaller size, with a Qwen3 text encoder (to be checked against the release).
  • New module flux2.rs, sharing flux.rs’s blocks where the shapes allow.
  • Realistically the 32B dev model needs a GPU and Q4 GGUF. On the CPU, klein 4B is the usable one.

6. Tests

Section titled “6. Tests”
  • For each family, a tiny synthetic model in crates/inga-diffusion/src/testing.rs (2 blocks, 64 wide), with shapes checked, a generation repeated by its seed, and the CLI against the server.
  • Name maps: every diffusers name of a synthetic folder maps to a name the model loads, and the fused qkv equals the three parts joined.
  • FP8: decoding E4M3 / E5M2 against a table of all 256 codes, the Q8_0 conversion error bound, and scale_weight applied.
  • SLG: with slg_scale = 0 the output equals the plain SD 3 run. The refiner at refiner_at = 1.0 equals the base alone.
  • Kontext / Fill / Edit: the reference tokens change the output, and they are dropped from the result’s shape.
  • Real-world checks (TODO.md, A), per family: the real file against diffusers or stable-diffusion.cpp at the same seed and sampler, PSNR above 30 dB on 512² at 8 steps, plus time and memory on the maintainer’s machines.

7. Risks and size

Section titled “7. Risks and size”
  • Memory: Flux 2 dev with Mistral Small is about 60 GB in bf16, so it is GPU-only in practice. Klein, Chroma and Z-Image fit 16-24 GB with Q8.
  • Several references are moving targets (Qwen-Image 2.1, klein’s text encoder). Each group is checked against the current diffusers code when it starts.
  • No new dependency. Each family adds tens of KB.

8. Phases and effort

Section titled “8. Phases and effort”
  • Group A (FP8, diffusers folders, SLG, refiner). M.
  • Group B (Chroma, Z-Image). M.
  • Group C (Kontext, Fill, Qwen-Image-Edit), after PR #591. M.
  • Group D (Flux 2 dev and klein). L.
