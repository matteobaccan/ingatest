Ollama's API, the rest: create, copy, delete, push, blobs

Status: 0.32.0 (moved to 0.33.0 and back to 0.32.0 on 2026-10-15: the maintainer wants Inga to replace Ollama; decided 2026-10-15). First proposal (asked by the maintainer on 2026-10-15, the drop-in set: “switch Ollama off, switch Inga on”). OC3 built (2026-10-15, branch feat/ollama-oc3, see “As built” at the end); OC1 and OC2 proposed. Family ollama of the API families. Code: crates/inga-server/src/ollama.rs (the routes), crates/inga-hub/src/local.rs (ollama_stores, ollama_models, inga_ollama_dir), crates/inga-hub/src/ollama_registry.rs (write_manifest, the layer media types), crates/inga-server/src/keys.rs (group), crates/inga-server/src/http.rs (is_upload, a streamed body), crates/inga-engine (the chat template, the model’s defaults), docs/api/ollama.yaml. New: crates/inga-hub/src/modelfile.rs, crates/inga-engine/src/go_template.rs.

1. What Inga has today, and what it lacks

Section titled “1. What Inga has today, and what it lacks”

Built (docs/api/ollama.yaml): GET /, /api/version, /api/tags, /api/ps, POST /api/show, /api/chat, /api/generate, /api/embed, /api/embeddings, /api/pull (into ~/.cache/inga/ollama/, or Ollama’s own store with --ollama-store).

Missing, checked against ollama.rs on 2026-10-15:

Ollama route or field Inga today This spec
POST /api/create 404 §3
POST /api/copy, DELETE /api/delete 404 §4
POST /api/push 404 §5: refused with a reason
HEAD /api/blobs/:digest, POST /api/blobs/:digest 404 §6
/api/ps the same list as /api/tags the loaded models only, with size_vram, expires_at, context_length (to verify the last against the official docs) from the router’s leases
/api/show empty modelfile, parameters, template, model_info the GGUF’s metadata as model_info (general.architecture, <arch>.context_length, …), the Modelfile Inga would write for it (§3.3), capabilities from inga_engine::capabilities instead of a fixed list, license
/api/generate’s suffix ignored fill in the middle through GenRequest.infill (the /infill path)
/api/generate’s context (in and out) not returned, ignored returned as the token ids of the conversation; taken back as the prompt’s start (deprecated by Ollama but still sent by older clients; to verify)
/api/generate’s template ignored a Go template for this request (§3.3)
/api/embed’s truncate, dimensions ignored truncate: false → 400 past the context; dimensions with embeddings part 2 (0.34.0)

logprobs, top_logprobs on chat / generate not read the OpenAI path’s log-probabilities (to verify the field names against the official docs: added to Ollama in 2025)

/api/version Inga’s version see §8, question 1
/api/web_search, /api/web_fetch 404 out of scope: Ollama’s hosted service (they need an ollama.com key, to verify); Inga’s web_search tool already answers the same need

2. What the user sees

Section titled “2. What the user sees”

Open WebUI’s model editor (“create a model from a Modelfile”), its delete button, and ollama create from a GGUF file on disk all work. The models created appear in inga list --ollama, the web UI’s library and /api/tags.

3. POST /api/create

Section titled “3. POST /api/create”

3.1 The protocol

Section titled “3.1 The protocol”

Current Ollama clients (the CLI since about 0.5.5; to verify the version) parse the Modelfile on the client, upload each file as a blob (§6), then send:

Older clients send {"name": "mymodel", "modelfile": "FROM …\nPARAMETER …", "path": …}; Inga accepts both: a modelfile string is parsed on the server by modelfile.rs into the same structure. Streamed answers (NDJSON, as /api/pull) are statuses such as {"status": "parsing modelfile"}, {"status": "using existing layer sha256:…"}, {"status": "creating new layer sha256:…"}, {"status": "writing manifest"}, {"status": "success"} (the exact strings to verify against the official docs; clients print them, none parses them but success and error).

The Modelfile’s instructions:

Instruction Layer written (application/vnd.ollama.image.*) What Inga does with it at run time
FROM a model name the base model’s layers reused (same digests) —
FROM a GGUF file / blob model the weights
FROM a safetensors folder refused in OC1: “convert it first (inga quantize)”; Ollama converts some architectures itself —
PARAMETER k v params (JSON) the model’s default sampling and options: temperature, top_k, top_p, min_p, repeat_penalty, repeat_last_n, seed, num_ctx, num_predict, stop (several), mirostat*; a request’s own fields win; unknown keys kept and listed by /api/show
TEMPLATE template §3.3
SYSTEM system the default system message when a request has none
ADAPTER adapter a LoRA loaded with the model (Model::add_lora; GGUF LoRA only; safetensors adapters refused as above)
LICENSE license printed at load as for pulled models, in /api/show
MESSAGE role text messages prepended to every chat with this model
REQUIRES config the minimum Ollama version; read and ignored (to verify the instruction against the official docs)

quantize: the model layer quantized with inga quantize (q4_K_M, q8_0, …, llama.cpp’s names; the same file llama-quantize writes), streamed as quantizing F16 model to Q4_K_M statuses.

3.2 Where the result goes

Section titled “3.2 Where the result goes”

As /api/pull: a manifest under ~/.cache/inga/ollama/manifests/registry.ollama.ai/library/ NAME/TAG (or Ollama’s own store with --ollama-store), blobs content-addressed, so Ollama itself can read what Inga created. ollama_models then lists it; reading the params, system, template, adapter and messages layers is new in local.rs (OllamaModel { model, projector, params, system, template, adapters, messages, license }), used by the server and by inga run ollama://NAME.

3.3 Go templates

Section titled “3.3 Go templates”

Ollama’s TEMPLATE is a Go text/template; Inga’s chat templates are Jinja (minijinja). Today Inga ignores Ollama’s template layer and uses the GGUF’s own tokenizer.chat_template. Proposed: go_template.rs translates the subset Ollama’s library uses ({{ .System }}, {{ .Prompt }}, {{ .Response }}, {{ range .Messages }}, {{ .Role }}, {{ .Content }}, {{ if }} / {{ else }} / {{ end }}, eq, and, or, {{ .Tools }}, {{ .ToolCalls }}, {{- -}} trimming, $var :=, slice, len, json) into a minijinja template, and only for a model whose TEMPLATE was given explicitly in a create (a pulled model keeps its GGUF template: it is the same text, better tested). A construct outside the subset: the create succeeds, the GGUF template is used, and the status stream and /api/show say which construct was not understood (informative rule). The converter is tested on the templates of the 30 most pulled library models (fixtures copied into tests/fixtures/ollama-templates/, their licences permitting; else hand-written equivalents).

4. POST /api/copy and DELETE /api/delete

Section titled “4. POST /api/copy and DELETE /api/delete”
  • copy {"source": "a", "destination": "b"}: a new manifest with the same layers; 200 with an empty body; 404 if source is not found.
  • delete {"model": "b"} (older name): the manifest removed, then every blob of the store no manifest references deleted (Ollama prunes the same way, to verify); 404 if not found. A model of Ollama’s own store is deleted only with --ollama-store (the store Inga writes into); otherwise 403 “this model is in Ollama’s store (~/.ollama/models); Inga deletes there only with –ollama-store”. A model loaded is unloaded first. Models that are not Ollama manifests (a GGUF in a folder, a Hugging Face cache entry) are deleted only through /api/inga/library/delete: 400 naming it.

5. POST /api/push

Section titled “5. POST /api/push”

Refused: {"error": "Inga does not publish models to a registry (push); use ollama push with Ollama, or upload the GGUF to Hugging Face"} with status 501, streamed as one {"error"} line when stream is true. The Ollama pull spec (O3) decided Inga does not publish. See §8, question 3.

6. Blobs

Section titled “6. Blobs”
  • HEAD /api/blobs/sha256:<hex>: 200 when the blob is in Inga’s store (or any store ollama_stores reads), 404 otherwise.
  • POST /api/blobs/sha256:<hex> with the raw bytes: written to blobs/sha256-<hex>-partial while hashed, renamed when the hash matches → 201; a mismatch → 400 “digest mismatch” and the file deleted; already present → 201 without reading the body past what is needed (to verify Ollama’s status for an existing blob).
  • Size: blobs are model files (GBs). http.rs reads bodies into memory up to 16 MiB (MAX_BODY) today; this route gets a streamed body (Request::body_reader, read straight to the partial file, no cap but the disk’s free space, checked first with inga_engine::disk_free against Content-Length). The same reader serves /v1/files (Batch and Files).

7. Errors, auth, tests, OpenAPI

Section titled “7. Errors, auth, tests, OpenAPI”
  • Errors in Ollama’s form {"error": "…"} (ollama.rs::error_body), with Ollama’s statuses: 400 for a bad Modelfile (the line and instruction named), 404 for a missing model or blob, 500 for a failed write. A streamed create ends with an {"error"} line, as /api/pull.
  • Auth: /api/create, /api/copy, /api/delete, /api/push, /api/blobs/* join /api/pull in the admin group of --api-keys (keys.rs::group): they change the server’s disk.
  • Tests (tests/server.rs, a synthetic GGUF): the CLI’s sequence recorded as request/response pairs (HEAD blob 404, POST blob 201, create with files, parameters, system, messages), then /api/chat with the model applies the system message and the parameters; the legacy modelfile string; copy then delete prunes nothing shared; a digest mismatch; push refused; /api/ps after a load and after an idle unload; suffix reaching the infill path; the Go template converter’s unit tests (go_template.rs) on the fixtures and on an unsupported construct. A real-world check in TODO.md group B: ollama create, cp, rm, and Open WebUI’s model editor against Inga.
  • OpenAPI: no new file; docs/api/ollama.yaml gains the routes (tests/api_specs.rs needs them when the routes land).

8. Open questions

Section titled “8. Open questions”
  1. /api/version: some clients compare it with Ollama’s versions to switch features on (to verify which: Open WebUI shows it; the ollama CLI warns when client and server differ). Report the Ollama version whose API Inga follows (a constant updated when the spec is followed again, e.g. 0.12.0) and Inga’s own as inga_version? Proposed: yes, with [api.ollama] version to override.
  2. Delete in Ollama’s own store without --ollama-store: allowed when Ollama is not running (the user switched it off)? Proposed: no; one flag, one rule.
  3. Push to a private registry (Harbor, a team’s registry), since /api/pull reads private registries with [ollama] token: worth it later? Not proposed now.
  4. FROM a safetensors folder: convert through Inga’s safetensors reader into a GGUF blob (Inga reads safetensors but writes GGUF only through inga quantize from GGUF today).

9. Phases and effort

Section titled “9. Phases and effort”
  • OC1 (M): blobs with the streamed body, create (structured and legacy), the layers read at run time but TEMPLATE, copy, delete, push refused.
  • OC2 (S): the Go template subset.
  • OC3 (S): /api/ps, /api/show, suffix, context, num_ctx, HEAD /, logprobs.

As built (OC3)

Section titled “As built (OC3)”
  • Code: crates/inga-server/src/ollama_models.rs (new: the names, /api/tags, /api/ps, /api/show), ollama.rs (the options), router.rs (loaded_contexts), lib.rs (GenRequest::context, with_context), inga-tokenizer’s has_fim (the card’s fill-in-the-middle now as /infill finds the tokens, by their text too).
  • Models of the Ollama stores by name: a name that is not one of the server’s is parsed as Ollama parses it (qwen3 is qwen3:latest) and looked up in ollama_stores(); found, it is added to the router as the web UI’s factory adds a model, under its Ollama name, and loaded on first use. inga serve ollama://NAME serves it under the same name (model_id kept the file stem, qwen3:0 for qwen3:0.6b). Other names keep the other APIs’ rules (the only model answers any name), but for /api/show, which answers 404 for a name the server does not have (ollama run then pulls it).
  • /api/tags: the server’s models, then the stores’ models it does not serve yet, then the API nodes’. Digests: an Ollama model’s manifest SHA-256 (what ollama list shows); a Hugging Face cache file’s blob name; any other file’s SHA-256, computed once in a background thread and kept by path, size and time (until it is done, the SHA-256 of those three: a 20 GB file takes a while, and /api/tags is asked at every client start). details from the GGUF’s header, kept the same way: general.architecture, parameter_size written as Ollama’s HumanNumber, quantization_level from general.file_type (Inga’s FileType names), else the type of most matrices.
  • /api/ps: the router’s idle list (loaded models only). size is the placement’s weights, experts and KV cache in RAM, or the GPU’s bytes when larger; size_vram the GPU’s; expires_at now plus what is left of the model’s keep (about 292 years when it stays, Go’s longest duration); context_length the context of its sessions. Ollama’s context_length field: as the spec’s table proposed, not verified against the official docs.
  • /api/show: model_info is every metadata key but the chat template, arrays over 5 values empty unless verbose (Ollama’s rule), general.parameter_count added when missing; template is the Ollama template layer (Go) of a store model, else the GGUF’s Jinja template; capabilities map Inga’s (text → completion, embeddings → embedding, reasoning → thinking, fill-in-the-middle → insert, tools, vision), the Ollama template’s .Tools, .Thinking and .Suffix adding theirs. The Modelfile is the one §3 parses (FROM the blob’s path).
  • Options: suffix makes the request an Infill (prefix = the prompt; the infill path’s 2 * n_predict saturates for Ollama’s unlimited num_predict); context is GenRequest::context, prepended to the prompt’s tokens (their BOS dropped), and the answer’s context is the request’s, the prompt’s tokens and the answer’s (not for raw or suffix, as Ollama); num_ctx larger than the model’s present context goes through Router::set_ctx (a reload), said in inga_num_ctx; logprobs / top_logprobs in the last object, in OpenAI’s per-token shape (token, logprob, bytes, top_logprobs; Ollama added the fields in 2025, the exact shape to verify); /api/chat with no messages loads or unloads (ollama run, ollama stop send it). /api/embed: truncate (true by default) against the model’s trained context (an embedding gets its own cache) or a smaller num_ctx; dimensions other than the model’s is a 400 until embeddings part 2; an empty input loads the model.
  • /api/version: OLLAMA_VERSION (0.12.0, §8 question 1) and inga_version (left out with --hide-version). The [api.ollama] version override waits for the configuration file of every setting (PR #650): no flag or variable was added for it.
  • Tests: tests/server.rs (ollama_s_list_ps_and_show_report_the_real_models: an Ollama store written in INGA_HOME with template, system, params and licence layers, /api/tags’ sizes and digests, ollama stop / ollama run’s loads, /api/ps after a load and after an idle unload, /api/show’s fields and its 404; ollama_s_generate_options_reach_the_engine: suffix against /infill, context out and in, logprobs streamed and not, num_ctx growing and not, /api/embed’s truncate, dimensions and empty input), the unit tests of ollama_models.rs.
