Video generation (Wan 2.x, LTX-Video, HunyuanVideo) — design and work plan

Status: V1 revised for Wan 2.1 T2V 1.3B first (§8, 2026-10-13; the 0.29.0 item puts it before LTX-Video), built on feat/video-wan21 on the CPU (see “As built (0.29.0)” at the end; not yet run on the real files); the rest proposed, 2026-10-09 (asked by the maintainer). 0.27.0 item “Video generation”, moved to 0.29.0. Builds on 0.20.0’s image generation crate inga-diffusion (#208; not merged when this was written): §3.1 states the interface this work expects from it, and the 0.20.0 implementation should keep it in mind. Impractical on a CPU; needs a GPU backend (CUDA on the maintainer’s P1000 first).

1. Goal and scope

Section titled “1. Goal and scope”
  • inga video MODEL -p TEXT -o out.webm (--frames, --fps, --width, --height, --steps, --cfg-scale, --seed, --image START.png for image-to-video), and POST /v1/videos in inga serve (OpenAI’s videos API shape: create a job, poll, GET /v1/videos/{id}/content), plus a “Video” tab in the web UI.
  • Models, in order: LTX-Video (2B DiT, highly compressed VAE: the fastest and the best fit for a 4 GB card), Wan 2.1 / 2.2 T2V-1.3B / TI2V-5B (Wan 2.2’s 5B with its 4×16×16 VAE), then HunyuanVideo (13B: only with weights streamed and the text encoder on the CPU; a stretch goal).
  • Checkpoints as published in the GGUF / single-file safetensors forms that stable-diffusion.cpp and ComfyUI-GGUF read (DiT in GGUF Q4_K/Q8_0, text encoder GGUF, VAE safetensors).
  • Output identical to stable-diffusion.cpp’s for the same seed and noise on a tiny synthetic checkpoint (as 0.20.0 does for images); on real models, visual parity.
  • Out of scope: training, LoRA for video (later, reusing --lora), audio tracks, real-time preview of every step (one preview frame per N steps only).

2. What the maintainer needs

Section titled “2. What the maintainer needs”
  • The P1000 (4 GB) with the CUDA backend through P5 (prefill-style matmuls and attention: a DiT step is one big prefill). Realistic sizes on it (§4): LTX-Video 768×512×49 frames, Wan 1.3B 480×272×33 frames; minutes per clip, not seconds.
  • stable-diffusion.cpp built with CUDA (-DSD_CUDA=ON) as the oracle and the speed reference; ComfyUI for visual comparison if available.
  • Disk: umT5-XXL (Wan’s text encoder) is ~6 GB in Q8_0, T5-XXL (LTX) ~5 GB: both run on the CPU once per prompt.
  • Crates for encoding the output (§3.4): png already allowed (APNG); a pure-Rust AV1 encoder rav1e (BSD-2, built without its asm feature so no nasm is needed) is the candidate for compressed video, justified in its PR; a WebM (Matroska) muxer written in Inga (~300 lines: EBML header, one track, SimpleBlocks) rather than a crate.

3. Design

Section titled “3. Design”

3.1 What inga-diffusion (0.20.0) is expected to provide

Section titled “3.1 What inga-diffusion (0.20.0) is expected to provide”

Video needs: a time axis in Latent / Pixels ([c, t, h, w]; images are t = 1), the flow-matching scheduler (also needed by Flux / Qwen-Image in 0.20.0), classifier-free guidance with a negative prompt, and a T5 / umT5 encoder (Flux needs T5 too). If 0.20.0 lands without these, video adds them there, not in a fork.

3.2 New model parts (crates/inga-diffusion/src/video/)

Section titled “3.2 New model parts (crates/inga-diffusion/src/video/)”
  • dit3d.rs: the video DiT blocks — 3D patch embedding (1×2×2 for Wan, 1×1×1 for LTX after its VAE), self-attention over all t·h·w tokens with 3D RoPE (separate frequency bands for time, height, width), cross-attention to the text tokens, AdaLN-style modulation from the timestep embedding, Wan 2.2’s MoE of two experts (high-noise / low-noise) chosen by timestep.
  • vae3d.rs: causal 3D convolutional VAEs (Wan-VAE: 4×8×8 compression, Wan 2.2 5B: 4×16×16; LTX: 8×32×32) decoded in temporal and spatial tiles with overlap so the activations fit in VRAM (the decoder is the memory peak).
  • t5.rs: T5 / umT5 encoder (relative position buckets), run on the CPU by default.
  • New ops for Backend (CPU first, then each GPU backend): conv3d (causal in time), group_norm, layer_norm, silu, upsample_nearest3d; attention without the causal mask (AttnOpts::full, there since 0.15.0 for Gemma 3’s image tokens and the vision encoders).

3.3 Running it on a 4 GB card

Section titled “3.3 Running it on a 4 GB card”
  • Weights: the DiT on the GPU (GpuLayers-like stage per block range; Wan 1.3B Q8_0 ≈ 1.4 GB, LTX 2B Q8_0 ≈ 2.1 GB); text encoder on the CPU; VAE on the GPU only while decoding (DiT weights freed or streamed meanwhile).
  • Attention over N = t·h·w / patch tokens is the cost: Wan 1.3B at 480×272×33 frames → 9×17×30 = 4 590 tokens per step; flash-attention kernels from the CUDA spec are mandatory (no N² score buffer).
  • Classifier-free guidance doubles the work; batch cond + uncond as two sequences.

3.4 Output

Section titled “3.4 Output”
  • .webm (AV1 via rav1e, our muxer) as the default; .apng / .gif (animated PNG through png; GIF via a small palette quantizer) for short clips; a directory of PNG frames with --frames-dir; .y4m raw for piping into ffmpeg.
  • MP4 / H.264 is not planned (no pure-Rust encoder of quality); AV1 in MP4 later if asked.

4. Phases

Section titled “4. Phases”
  1. V1 — LTX-Video on the CPU (correctness). T5 encoder, 3D DiT, LTX VAE, flow scheduler, APNG/PNG output; a tiny synthetic checkpoint matches stable-diffusion.cpp (or the reference diffusers run) within 1e-3 on latents after 2 steps.
  2. V2 — on the GPU. conv3d and friends in the CUDA backend, tiled VAE. Acceptance on the P1000: LTX-Video 2B Q8_0, 768×512, 49 frames, 30 steps in ≤ 15 min; the same seed gives the same frames as stable-diffusion.cpp CUDA (PSNR ≥ 35 dB); speed ≥ 80 % of stable-diffusion.cpp on the same card.
  3. V3 — Wan 2.1/2.2. umT5, Wan blocks, Wan-VAE, Wan 2.2 high/low-noise experts, image-to-video. Acceptance: Wan 2.1 T2V-1.3B Q8_0 at 480×272×33, 30 steps, on the P1000 within 2× stable-diffusion.cpp’s time, frames matching it (PSNR ≥ 30 dB).
  4. V4 — serving and encoding. /v1/videos, the web UI tab, WebM/AV1 output.
  5. V5 — HunyuanVideo (stretch): 13B DiT streamed layer by layer from RAM to the GPU (Model::stream_layers’ idea for DiT blocks), LLaVA-Llama-3 text encoder on the CPU. Acceptance: a 320×192×17 clip completes on the P1000 + 32 GB RAM.

5. Test plan

Section titled “5. Test plan”
  • CI (CPU, tiny synthetic checkpoints generated by a script in tools/, as 0.20.0’s): every new op against a scalar reference; conv3d causality (frame k of the output depends only on frames ≤ k); the tiled VAE equals the untiled one on a small latent; 2 denoising steps of a 2-block DiT equal the stored oracle latents; the WebM muxer’s output parsed back by a minimal EBML reader; APNG frame count and timing.
  • Maintainer (INGA_CUDA=1, INGA_MODELS): #[ignore] end-to-end clips with fixed seeds compared with stable-diffusion.cpp by PSNR; timings in docs/performance.md.

6. Risks and open questions

Section titled “6. Risks and open questions”
  • Time: even small clips take minutes on a P1000; every acceptance states sizes.
  • Model formats move quickly (Wan 2.2, LTX-2 with audio); support exactly what stable-diffusion.cpp reads at the time of V1 and document it.
  • rav1e is large; if its size or speed is unacceptable, keep APNG/PNG/Y4M and document piping Y4M to an external encoder (the user’s choice, not a dependency).
  • Open: should the web UI stream preview frames (latents decoded at low resolution every few steps)? Cheap with LTX’s VAE; proposed for V4.

Section titled “7. References”

8. Revision: Wan 2.1 T2V 1.3B first, on the CPU (0.29.0)

Section titled “8. Revision: Wan 2.1 T2V 1.3B first, on the CPU (0.29.0)”

The 0.29.0 item orders the models “the easiest first: Wan 2.1 T2V 1.3B”, with stable-diffusion.cpp’s Wan as the reference; LTX-Video comes after Wan 2.2. This revision replaces V1 (LTX-Video) with Wan 2.1 T2V 1.3B and takes from V3 and V4 what a first usable clip needs. 0.20.0’s image crate shipped without the traits of §3.1; video follows the crate as it is (feature maps ops::Fmap, one model struct with generate), with the time axis as the batch: a video is an Fmap of b = frames.

8.1 Scope

Section titled “8.1 Scope”
  • Text encoder: umT5-XXL (google/umt5-xxl‘s encoder, 24 layers, 4096 wide, 64 heads): t5.rs gains umT5’s one relative position bias per layer (T5 v1.1 shares the first layer’s) and a unigram vocabulary from the files (umT5 has 256,384 pieces, too many to build in): the GGUF file’s tokenizer.ggml.tokens / scores, or a tokenizer.json beside the encoder (or the diffusers folder’s tokenizer/). As diffusers’ WanPipeline: the prompt’s whitespace collapsed, the pieces and </s>, at most 512 tokens, encoded alone (a padded encoding under the attention mask is the same), then padded with zero rows to 512 (the DiT’s text_len), which go through its text embedding and are attended to.
  • DiT (video/wan.rs, Wan’s original names under model.diffusion_model. as stable-diffusion.cpp and ComfyUI read them, and diffusers’ WanTransformer3DModel names renamed to them): the 1 x 2 x 2 patch embedding, the timestep’s sinusoid (cos then sin, 256 values) through time_embedding and time_projection to six modulation vectors per block, the text through text_embedding (GELU, tanh), then per block: LayerNorm (no affine, eps 1e-6) modulated, self-attention with RMS-normed q and k (over all heads) and 3D RoPE (Wan’s split of a head’s pairs: d/2 - 2⌊d/6⌋ for time, ⌊d/6⌋ each for height and width, theta 10000, interleaved pairs), gated residual; LayerNorm with affine, cross-attention to the 512 text rows (RMS-normed q, k); modulated LayerNorm, GELU (tanh) feed-forward, gated residual; the head’s two modulation vectors from the time embedding, the 64 outputs per token unpatchified. Heads of 128 (Wan’s 1.3B: 12 heads of 1536; 14B: 40 of 5120).
  • VAE (video/wan_vae.rs): Wan 2.1’s causal 3D decoder, decoded one latent frame at a time as Wan’s feat_cache does: every causal 3 x 3 x 3 convolution keeps the last two frames it saw (zeros before the first), the temporal upsamplers (upsample3d, time_conv of 3 x 1 x 1 to twice the channels, the two halves becoming two frames) skip the first latent frame, so T latent frames give 1 + 4 (T - 1) frames. RMS norms over the channels, per-frame single-head attention in the middle, the latents un-normalized by Wan’s per-channel mean and deviation. The memory peak is one latent frame’s activations (four frames at full size), not the clip’s: no spatial tiling needed at Wan 1.3B’s sizes on the CPU. The 0.28.0 Qwen-Image branch (feat/qwen-image) has a single-frame decoder of the same VAE (wan_vae.rs, the kernels’ last temporal slice): the same computation as this one on one frame; when both are merged, Qwen-Image should decode with video::wan_vae (one frame) and its file go.
  • Scheduler: diffusers’ WanPipeline with the scheduler of Wan-AI/Wan2.1-T2V-1.3B-Diffusers: UniPCMultistepScheduler, flow prediction, flow sigmas shifted by 3 (--shift), bh2, order 2 with the corrector, lower order at the last step, final sigma 0; the DiT’s timestep ⌊1000 σ⌋ as diffusers truncates it. --sampler euler: Euler steps of the flow along the same sigmas (stable-diffusion.cpp samples Wan with Euler). Classifier-free guidance uncond + cfg (cond - uncond) (cfg 5 by default; 1: one pass per step). The noise: stable-diffusion.cpp’s Philox of the seed in [c][t][h][w] order (PyTorch’s CPU generator, which diffusers uses, is not reproduced).
  • Output without ffmpeg (§3.4, its short-clip formats): .gif (the gif crate the repository decodes GIF with, a median-cut palette of 256 colours shared by the frames), .png / .apng (lossless APNG through png), .y4m (raw YUV 4:2:0 to pipe into an encoder). WebM / AV1 (rav1e) and animated WebP stay for V4.
  • Interfaces: inga video MODEL -p TEXT -o out.gif (--negative, --frames, --fps, --width, --height, --steps, --cfg, --shift, --sampler, --seed, --vae, --t5xxl, --diffusion-model); inga serve with a video model serves OpenAI’s videos API: POST /v1/videos (a job: queued, in_progress, completed, failed, with progress), GET /v1/videos, GET /v1/videos/{id}, GET /v1/videos/{id}/content (the GIF; ?variant=apng), DELETE /v1/videos/{id}; one clip at a time, behind the machine’s memory-heavy jobs. No web UI tab yet (the item does not ask for one; §1’s tab stays for V4).
  • Defaults as diffusers’ WanPipeline: 832 x 480, 81 frames, 50 steps, cfg 5, shift 3, 16 frames per second. Sizes: width and height multiples of 16, 4k + 1 frames.

8.2 Tests (CPU, synthetic tiny models, no download)

Section titled “8.2 Tests (CPU, synthetic tiny models, no download)”

Tiny Wan files from testing.rs (Wan’s names, values from the hash of each name):

  • the causal 3D convolution against a direct six-loop one, and its frame-by-frame cached run equal to the whole clip at once;
  • the VAE decoder against a scalar reference written from Wan’s Decoder3d on the whole latent clip (causal padding, upsample3d skipping the first frame);
  • the DiT’s velocity against a scalar per-token reference of Wan’s WanModel.forward (patchify, sinusoid, modulation, RoPE, attention, unpatchify);
  • umT5’s per-layer bias against a scalar encoder;
  • UniPC against the numbers of a NumPy transcription of diffusers’ UniPCMultistepScheduler (tools/wan_unipc_oracle.py), and exact on a linear flow;
  • the GIF and APNG decoded back (frames, size, timing), the Y4M header and planes;
  • a whole generation from the tiny files (umT5 with a tokenizer.json) through the library, inga video and POST /v1/videos.
