Speech output and hands-free voice chat

Status: built for 0.26.5, on synthetic weights (asked by the maintainer on 2026-10-12: “I talk to the model and the model answers me”); what is left is in §9. Code: crates/inga-vision/src/wavtokenizer.rs (the vocoder), crates/inga-engine/src/tts.rs (the voice), src/commands/speak.rs (inga speak), crates/inga-server/src/voice.rs (/v1/audio/speech, the models chosen in the web UI), crates/inga-server/src/webui.html (the voice mode and the Voice section), crates/inga-server/tests/webui_voice.rs.

1. Why

Section titled “1. Why”

Inga hears: Whisper and Parakeet transcribe (inga transcribe, /v1/audio/transcriptions, inga serve --whisper), and the omni models read audio. It does not speak. Two TODO.md items of 0.26.5 close the loop:

  • Speech output (TTS): a first voice Inga runs itself, inga speak, OpenAI’s POST /v1/audio/speech;
  • Hands-free voice chat in the web UI: speak, the chat model answers, the answer is spoken while it is still written, and talking over it stops it.

2. The first voice

Section titled “2. The first voice”

The TODO.md item asks for a small, permissively licensed model first, Higgs Audio v3 (non-commercial) later. The candidates, against what Inga already has (a GGUF reader, every llama.cpp quantization, Qwen / Llama models, the CPU backend’s matrix products, Whisper’s and Parakeet’s convolutions and FFT):

Model Size What it needs besides Inga’s parts
OuteTTS 0.2 / 0.3 + WavTokenizer 0.5 B + 0.07 B a ConvNeXt vocoder, an inverse STFT
Kokoro-82M 0.08 B StyleTTS 2, iSTFTNet, a phonemizer
Piper (VITS) 0.02–0.08 B ONNX weights, espeak-ng phonemes
Orpheus 3B + SNAC 3 B the SNAC decoder; 84 tokens per second of audio
Higgs Audio v3 TTS 4 B its own GGUF layout; non-commercial

Chosen: OuteTTS with the WavTokenizer vocoder, as llama.cpp’s llama-tts:

  • The speaking model is a language model Inga runs already. OuteTTS is a Qwen2.5 (0.2 and 0.3, 500M) whose vocabulary holds 4100 audio tokens <|0|> … <|4099|>. It reads plain words: no phonemizer, the part that stops Kokoro and Piper (espeak-ng is GPL, misaki is Python).
  • The vocoder is small and made of known parts: a codebook (4096 × 512), a convolution, a “posnet” (four ResNet blocks with group norm, one self-attention, one group norm), twelve ConvNeXt blocks, a linear head to 641 magnitudes and 641 phases, an inverse STFT (FFT 1280, hop 320): 320 samples at 24 kHz per token, 75 tokens a second.
  • GGUF files exist for both, made for llama.cpp: hf://OuteAI/OuteTTS-0.3-500M-GGUF/OuteTTS-0.3-500M-Q8_0.gguf (the suggestion, see §2.1) and hf://ggml-org/WavTokenizer/WavTokenizer-Large-75-F16.gguf (general.architecture = wavtokenizer-dec); llama.cpp’s own preset (llama-server --tts-oute-default) pairs the vocoder with OuteTTS 0.2.
  • Licences: WavTokenizer is MIT. OuteTTS 0.2 500M is CC-BY-NC-4.0 (non-commercial). OuteTTS 0.3 500M is CC-BY-SA-4.0 (commercial use allowed, share-alike) as far as we know (§2.1: not read from its card here). Inga prints a file’s general.license when it loads it, and the web UI’s card shows it.
  • The suggestion is OuteTTS 0.3 500M (the maintainer’s decision, 2026-10-12: 0.2’s licence is non-commercial): the web UI’s Voice section offers it, inga speak’s and --tts’s help name it, GET /api/inga/voice returns it as suggested.speech (inga_engine::SUGGESTED_TTS). 0.2 files still run (§3).
  • Not the fastest: 75 tokens of a 0.5B model per second of speech is about real time on a recent CPU, slower on an old one. A first sentence is short, so the first sound comes after one sentence’s generation (§6, the time is shown). Kokoro (with a phonemizer of our own) is the candidate for a faster second voice.

3. The voice in the engine (tts.rs, wavtokenizer.rs)

Section titled “3. The voice in the engine (tts.rs, wavtokenizer.rs)”

TextToSpeech::load(model, vocoder): the OuteTTS file as an Engine, the WavTokenizer file as a WavTokenizer.

  1. Text → words, as llama.cpp’s process_text: lower case; numbers in words of the text’s language (TextLang): English (3.5 → three point five, 1,000 → one thousand, llama.cpp’s) or Italian (3,50 → tre virgola cinquanta, 1.000 → mille, 2026 → duemilaventisei, 23 → ventitré: comma decimals, dot thousands, the tens’ elision before uno / otto, the accent of a compound’s final tre, un milione, miliardi); - _ / , . \ as spaces; apostrophes dropped (l'acqua → lacqua, as OuteTTS’s processor does); other characters that are not letters dropped (letters of any script kept); words joined by <|text_sep|> (0.2) or <|space|> (0.3). The language is the request’s (inga speak --language, language of /v1/audio/speech, the page’s language in the web UI), else the voice file’s "language", else the model’s only general.languages entry, else English; a language Inga has no number words for is read as English and said so (inga speak’s summary, X-Inga-Text-Language). A voice saved with --save-voice records the language it was read in.
  2. Long texts in pieces: sentences (at . ! ? ; and new lines), grouped up to 30 words, each a prompt of its own; the audio of the pieces joined.
  3. The prompt: <|im_start|>\n<|text_start|> + the speaker’s words (if a voice is given) + the words + <|text_end|>\n<|audio_start|>\n + the speaker’s audio (word<|t_0.32|><|code_start|><|…|>…<|code_end|>\n per word; 0.3 without <|code_start|> and with <|space|> for <|code_end|>). The version (detect_version): the chat template outetts-0.3 (llama.cpp’s rule); else the version in general.name, general.basename or the file name (OuteTTS-0.3-500M-Q8_0.gguf; 0.1 and 0.2 share a format), else general.version; else a vocabulary with only <|text_sep|> (0.2) or only <|space|> (0.3). A file none of these tell apart is refused with what was read (template, names, which separators), not guessed; OuteTTS 1.0 (a name saying 1.0, or the DAC tokens <|c1_N|>) is refused as another codec.
  4. Generation: a Session with OuteTTS’s sampling (temperature 0.4, top-k 40, repetition penalty 1.1 over 64 tokens, a seed), stopped at <|audio_end|> or the end of turn; the audio tokens’ numbers are the codes.
  5. Vocoder: the codes through the network above, then the inverse STFT: each frame’s magnitude exp(m) (at most 100) and phase, the inverse real FFT, a periodic Hann window, overlap-add, divided by the window’s squared sum, the (1280 − 320) / 2 samples of padding cut at both ends.
  6. Voices: without one, the model picks its own (fixed by the seed), and the words it wrote for the first piece (with their durations and audio tokens, at most 20 words and a quarter of the context) become the voice of the next pieces; the server keeps the first voice it learns as its default, so the sentences of an answer, spoken one request at a time, keep one voice. A voice is an OuteTTS speaker file (interface.save_speaker: {"text", "words": [{"word", "duration", "codes"}]}): --voice FILE, or NAME for $INGA_HOME/voices/NAME.json.

The output: mono f32 samples at 24 kHz, written as 16-bit WAV or raw PCM.

4. inga speak

Section titled “4. inga speak”
  • --vocoder F (default the WavTokenizer above, downloaded unless --offline), --voice V, --language it|en, --temp X, --seed N, --format wav|pcm, -o FILE (default speech.wav; - the standard output), -f FILE or the standard input for the text.
  • Prints the licence, then the tokens per second, the real-time factor, the model’s format and the language the numbers were read in.

Section titled “5. Over HTTP”

5.1 POST /v1/audio/speech (OpenAI)

Section titled “5.1 POST /v1/audio/speech (OpenAI)”
Field Inga
input the text, at most 4096 characters
model any name: the server’s speech model answers

The answer is audio/wav (or audio/pcm, 24 kHz, 16-bit little-endian), with X-Inga-Audio-Seconds and X-Inga-Text-Language (it, en, or en (no number words for fr), the asked code kept to letters, digits and -). One text is spoken at a time.

5.2 Which models answer

Section titled “5.2 Which models answer”
  • From the command line: inga serve chat.gguf --whisper W --tts OuteTTS.gguf [--vocoder F] [--voice V].
  • From the web UI when the command line names none: the settings transcription_model, speech_model and vocoder_model (/api/inga/settings), loaded at the first request that needs them, replaced when the setting changes. POST /api/inga/pull takes "use": "transcription" | "speech" | "vocoder", as it takes "embeddings": the model is chosen once downloaded.
  • GET /api/inga/voice: which model answers each part, where it comes from (command line, settings), whether it is loaded, and the load’s error.
  • The library tells them apart (use): speech (Whisper, Parakeet), tts (a vocabulary with <|audio_start|> and the audio tokens), vocoder (wavtokenizer-dec).

6. The voice mode of the chat

Section titled “6. The voice mode of the chat”

A Voice button beside Send (and Alt+Shift+V: Ctrl+Shift+V is the browsers’ “paste as plain text”). Pressed:

  1. What is missing is said first. No transcription model (and a chat model that does not hear audio) or no speech model: a note names it and opens Models → Voice, where the cards offer the models of this machine or a download, as the embedding model’s cards do. A machine with a model of a kind gets its first one chosen. Browsers give a microphone only to HTTPS pages and localhost: another page is told so.
  2. Listening: the microphone with the browser’s echo cancellation, noise suppression and gain. Voice activity detection in the page: the level (RMS) of each frame (1024 samples, about 21 ms) against three times a noise floor that follows the room (at least 0.01), twice that while the answer plays; speech starts after 120 ms above it, ends after 800 ms below, 30 s at most. No button to stop talking. Speech that resumes before the transcription is sent joins it.
  3. Thinking: the speech (with 300 ms before its start) as a 16 kHz WAV, to /v1/audio/transcriptions, its text sent as a message. A chat model that hears audio gets the recording itself (two models instead of three).
  4. Speaking: the streamed answer cut into sentences (reasoning, code blocks and Markdown marks left out); each sentence to /v1/audio/speech as soon as it ends, played in order.
  5. Barge-in: speech while the answer is written or spoken stops both: the generation is cancelled, the audio cut, the queue emptied, the new speech recorded.
  6. The state shows in a bar over the input: Listening (with the level), Thinking, Speaking, and the time from the end of the user’s speech to the first sound. Esc or the button ends the mode; the bar is a live region for screen readers.

7. Tests

Section titled “7. Tests”
  • wavtokenizer.rs: a synthetic vocoder (testing::synthetic_wavtokenizer): the inverse STFT of a known spectrum against a direct sum, the group norm and the ConvNeXt block against direct loops, 320 samples per code, finite and deterministic.
  • tts.rs: the words of a text, numbers in English and Italian words (elisions, accents, scales, comma decimals and dot thousands), the language chosen from the request, the voice or the model, the prompt format told from the template, the names, general.version or the vocabulary and refused otherwise, the prompt of 0.2 and 0.3 with and without a speaker, pieces of a long text; a synthetic OuteTTS (a tiny Qwen2 whose vocabulary has the markers and audio tokens) with the synthetic vocoder: audio whose length is 320 samples per code generated, the same for the same seed; the WAV.
  • tests/speak.rs: inga speak writes a WAV (--language it, a voice file’s language, a refused language); inga serve --tts answers /v1/audio/speech (WAV, PCM, language and X-Inga-Text-Language, the refused fields) and --whisper the transcription of that WAV.
  • The server’s unit tests: the speech request’s fields, the settings’ new keys, the pull’s use.
  • webui_voice.rs (Playwright, Chromium’s fake microphone fed a WAV of a tone, then silence, then the tone again): the missing models said; listening → thinking → speaking; the transcription and speech requests (each with the page’s language); the sentences sent one by one; barge-in stops the playback and the stream; Esc ends.

9. As built

Section titled “9. As built”
  • Built: §3–§7, and Read aloud on every answer (the play button of the TTS item).
  • The inverse FFT is a true irfft (as torch.istft in WavTokenizer); llama.cpp’s irfft sums the one-sided spectrum and divides by n / 2 + 1, which differs by about 0.2 % in level and doubles the first and last bins’ weight.
  • The suggestion moved from OuteTTS 0.2 to 0.3 500M (the maintainer, 2026-10-12); Italian number words and the language choice added; the prompt format read from more than the chat template, and refused when unclear (§2.1, §3).
  • Not tried on the real files (the machines that built it had no access to Hugging Face): the pipeline is checked on synthetic weights only.
