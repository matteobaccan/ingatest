An Agent Skill for Inga itself, and llms.txt

Status: proposed for 0.33.0 (decided 2026-10-14). First proposal (feature survey of 2026-10-13, rank 23, Low). Files: new skills/inga/SKILL.md (and skills/inga/reference/*.md), new llms.txt at the repository root, .github/workflows/build.yml (the release job’s assets), a test module in the binary crate (src/commands/skill.rs, #[cfg(test)] mod agent_skill, since cli::parse lives there).

Decisions (2026-10-14)

Section titled “Decisions (2026-10-14)”
  1. Where it is published: release assets (inga-skill.zip, llms.txt) and Inga’s own default catalog; the public catalogs by hand later.
  2. inga connect claude-code|codex|opencode: a hint line only, never a write.

1. Goal

Section titled “1. Goal”

Coding agents (Claude Code, Codex, OpenCode, Cursor) are more and more asked “install a local model server and run Qwen on it”. llamafile 0.10.5 ships a skill that teaches agents to update it. Inga has a long command line; a skill gives an agent the few commands that matter and the way to diagnose a failure, so it does not guess flags.

2. What the skill holds

Section titled “2. What the skill holds”

SKILL.md (Agent Skills format, the one Inga itself reads, name: inga, description: “Install, run, update and troubleshoot Inga, a local LLM engine and server in one executable”), under 300 lines, with progressive disclosure:

  • Install: the release asset per OS and architecture (the names the release job publishes), checking SHA256SUMS, the Docker image, cargo install from source.
  • Run: inga run hf://…, inga serve MODEL --port, inga fit MODEL before a download, inga connect TOOL --run, inga service install.
  • Update: there is no inga update; how to replace the executable (the same asset, inga --version before and after, inga service restarted), and that $INGA_HOME is kept.
  • Troubleshoot: a decision list from symptoms to commands: out of memory (inga fit, --variant, --ctx), slow (inga bench, inga devices), GPU not used (inga devices, the backend features), model not supported (inga info, docs/supported-models.md), server unreachable (/health, the port, --host), error reports (inga system).
  • reference/: the command table and the HTTP endpoints, generated (below), read only when needed.

llms.txt (the llmstxt.org format): the project in one paragraph, then links to the README sections, docs/use-cases/README.md, docs/api/README.md, docs/integrations/README.md, the skill; llms-full.txt is not produced.

3. Keeping it true

Section titled “3. Keeping it true”
  • reference/commands.md is generated from src/cli.rs‘s help text by a test helper (INGA_BLESS=1 cargo test --bin inga agent_skill writes it, as the hardware profiles’ golden files), and the test fails when it differs, so a new flag cannot leave the skill behind.
  • Every line in SKILL.md that starts with inga inside a code block is parsed by the CLI’s parser (cli::parse) in the same test: a renamed command or flag fails it.
  • Every relative link in llms.txt and the skill must resolve to a file.
  • The skill is installed in a temporary $INGA_HOME with Skills::stage and approve: it must pass Inga’s own skill checks (frontmatter, limits).

4. Release

Section titled “4. Release”

The release job zips skills/inga/ as inga-skill.zip and copies llms.txt into final-release/ (the folder softprops/action-gh-release uploads), so both are on every release page and at releases/latest/download/…. The README’s Documentation section links them; docs/integrations/claude-code.md says how to install the skill (unzip inga-skill.zip -d ~/.claude/skills/).

5. Tests

Section titled “5. Tests”

The agent_skill tests as §3. Manual once: Claude Code with the skill installed, asked “install Inga and run Qwen3-4B”, on a clean Linux VM; the transcript summarised in the PR.

6. Phases and effort

Section titled “6. Phases and effort”
