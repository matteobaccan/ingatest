Hybrid models on the GPU, the rest: chunked prompts, LFM2, layers in one call

Status: part 1 built on feat/delta-chunked-gpu (2026-10-14; see As built), its measures on the P1000 runner and the RX 9060 XT left; part 2 proposed for 0.31.0 (decided 2026-10-14). This finishes H2 and H3 of 2026-10-10-gpu-hybrid-layers-design.md. That spec gives delta_chunked one sentence (§3.4) and lists the rest of H3 as left (§3.6). This spec designs them. TODO.md, 0.22.1: “H2, left” and “H3, left”. Code: crates/inga-gpu/src/ops.rs (GpuOps), crates/inga-gpu/src/host.rs (HostOps), crates/inga-gpu/src/layers.rs (GpuAttentionStages, GpuLayers::{delta, mamba, chunks}), crates/inga-cuda/kernels/{delta,ssm}.cu and src/device.rs, crates/inga-vulkan/shaders/ (new delta_chunk_*.comp, ssm_chunk_*.comp, short_conv.comp), crates/inga-model/src/model.rs (RemoteAttention, plain_attention), crates/inga-model/src/model/shortconv.rs, crates/inga-cpu/src/reference.rs (delta_head_chunked, DELTA_CHUNK), src/commands/placement.rs.

Decisions (2026-10-14)

Section titled “Decisions (2026-10-14)”
  1. Both CUDA and Vulkan in part 1: the PTX is built on the runner either way.
  2. The device state keeps the CPU’s layout ([n_v, dim, dim], row j = column j of S): a fixed rule, which the prefix-cache copies of the GPU layers rely on.
  3. LFM2 goes to part 2.

1. Goal

Section titled “1. Goal”

A prompt on a hybrid model reads as fast on the GPU as its attention layers already do. Today:

  • DeltaNet (Qwen3.5, Qwen3.6, Qwen3-Next): delta_step runs a prompt one token after the other. Each token reads and writes the whole state: per value head, dim x dim floats (64 KiB), twice. Thread j walks row j, so a warp’s loads hit 32 cache lines (kernels/delta.cu). For 32 heads, that is about 4 MiB of traffic per token per layer.
  • Mamba2 (Nemotron-H): ssm_scan keeps the state in registers. Every channel block re-reads the token’s B and C for its group and reduces over d_state once per token.
  • LFM2: one short-convolution layer keeps the whole model on the CPU (plain_attention: “short convolution (LFM2) layers”).
  • Round trips: every GPU layer of a split model is its own call (forward of RemoteAttention: upload the hidden state, run, read it back), even when the next layer runs there too.

No new flag. The gpu: line gains “short convolutions of layers …” for LFM2. Prompt speed shows in inga bench.

2. The chunked delta rule (H2)

Section titled “2. The chunked delta rule (H2)”

The CPU’s form (reference::delta_head_chunked, chunks of DELTA_CHUNK = 32), for chunk c of C tokens with cumulative log decays G:

T, W and U do not depend on the state, so every chunk of the prompt computes them at once. Only the last three lines run in order. Two kernels per layer and prompt chunk:

  • delta_chunk_prep: grid (n_v, n_chunks), one block per (head, chunk), dim threads. It L2-normalizes q and k (as delta_step), takes G, builds T by forward substitution in shared memory (32 x 32 floats), and writes W, U and the masked Q·Kᵀ to a scratch buffer: rows x n_v x (2 dim + C) floats, 16.5 MiB for 512 tokens of Qwen3.6 (32 heads of 128).
  • delta_chunk_scan: grid n_v, dim threads, chunks in order. Thread j keeps column j of S in registers or local memory, loaded once per prompt chunk instead of twice per token. The block computes Q·S0, W·S0 and the update with the chunk’s K, Q, W and U staged in shared memory: C x dim x 4 floats is 64 KiB for C = 32, so on the P1000 (48 KiB) the stage is split into two halves of 16 tokens.

C = 32 matches the CPU. With the same chunk boundaries, the GPU matches the CPU’s delta_head_chunked order of operations, and the existing tolerances hold. GpuOps::delta_chunked(qkv, gates, heads, rows, eps, state, out, scratch) has a default that calls delta_step, so a device without the kernels (Metal, a driver that refuses the module) behaves as today. GpuLayers::delta calls it when rows > max_rows (prompts). Decode keeps delta_step. The scratch is counted in GpuOps::reserve_prompt, so the prompt chunk sizing of 2026-10-13-gpu-runtime-memory-design.md accounts for it. HostOps runs the CPU reference.

The state layout does not change (decision 2): checkpoints (RemoteAttention::checkpoint) and the prefix-cache copies keep working. debug.delta_chunked = false (a key of inga.toml, the configuration file) keeps delta_step for prompts, so inga bench --ab debug.delta_chunked=false compares both forms.

3. The chunked scan (H3)

Section titled “3. The chunked scan (H3)”

The same idea for Mamba2, with the SSD form (“state space duality”, as in mamba_ssm’s chunk_scan). Per head and chunk of C = 64:

ssm_chunk_prep computes C·Bᵀ per (group, chunk) in parallel: it is shared by the heads of a group, so B and C are read once per chunk. ssm_chunk_scan then walks the chunks per (head, channel tile) with the state in registers, as ssm_scan. GpuOps::ssm_scan_chunked falls back to ssm_scan by default.

This half is gated on measurement (§6, step 1). ssm_scan already has a lot of parallelism (n_head x head_dim blocks), and its cost on the P1000 may be small next to the products.

4. LFM2’s short convolutions (H3)

Section titled “4. LFM2’s short convolutions (H3)”

As shortconv::forward, per layer: in_proj gives b, c and x; then c * conv(b * x) with l_cache taps and no SiLU; then out_proj. New pieces:

  • GpuOps::short_conv(bcx, rows, w, l_cache, past, out): one thread per channel, tokens in order, as conv_step. The b * x product and the c gate are fused, so there is no intermediate. CUDA: short_conv_f32 in kernels/delta.cu, loaded apart with it. Vulkan: short_conv.comp. HostOps: conv_seq.
  • Model::plain_shortconv(l) -> PlainConv (the three weights, l_cache), and a Mix::Conv in GpuAttentionStages, its state (l_cache - 1 inputs per channel) a Cache::State with its checkpoint, as DeltaNet’s convolution.
  • plain_attention no longer refuses the whole model. LFM2’s attention layers go through the usual path. The planner counts a conv block like an attention block.
  • LFM2-MoE (lfm2moe): the routed experts stay where the planner puts them, as for qwen35moe.

5. Consecutive GPU layers in one call (H3)

Section titled “5. Consecutive GPU layers in one call (H3)”

GpuAttentionStages::forward already runs chunks(pos0, &input, h, extra, (i, i..i + 1), ...) over a range of its layers. A span is the same call with i..j:

  • RemoteAttention::span(&self, l) -> usize. The default is 1. It counts the layers from l on that run there and leave nothing here: ffn(l) == RemoteFfn::Dense, or no feed-forward block (Nemotron-H’s Mamba2 and attention layers), and no Gemma 4 tail. The last layer of the span may have any ffn.
  • RemoteAttention::forward_span(l, n, pos0, h, shared). The default runs forward n times.
  • Model::forward’s loop (while l < first + layers.len()) calls forward_span when span(l) > 1 and no EAGLE-3 tap or control vector falls inside the span. Otherwise it goes layer by layer as now. Then l += n.

A Nemotron-H plan with its Mamba2, attention and squared-ReLU layers all on the card, and a Qwen3.5 dense plan with whole layers placed by attention stages, then move one hidden state per step instead of one per layer.

7. Phases

Section titled “7. Phases”
  • Part 1: step 1’s measures; delta_chunked (CUDA, Vulkan, HostOps); spans.
  • Part 2: LFM2’s convolutions; the chunked scan if step 1 shows ssm_scan above 10 % of a Nemotron-H prompt step.

8. Risks

Section titled “8. Risks”
  • Floating-point order: the chunked form sums differently from the token-by-token form. Comparing against delta_head_chunked (not delta_head) keeps the tolerances. The greedy-text check is the end-to-end guard.
  • Shared memory on Pascal (48 KiB) limits C, as §2 says. AMD and newer NVIDIA cards take the whole stage.
  • The PTX must be built by nvcc 12.4 on the runner (no nvcc in the development container). Clang 18 with ptxas 12.4 is the fallback, as for delta.ptx.
  • Binary size: two or three PTX kernels and four SPIR-V shaders, a few tens of KiB.

Effort: L (part 1 M, part 2 M).

As built (part 1)

Section titled “As built (part 1)”

Built on 2026-10-14 (branch feat/delta-chunked-gpu). Where the code differs from the design above, the code is described here.

Step 1’s measures. No P1000 or AMD card in the development container: the timing tests are written, and run on lavapipe only. recurrent_operations_speed in crates/inga-cuda/tests/layers.rs (#[ignore], INGA_CUDA=1 or INGA_HIP=1) times delta_step, delta_chunked and ssm_scan alone on 512 tokens at Qwen3.6’s and Nemotron-H’s sizes, each call waited for. delta_rule_speed in crates/inga-vulkan/tests/layers.rs does the same for the delta rule; ssm_scan at Nemotron-H’s size takes about a minute on lavapipe, too long for CI’s lavapipe job, so it is timed on the CUDA side only. hybrid_prompt_speed (both files) gives a synthetic Qwen3.5-style model’s pp512 with each switch on and off. The lavapipe numbers are in docs/experiments.md; the cards’ numbers, and with them the decision on §3, are left to the runner.

The kernels (crates/inga-vulkan/shaders/delta_chunk_{prep,scan}.comp; delta_chunk_{prep,scan}_f32 in crates/inga-cuda/kernels/delta.cu, the same source for HIP’s bundle):

  • The CPU’s order is kept but not its exact form: delta_head_chunked substitutes the corrections d directly (with K·S0 inside); the GPU solves [W U] once per chunk in the prep kernel and forms D = U - W·S0 in the scan, as §2 writes. The two agree within the existing tolerances (1e-4 of the largest value, op by op; 1e-3 on the logits).
  • The scratch record is 2 dim + C + 3 floats per token and value head: W, U, the row of M, then G and the query’s and key’s L2 scales (inga_gpu::delta_chunk_values). The scan reads q and k from qkv and applies the scales, so the normalized vectors are not stored.
  • The scan stages nothing in shared memory: thread j needs only its own column, and every thread of a block reads the same W, q and k rows (broadcast loads through the cache). So there is no 48 KiB limit on the P1000 and no split into halves of 16 tokens. Blocks are 32 threads for 32 columns, grid n_v x dim / 32 (128 blocks for 32 heads of 128, rather than 32 blocks of 128 threads). D_t is written over U_t[j], which only thread j reads, and o_t is formed as soon as D_t is known: no per-thread arrays indexed by the token, so the shader builds quickly (a first version with fully unrolled per-token arrays took 3.6 s to build on lavapipe at every device open).
  • The state stays in registers for heads of at most 128 (DELTA_D, the loops over the state unrolled; 255 registers on sm_61, no spills). Wider heads, and a device without the kernels (Metal; PTX or a HIP bundle built before them), go token by token: GpuOps::delta_chunk_scratch returns 0 there and delta_chunked calls delta_step.
  • The PTX was built with clang 18 and libdevice from CUDA 12.4 and checked with ptxas 12.4 for sm_61, as delta.ptx was before; tools/build-ptx.sh with nvcc 12.4 on the runner rebuilds it as the other modules. HIP’s delta.hipfb.gz was rebuilt with clang 18.1.3 (tools/build-hsaco.sh’s command, for this file only).

The switch. The configuration file has not landed (no inga.toml), and no new environment variable is added: GpuAttentionStages::set_delta_chunked and GpuStages::set_delta_chunked (on by default) are the test hook that compares the two forms; inga bench --ab debug.delta_chunked=false comes with the configuration file. GpuAttentionStages::set_spans turns the layers in one call off the same way.

The scratch is a buffer of each prompt chunk’s Scratch, made with the chunk as the other activations and counted in scratch_bytes for every prompt chunk size, rather than in GpuOps::reserve_prompt.

Spans. RemoteAttention::span and forward_span as §5. GpuLayers::span(l) counts the next local layers that are the model’s next layers, each before the last with ffn() == RemoteFfn::Dense (Nemotron-H’s single blocks included); Model::remote_span cuts it at a layer that runs here, a Gemma 4 layer, an EAGLE-3 tap or a control vector. A recorded decode step has a key of its own per span.

Tests. the_chunked_delta_rule_matches_the_cpus (Vulkan, CUDA): prompts of 1, 31, 32, 33, 100 and 517 tokens on one carried state, Qwen3.5’s and Qwen3-Next’s grouped heads, heads of 128, 64 and 16, against HostOps::delta_chunked (the CPU’s delta_head_chunked), then delta_step against the same. hybrid_prompts_match_by_chunks_and_spans (Vulkan, CUDA) and hybrid_prompts_by_chunks_and_spans_give_the_cpus_logits (HostOps): synthetic Qwen3.5 (and Qwen3.5 MoE, Qwen3-Next) models, prompts of 1 to 100 tokens and a rollback to a checkpoint, against CpuBackend (whose prompts go by chunks too), the spans on and off giving the same bits. hybrid_models_generate_the_cpus_text_by_chunks_and_spans (HostOps): Qwen3.5 MoE and Nemotron-H generate the CPU’s 64 greedy tokens twice in a session, with the layers in one call and one at a time. The older HostOps tests that compare bits with the reference backend’s token-by-token rule (hybrid_models_run_their_layers_on_the_device, routed_experts_run_on_the_device) keep delta_step with set_delta_chunked(false). SyntheticCfg::delta_heads sets a synthetic hybrid’s DeltaNet heads (Qwen3.6’s 16 / 32 for the speed test). The CUDA and HIP tests could not run here.
