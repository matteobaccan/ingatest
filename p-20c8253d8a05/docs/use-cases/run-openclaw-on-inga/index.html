Run the OpenClaw agent on Inga

Supported since: 0.25.0

What you get

Section titled “What you get”

OpenClaw is a personal agent you reach from WhatsApp, Telegram, Discord, Slack, Signal and other chat apps: it runs commands, reads and writes files, browses, keeps its own notes and runs scheduled jobs. Its “brain” is any model behind an OpenAI-compatible API. With this guide that model runs in inga serve on your own machine: OpenClaw keeps doing what OpenClaw does (the agent, its tools, its channels), Inga answers every model request, with tool calls, and can also hold the agent’s memory (Inga’s persistent memory, shared with the web UI and every other client). Inga’s own scheduled tasks (0.26.0, guide) can run prompts at set times too; OpenClaw’s scheduler keeps running its own jobs, on Inga’s model.

What was checked, and how: OpenClaw 2026.9.9 (npm) ran against inga serve with a synthetic test model, through a proxy that logged every request (huggingface.co is not reachable from the machine this was built on, so no real model): agent turns with openclaw agent exec and through the Gateway (openclaw gateway + openclaw agent), tool calls round trips (exec called, run, its result sent back, the answer) with both api: "openai-completions" and api: "openai-responses", reasoning kept apart, openclaw memory index / memory search on Inga’s embeddings, a scheduled job (openclaw cron run), a prompt longer than the context, and Inga’s memory with OpenClaw’s prompts. Those requests are replayed by openclaw_requests_are_answered in tests/server.rs. The chat apps themselves (WhatsApp, Telegram, Discord) could not be reached from there: their setup below follows OpenClaw’s documentation and was not tested.

Requirements

Section titled “Requirements”
  • Windows, Linux or macOS; any x86-64 or ARM64 CPU, a GPU helps a lot (see run-on-an-nvidia-gpu.md).
  • Node.js 24 (24.16 or later) or 26.1+ for OpenClaw (node --version); OpenClaw’s installer adds it when missing.
  • A model trained for tool calls whose chat template has tools (the web UI’s model card says tools; inga info MODEL shows the template): Qwen3 / Qwen3.5, Qwen3-Coder, gpt-oss, Llama 3.1+, Mistral Small 3+. An agent is demanding: models of 4B parameters work for simple tasks, 20–30B (an MoE model such as Qwen3-30B-A3B runs on a CPU) are much more reliable.
  • A large context: OpenClaw’s system prompt and tool definitions were about 33 KB of text in these checks (roughly 8 000 to 10 000 tokens of a real model’s tokenizer), before any conversation. Give Inga 32 768 tokens at least, 65 536 is better (OpenClaw’s own local recipes use 64K).
  • RAM: the model (about 18 GB for Qwen3-30B-A3B Q4_K_M, 2.5 GB for Qwen3-4B Q4_K_M) plus its KV cache (with --cache-type q8_0, about 3.4 GB at 65 536 tokens for Qwen3-30B-A3B).

1. Get Inga

Section titled “1. Get Inga”

Download the archive for your system from the Releases page and put inga on your PATH (details); inga --version checks it. This guide needs 0.25.0 or later.

2. Get a model

Section titled “2. Get a model”

The first is a mixture-of-experts model: it runs even with less RAM than its size (see run-a-mixture-of-experts-model.md).

3. Start the engine

Section titled “3. Start the engine”
  • --ctx 65536: the context (4096 by default, which OpenClaw’s prompt does not fit in). OpenClaw needs to know it too (contextWindow below).
  • --cache-type q8_0: half the KV cache’s memory.
  • --api-key change-me: requests must carry this key (Authorization: Bearer change-me); use your own random text. Leave it out only when nothing but your own user can reach the port. The server listens on 127.0.0.1:8080; to run OpenClaw on another machine, add --host 0.0.0.0 (then the key is a must).
  • --memory (optional, see step 6): every request uses Inga’s memory.

With one model, Inga answers whatever model name OpenClaw sends; with several (inga serve a.gguf b.gguf), the name must be one GET /v1/models lists.

Then add Inga as a provider in ~/.openclaw/openclaw.json (JSON5; on Windows %USERPROFILE%\.openclaw\openclaw.json), and make it the default model:

Or let OpenClaw’s onboarding write it (and the rest of a first configuration: the workspace, the Gateway’s token):

It names the provider after the address (custom-127-0-0-1-8080, so the model is custom-127-0-0-1-8080/qwen3-30b) and writes contextWindow: 128000 and maxTokens: 4096: set contextWindow to the --ctx given to Inga, or OpenClaw sends prompts Inga cannot hold. Notes on the provider:

  • api: with openai-completions OpenClaw calls POST /v1/chat/completions, streamed, with stream_options.include_usage, its tools and tool_choice: "auto", max_completion_tokens; with openai-responses it calls POST /v1/responses, streamed, store: false, the whole conversation as input items. Inga answers both, tool calls included. The checks found no difference; pick the first unless you have a reason.
  • Thinking models (Qwen3 Thinking, gpt-oss, Qwen3.5): set reasoning: true. Inga sends the reasoning apart (reasoning_content, or reasoning items in the Responses API), so only the answer reaches your chat app.
  • Images: for a vision model served with its projector (see chat-about-an-image.md), set input: ["text", "image"].

6. Memory: OpenClaw’s, Inga’s, or both

Section titled “6. Memory: OpenClaw’s, Inga’s, or both”

There are two independent memories; each works with the other or alone.

OpenClaw’s memory is Markdown in the agent’s workspace (~/.openclaw/workspace: MEMORY.md, USER.md, memory/YYYY-MM-DD.md), written by the agent with its file tools and searched with its memory_search tool. Its search uses embeddings, OpenAI’s by default; to keep them on your machine too, let Inga compute them:

OpenClaw then sends POST /v1/embeddings with its chunks (openclaw memory index --force) and with each query (openclaw memory search "coffee"). Without an embedding model Inga embeds with the chat model, which works but ranks less well: load an embedding model next to the chat model (inga serve CHAT.gguf nomic-embed-text.gguf --models-max 2, and use its name as GET /v1/models lists it; with two models the id of OpenClaw’s chat model must be the chat model’s listed name too; see embeddings-reranking-and-classification.md).

Inga’s memory (remember-across-chats.md) is a list of short facts in ~/.cache/inga/store/, on the machine running Inga: before each answer the closest ones are added to the system prompt, and the model gets three more tools, remember, recall and forget, which Inga runs itself (OpenClaw only sees the answer). The same facts are seen by the web UI’s chats, by other clients and by OpenClaw, and you see, edit and delete them on the web UI’s Memory page. Turn it on for OpenClaw with --memory on the server (every request), or only for OpenClaw’s model with an extra field OpenClaw passes through:

Inga recalls memories for the user’s own words: OpenClaw sends its runtime context (the active sessions and subagents, a Runtime: agent=... | os=... line) inside or after the user’s message, and Inga leaves those out of the search.

Which one to use: Inga’s when the same facts should follow you across OpenClaw, the web UI and other apps, and be managed on one page; OpenClaw’s when you want the notes as files in the agent’s workspace (daily notes, USER.md directives, its “dreaming” summaries). Using both is fine; the model then has two ways to save a fact, so tell it which one you prefer (in USER.md, for example “save facts about me with the remember tool”).

7. Chat apps (not tested here)

Section titled “7. Chat apps (not tested here)”

These steps follow OpenClaw’s documentation (docs.openclaw.ai/channels); they need the Gateway running (openclaw gateway) and real accounts, which the machine this guide was checked on could not reach. Every message from a chat app becomes an agent turn, answered by Inga as in step 5.

  • Telegram: create a bot with @BotFather (/newbot), then openclaw channels add --channel telegram --token <bot-token>. Send the bot a message: it creates a pairing request, which openclaw pairing list telegram shows; approve it with openclaw pairing approve telegram <CODE>.
  • WhatsApp: openclaw channels login --channel whatsapp installs the WhatsApp plugin and shows a QR code; scan it from WhatsApp’s Linked devices. Set who may write to the agent (channels.whatsapp.allowFrom: ["+15551234567"], dmPolicy: "pairing").
  • Discord: create an application and a bot in the Discord developer portal, enable the message content intent, invite the bot to your server, then give OpenClaw its token: export DISCORD_BOT_TOKEN=... and in the configuration channels: { discord: { enabled: true, token: { source: "env", provider: "default", id: "DISCORD_BOT_TOKEN" } } }.

OpenClaw’s documentation advises the Responses API (api: "openai-responses") for WhatsApp, so that only the final text is sent; with Inga both APIs keep the reasoning apart.

8. Scheduled tasks

Section titled “8. Scheduled tasks”

OpenClaw’s scheduler works unchanged with Inga as the model:

runs an agent turn on Inga every morning at 7 and sends the answer to that Telegram chat (the turn was checked with openclaw cron run <job-id>; the delivery to a chat app was not). Its heartbeat also runs an agent turn every 30 minutes; on a CPU each one costs a prompt evaluation, so set agents.defaults.heartbeat.every: "0m" to turn it off, or a longer interval. Inga’s own scheduled tasks (prompts run by inga serve at set times, with the memory and web search, results in the web UI) are the other way, since 0.26.0: Run prompts at set times.

Options worth knowing

Section titled “Options worth knowing”
Option Effect
--ctx N Context size; OpenClaw needs 32768 or more. Keep contextWindow in OpenClaw equal to it.
--cache-type q8_0 Half the KV cache memory.
--api-key KEY Require a key (apiKey in OpenClaw’s provider).
--host 0.0.0.0 Listen on every interface, for OpenClaw on another machine.
--memory Inga’s memory in every request (or inga_memory per model, step 6).
--prefix-cache SIZE KV caches of the conversations the server switches between: OpenClaw’s sessions, subagents and scheduled jobs share the same long system prompt.
--parallel N Answer N requests at once (a chat app and a scheduled job at the same time).
--web-search Inga’s web search tool in every request; OpenClaw has its own web_search / web_fetch tools, configure one of the two.

Limits

Section titled “Limits”
  • Context: OpenClaw’s prompt is long. When a conversation no longer fits, Inga answers OpenAI’s context_length_exceeded (“the prompt has N tokens, which exceeds the maximum context length of M tokens”); OpenClaw recognises it as a context overflow and compacts the session (or asks you to /new). Raise --ctx if it happens often.
  • Speed: on a CPU the first turn of a session evaluates the whole system prompt (minutes for a 30B model); later turns reuse the KV cache. A changing memory block (Inga’s memory, step 6) is in the system prompt, so when the recalled facts change between turns the prompt is evaluated again.
  • Streaming with tools: when tools are offered, Inga sends the answer once it is complete rather than token by token (it must see whether the text is a tool call); OpenClaw shows it when it arrives.
  • Small models call tools less reliably: a call written as plain text is not run (OpenClaw logs a warning). OpenClaw’s --local-model-lean / localModelLean and its Tool Search keep fewer tools in the prompt; a larger model is the real fix.
  • Not checked here: real models (only a synthetic one could be loaded), the chat apps, and Windows / macOS.

Troubleshooting

Section titled “Troubleshooting”
  • “LLM request failed: provider rejected the request schema or tool payload” with Inga’s message the prompt has N tokens...: an Inga older than 0.25.0 (OpenClaw read its context error as a bad request); raise --ctx, or update Inga.
  • 401 from Inga: OpenClaw’s apiKey differs from --api-key.
  • OpenClaw times out on the first turn: raise timeoutSeconds in the provider (and agents.defaults.timeoutSeconds if it is lower); watch the prompt being evaluated on Inga’s Server page.
  • Tool calls appear as text (<tool_call>... in the answer): the model’s chat template has no tools, or the model is too small; check inga info MODEL, try a larger model.
  • memory_search reports memory as unavailable: the embeddings request failed; check remote.baseUrl and apiKey, and that curl -H "Authorization: Bearer change-me" http://127.0.0.1:8080/v1/embeddings -d '{"input": "x"}' answers.
