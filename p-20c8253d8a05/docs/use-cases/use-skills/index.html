Give local models skills

What you get

Section titled “What you get”

Agent Skills are ready-made instructions for a task: a folder with a SKILL.md (a short header with a name and a description, then instructions in Markdown), reference files and sometimes scripts. Claude Code, Codex and OpenClaw (ClawHub) use the same format, and public repositories hold thousands of them. Inga installs them, lists their names and descriptions in the system prompt, and lets a model that calls tools load one when the request needs it (load_skill), read its files (read_skill_file) and, only if you allow it, run its scripts (run_skill_script), each run approved by you.

What was checked, and how: skills installed from a folder, a .zip holding several skills, and a git repository made by git (loose objects, then packed with deltas; at HEAD, a branch, an annotated tag and a commit) and served over git’s smart HTTP protocol by a local server; a whole server with a synthetic model made to call load_skill and run_skill_script: the review, the install, the refusal without --allow-skill-scripts, an approval answered through the API, “always allow”. The store: a local registry serving a skills-index.json (with ETags) and an archive, a local copy of ClawHub’s API answers, a repository made by git as a source (an update after a new commit), the Browse tab in Chromium; Anthropic’s repository read from a clone. Real skills from public repositories with real models, and ClawHub’s real service, are still to be tried (docs/todo/real-world-checks.md).

Requirements

Section titled “Requirements”
  • A model that calls tools (Qwen3, Llama 3.1+, gpt-oss, Mistral …) served by inga serve (serve-openai-and-anthropic-apis.md).
  • The home, --home DIR (default ~/.cache/inga): skills are kept in ~/.cache/inga/skills.
  • Installing from a URL needs the network (not --offline). Inga reads git repositories itself: no git program is needed.
  • Running scripts needs their interpreter on the server (python3, sh, node …) and inga serve --allow-skill-scripts.

1. Install a skill

Section titled “1. Install a skill”

Every file is shown before anything is installed:

The source is a folder, a .zip (a file or a URL) or a git repository (http(s)://, file://, a bare repository). --ref picks a branch, a tag or a commit; --path the skill’s folder when the source holds several (Inga lists them). inga skill add prints SKILL.md, every file with its size (scripts marked) and the warnings, then asks; --yes installs without asking. The version is pinned — git:<commit> or sha256:<checksum> — and a skill is never updated by itself: run add again with --replace.

A skill is installed under the name of its header. The format asks for lowercase letters, digits and -; a name written another way is turned into one (lowercase, spaces, _ and . as -, other characters left out, at most 64 characters): name: News installs as news, My Tool as my-tool.

In the web UI: Skills → the source (and the branch or folder) → Review: each file opens for reading; Install.

2. Find skills in the store

Section titled “2. Find skills in the store”

The Skills page’s Browse tab, and inga skill search, search the catalogs where skills are published: by default Anthropic’s skills repository (anthropics) and ClawHub (clawhub, OpenClaw’s registry, every skill MIT-0). Each card shows the name, the description, the author, the licence, the source, the files and whether it has scripts (when the catalog says), downloads and stars (ClawHub), the last change, and Install; a skill already there shows Installed, or Update when the catalog lists a newer commit, checksum or version. Install and Update open the same review as above — every file, the scripts flagged, the version pinned — and nothing is installed until you press Install there. A catalog is text written by strangers: the page shows it as text, never runs anything from it, and scripts keep their gate (§4).

Listings are kept in ~/.cache/inga/skills/.catalog/ and read again after six hours or on Refresh (--refresh); an unchanged repository or index is not downloaded again (its commit or ETag). A source that cannot be reached keeps its last listing, and the page says why in words. With --offline the listings kept are searched and nothing is downloaded.

A source is a git repository (every folder holding a SKILL.md), ClawHub’s API, or a skills-index.json you can host anywhere (a file on a web server, a gist, a folder):

name, description and source (a git repository or a .zip) are needed; path is the skill’s folder; ref (a commit) or sha256 (of the .zip) pins what is installed — an archive with another checksum is refused; version, size, files, stars, downloads and homepage are shown. The whole format is in the store’s spec §3.

3. Use it in a chat

Section titled “3. Use it in a chat”

In the web UI, turn on the chat’s Skills button (remembered for each chat). The model sees the skills’ names and descriptions; when your request matches one, it calls load_skill, follows the instructions and reads the files they mention. Each call shows under the answer (Tools: N calls), with the start of what the model was given.

From the API, any of the OpenAI, Anthropic, Ollama and Responses routes:

"inga_skills": ["pdf"] offers some skills only. A streamed answer carries an inga_tool delta per call.

4. Scripts (only if you allow them)

Section titled “4. Scripts (only if you allow them)”

Inga runs no other program unless you start the server with --allow-skill-scripts. Then the model may call run_skill_script(name, script, args, network), and each run asks you first: the web UI shows the skill, the script and the exact command, with Run, Don’t run and Always allow this script (and the network, when the script asks for it). Other clients see the request as inga_approval on the stream and in GET /api/inga/approvals, and answer POST /api/inga/approvals/{id} {"allow": true, "always": false, "network": false}. A run waits five minutes for an answer.

The script runs in a temporary copy of the skill’s folder, with a cleared environment and a 60-second limit; its output goes back to the model. Without the network permission its proxy variables point to a closed port: that stops programs that honour them, not every program, as the approval says. Ask again on the Skills page (inga skill revoke NAME) takes back “always allow”. When the script ends, or at its time limit, the processes it started end with it: on Linux and macOS it leads a process group of its own, which Inga stops whole; on Windows it runs in a job that ends its processes. A process that leaves the group on purpose (setsid) is not reached.

At the chat’s approval level Only pre-approved tools ("inga_tool_approval": "auto"), only the scripts you allowed “always” run; the others are refused without asking. At Ask for everything and Ask only for changes each run asks, as above (use-mcp-tools.md, “Approval levels and the “always” kept”).

Without --allow-skill-scripts, a model that tries is told the server does not run scripts, and the command, so it can tell you what it would have run.

5. In scheduled tasks

Section titled “5. In scheduled tasks”

A task allows skills with skills (all that are on) or skill:NAME (inga schedule add … --skills, the Schedules page’s Skills box). A task has no one to approve a script: it runs only those you allowed with “always allow” (schedule-prompts.md).

Safety

Section titled “Safety”
  • A skill is text and code written by someone else: its instructions reach the model and can try to steer it. Read it before you install it; prefer sources you trust.
  • A skill’s files are read inside its folder only; symbolic links and git submodules are left out; at most 500 files and 32 MiB.
  • --offline refuses URLs, and the store searches only the listings kept.
  • The store never installs without the review, and pins what it installs to the commit or checksum its catalog lists.

Options worth knowing

Section titled “Options worth knowing”
Option What it does
inga serve --allow-skill-scripts skills’ scripts may run, each run approved
inga skill add SOURCE --ref REF --path DIR a git reference; the skill’s folder in the source
inga skill add … --replace update an installed skill (it keeps its switch, not “always allow”)
inga skill add … --yes install without asking (scripts, CI)
inga skill revoke NAME its scripts ask again
inga skill search [QUERY] --source S --scripts / --no-scripts --license L --refresh the catalogs
inga skill add SOURCE/NAME a catalog’s skill, through the review
inga skill sources [add NAME URL --kind K | remove NAME | refresh [NAME]] the catalogs’ sources (git, index, clawhub)
"inga_skills": true | [names] a request’s skills

Troubleshooting

Section titled “Troubleshooting”
  • “holds N skills; choose one with –path”: the repository has several; give the folder Inga lists.
  • “is not an Agent Skill”: no SKILL.md in the source.
  • “name must be lowercase letters, digits and -”: nothing of the header’s name is left once it is made a skill name (only symbols, for example). A name such as News or My Tool is not refused: it installs as news or my-tool.
  • “cannot start python3”: the script’s interpreter is not installed on the server or not on its PATH.
  • “… could not be read: cannot reach …” on the Browse tab: the catalog’s server is down or the network blocks it; the listing kept from before is searched.
  • “the archive of … is sha256:…, not the sha256:… its catalog lists”: the file changed since the index was written; it is not installed.
  • The model never loads the skill: a model that does not call tools ignores it; check the model’s tools icon on the Models page, and that the skill is on.
