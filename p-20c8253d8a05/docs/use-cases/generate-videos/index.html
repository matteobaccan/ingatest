Generate video clips from text

What you get

Section titled “What you get”

A short clip from a sentence with Wan 2.1 T2V (1.3B, and the 14B model that has the same layout): the web UI’s Videos page makes one in a few clicks, inga video writes an animated GIF, an animated PNG or raw YUV frames, and inga serve offers the model to OpenAI clients through the videos API (/v1/videos). Inga computes it as diffusers’ WanPipeline does: umT5-XXL reads the prompt, Wan’s transformer denoises the latent clip with UniPC along the shifted flow (classifier-free guidance with the negative prompt), Wan’s causal 3D VAE decodes it frame by frame.

Read this first: video generation is impractical on a CPU. A 832 x 480 clip of 81 frames is 32,760 tokens per step of the transformer, 50 steps, two passes each; on a desktop CPU that is days. Use small sizes and few steps to try it (below), or another tool on a GPU.

Requirements

Section titled “Requirements”
  • Windows, Linux or macOS; any x86-64 or ARM64 CPU (AVX2 or AVX-512 make it faster).
  • Three files, as stable-diffusion.cpp and ComfyUI take them:
    • the transformer: wan2.1_t2v_1.3B_fp16.safetensors (2.8 GB; ComfyUI’s repackaged files) or a GGUF conversion (city96’s wan2.1-t2v-1.3b-Q8_0.gguf, 1.4 GB; for the 14B model wan2.1-t2v-14b-Q4_K_M.gguf, 10.1 GB). city96’s files keep the patch embedding’s kernel in five dimensions, which Inga reads since this release; the 14B file is unverified on its real weights;
    • the VAE: wan_2.1_vae.safetensors (250 MB);
    • umT5-XXL’s encoder: a GGUF file with its vocabulary (city96’s umt5-xxl-encoder-Q8_0.gguf, 6 GB), or a .safetensors file with google/umt5-xxl’s tokenizer.json beside it (umT5’s 256,384 pieces are not built into Inga). Scaled FP8 files (umt5_xxl_fp8_e4m3fn_scaled.safetensors) are not read.
    • Or a diffusers folder (Wan-AI/Wan2.1-T2V-1.3B-Diffusers: transformer/, vae/, text_encoder/, tokenizer/).
  • RAM: the files’ size plus the activations (about 200 bytes per token per hidden channel; inga video prints the tokens per step).

1. Get the files

Section titled “1. Get the files”

Or the three in one step: inga pull kit://wan2.1-t2v-1.3b (it ends with the inga video command that runs them; see generate-images.md). The 14B model’s kit, kit://wan2.1-t2v-14b, takes city96’s Q4_K_M file (pinned to the commit read on 2026-11-02) with the same VAE and umT5 files: Wan-AI’s two repositories hold the same Wan2.1_VAE.pth and models_t5_umt5-xxl-enc-bf16.pth (the same SHA-256), so a second kit downloads only its transformer. Both are Apache 2.0, and Hugging Face gates neither.

Make a short video in the web UI

Section titled “Make a short video in the web UI”
  1. Start the server with no model, or with a chat model: inga serve. Open http://localhost:8080.
  2. Open Videos in the side bar, right under Images. Without a video model the page offers Wan 2.1 T2V 1.3B: Download asks first (the size, the licence), then takes its three files. Find more video models (under Video models) opens the Models page’s Images section on its Video clips quick choice, where the 14B model is too.
  3. Choose the model at the top (or Load in Video models): it loads into the server’s video slot beside the chat model, its progress on the page, without a restart. An idle chat model is unloaded first when the two do not fit, and said.
  4. Write a prompt (Example puts one in), keep Quick try (256 x 256) and the length of 17 frames (about one second at Wan’s 16 frames per second), and press Generate. The other sizes are the ones the model is made for, as Wan-AI’s cards say: 480p landscape and vertical, and 720p for the 14B model. Steps and guidance on auto are the model’s own (50 and 5); the negative prompt is folded, the sampler, the shift and the frame rate are under Advanced.
  5. While the clip runs the page shows each stage (the queue, the prompt read, the steps with a bar and the time left at the pace of the steps so far, the frames decoded), the time elapsed, Stop (which deletes the job: it stops before its next step) and the colour drops game. The clip then plays on the page; Download keeps it as a GIF or an animated PNG (the Format field), Y4M frames as raw frames for ffmpeg.
  6. Recent videos lists the server’s jobs, newest first: Show plays a finished one again, Delete forgets it. A clip still running when the page is opened again is followed there.

The page talks to the same API as any client: POST /api/inga/media/load {"kind": "video", "model": "kit://wan2.1-t2v-1.3b"}, then POST /v1/videos, GET /v1/videos/{id} every second (its inga.stage and inga.step), GET /v1/videos/{id}/content?variant=gif, GET /v1/videos and DELETE /v1/videos/{id}.

2. Make a clip

Section titled “2. Make a clip”

A small, quick try (256 x 256, 17 frames, 8 steps):

Inga says what it runs (the model, the frames, the tokens per step, the sampler) and, at the end, the file and the settings, seed included. The defaults are WanPipeline’s: 832 x 480, 81 frames (about 5 seconds at 16 frames per second), 50 steps, guidance 5, shift 3.

Option What it does
-o FILE .gif (default video.gif; 256 colours shared by the frames), .png / .apng (animated PNG, lossless), .y4m (raw YUV 4:2:0)
--frames N 4k + 1 frames (Wan’s VAE makes four frames per latent frame after the first)
--fps N the file’s frame rate (default 16, Wan’s)
--width, --height multiples of 16
--steps N, --cfg X sampling steps; guidance (1: one pass per step, the negative prompt unused)
--negative TEXT what to steer away from
--shift X the flow’s shift: 3 for 480p (default), 5 for 720p
--sampler unipc|euler UniPC as diffusers (default), or Euler as stable-diffusion.cpp
--seed N the noise’s seed (stable-diffusion.cpp’s Philox generator)

An MP4 or WebM file needs an encoder Inga does not have; pipe the Y4M output into ffmpeg if you have it: inga video ... -o clip.y4m && ffmpeg -i clip.y4m clip.mp4.

3. Serve it

Section titled “3. Serve it”

A video model given on the command line is served alone, with OpenAI’s videos API: a clip is a job, generated in the background one at a time. inga serve with no model (or a chat model) answers the same API from its video slot once a video model is chosen (above).

seconds becomes 4k + 1 frames at fps; Inga’s extensions are frames, fps, steps, guidance_scale, shift, seed, sampler and negative_prompt; ?variant=apng or y4m on /content gives the other formats. GET /v1/videos lists the jobs and DELETE /v1/videos/{id} forgets one; a clip being generated stops before its next step. GET /v1/videos/{id}’s inga.stage says where the job is (queued, loading, waiting, text, steps with inga.step, decoding, done). The full description is in docs/api/openai.yaml.

Good to know

Section titled “Good to know”

Video runs on the CPU and writes GIF, APNG or Y4M. The Videos page shows the time each clip took; the Models page says “not measured yet” for a clip’s time, and its fit counts the files only, not the memory a clip takes. The tests run tiny synthetic models against references written from Wan’s code: the real files are unverified against stable-diffusion.cpp. The design is in the spec, 2026-10-09-video-generation-design.md.
