Chat in the browser and manage models from the web UI

Supported since: 0.18.0 (the chat page); 0.19.0 (the model hub, Markdown, presets, the Server page); 0.20.0 (the arena, the Thinking choice, live speed); 0.22.0 (the device per model, web search, themes and languages, the embedding model); 0.22.1 (chat branches and export); 0.22.2 (the Storage tab); 0.24.0 (Optimize, Check and the Version selector); 0.25.0 (installable as an app, phones, shared links); 0.26.3 (the remote mode: the page talks to another inga serve); 0.26.5 (the system monitor, the Documents page, downloads shown on their model’s row); 0.27.0 (Fits here for the models on this machine, the Skills and Tools pages); 0.30.0 (formulas and diagrams, the queue, the model’s questions, Compact, the Models page’s panels and boxes, the themed tooltips and what each quantization means, the download folder)

What you get

Section titled “What you get”

A chat page served by inga serve itself, with nothing else to install: conversations kept in your browser, answers rendered as Markdown, every sampler, images and audio, and a Models tab, as LM Studio’s, that searches Hugging Face, downloads models into the Hugging Face cache and loads them into the running server. The brain at the top of the left column opens Server: this machine, with the loaded models and live metrics.

Requirements

Section titled “Requirements”
  • Windows, Linux or macOS; any x86-64 or ARM64 CPU; a recent browser (tested in Chromium; Firefox, Safari and phones are in TODO.md’s real-world checks).
  • Free RAM for the model you chat with (Qwen3-0.6B in Q8_0: about 1 GB).
  • Network access to huggingface.co to search and download models from the page.

1. Get Inga

Section titled “1. Get Inga”

Download the archive for your system from the Releases page and put inga on your PATH (details); inga --version checks it. This guide needs 0.18.0 or later. The parts marked with a release need that release or a later one.

3. Start the engine

Section titled “3. Start the engine”

Or start it with no model at all — inga serve alone — and pick one on the page: the chat says No model loaded (0.28.0), with Load a model (the Models page, where Load loads any model on the machine or downloads one), up to three models already on the machine with a Load button each, and the API nodes’ models with Use. Until a model is loaded the APIs answer 503 no model is loaded yet; the page never moves to another tab by itself.

On a machine with no model at all (none downloaded, none in the model folders, no API node), the page shows the setup card instead (since 0.32.0): this computer’s memory and GPU, a model proposed for it — the largest of the six Qwen3 sizes (0.6B to 30B-A3B, Apache-2.0) that runs on the GPU, else the largest that runs in memory at 8 tokens per second or more — with what it is good at, its size, where it runs and how fast, and Download and start: the download (with its progress), the load and a first question in the chat (“Say hello and tell me in one sentence what you can do.”), each step said in plain words. Two ticks add the voice models and the document search’s embedding model, which become the server’s. Other choices lists the others that fit and the Hugging Face search; Not now hides the card in this browser. GET /api/inga/starters gives the list with the verdict of each.

Open http://127.0.0.1:8080/. To reach the page from another device of your network, start the server with --host 0.0.0.0 and an --api-key KEY (the page asks for the key: API key → Set… in the settings); --no-webui turns the page off and leaves only the APIs.

Chat with the models of another PC (remote mode, since 0.26.3)

Section titled “Chat with the models of another PC (remote mode, since 0.26.3)”

The page can talk to another inga serve instead of the one that served it: for example the models on a desktop PC (B) and the browser on a laptop (A) that runs its own inga serve, with no mesh. Start B so that it accepts the page of A:

--cors takes the page’s origin exactly as the browser shows it (http:// plus the host and port you opened A with, e.g. http://127.0.0.1:8080), or *. Then on A’s page open Settings → Server (bottom left of the chat; on the Models tab, the Server… button at the top), give B’s address (http://192.168.1.20:8080, or just 192.168.1.20:8080) and its key, and press Test or Connect. The answer is in plain words:

Message What to do
... answers: Inga 0.26.3, 2 models. Connect: the page now talks to B.
... cannot be reached B is not running, the address or port is wrong, B listens on 127.0.0.1 only (add --host 0.0.0.0), or a firewall blocks it.
... answers, but does not let this page call it Restart B with --cors and the origin the message gives.
The server needs an API key (401) / refused the API key (401) Give B’s key, or check it.

Connected, the Server window says so once, with how to come back, and a bar across the top of every page names B (Using the models of the server http://192.168.1.20:8080) with Change… and Disconnect; the Models page’s first line says the same (Remote server http://192.168.1.20:8080: the models below, their loads and the generation are on that server., or This server (http://127.0.0.1:8080) when not connected) with Change… and Disconnect beside it. Everything the page asks goes to B: the chat, the model menu, and the Models (downloads go to B’s disk), Server, API, Memory, Schedules and Storage tabs. The conversations stay in A’s browser as always. The address and the key are kept only in the browser’s storage for A’s page (like the API key of this server), never sent to A. If B goes away or its key changes, the bar turns red and says why. Disconnect forgets B’s address and key and the page talks to A again.

4. Check that it works

Section titled “4. Check that it works”

Type a message and press Enter (Shift+Enter for a new line). The answer streams in; under it a line gives the tokens per second while it is written and, at the end (since 0.20.0), N tokens in, M out, X tokens/s, first token after Y s.

The chat

Section titled “The chat”
  • Conversations stay in the browser’s storage (nothing is kept on the server). The box above the list searches them; a double click renames one.
  • Export and import (since 0.22.1): the download button saves the chat shown as Markdown, as a self-contained web page (HTML: code blocks, the reasoning folded, the sources listed; no script, readable offline) or as JSON — OpenAI’s messages list (role, content, reasoning_content), the system prompt first, with Inga’s own fields under inga (model, time, statistics, sources, attached files, the other versions of the conversation) and, at the top, the title, model, settings and times — or every chat as a backup. The upload button reads a JSON export back as a new chat (also a plain list of OpenAI messages), or a backup’s chats.
  • Share (since 0.25.0): the link button keeps a snapshot of the chat shown (its HTML export) on the server and gives a link, http://HOST:PORT/shared/<id>, that anyone can open read-only in a browser. The id is 128 random bits and is the only secret: with --api-key, creating, updating and revoking a link need the key, opening it does not, so give it only to whom may read the chat. Update snapshot puts the chat as it is now behind the same link; Revoke deletes it (the link then leads nowhere); the window also lists every chat shared from the server, from any browser. The snapshots are in ~/.cache/inga/shared/ (readable by the server’s user only, at most 12 MiB each and 1000 in all) and are the kind Shared chats of the Storage tab and of inga data (inga data list shared, inga data clear shared). The page is served sandboxed: no script runs in it and it loads nothing from elsewhere (pictures sent as links, not as files, do not show). The link uses the address the page was opened with: open the web UI by the computer’s name or LAN address, not localhost, to share it with others. Over HTTP: POST /api/inga/shared, GET /api/inga/shared, DELETE /api/inga/shared/{id}.
  • Messages: hover one for copy, edit, regenerate, delete. Code blocks have a copy button. A thinking model’s reasoning is shown apart, in a collapsible Reasoning block; while it streams, its Stop thinking button (since 0.30.0) ends the reasoning and the model answers at once.
  • Formulas and diagrams (since 0.30.0): $...$ and \(...\) in a line, $$...$$ and \[...\] on lines of their own are drawn by KaTeX (a price such as “$5 and $10” stays text; a display formula has Copy LaTeX). A ```mermaid block is drawn once its closing fence arrives, with Copy source, Source, Download SVG and Download PNG. Both libraries come with Inga (/webui/lib/, loaded the first time an answer needs them): nothing is fetched from the internet. The HTML export and shared links keep the formulas and diagrams as text.
  • Typing while an answer streams (since 0.30.0): the button reads Queue; the message waits above the box (edit it there, or remove it) and is sent when the answer ends, the next queued one after it. Send now on a queued message, or Ctrl+Enter in the box, stops the answer (its text stays) and sends at once. After Stop the queue waits: Send now, or Send with the box empty.
  • The model’s questions (since 0.30.0): when a chat uses the server’s tools (web search, the memory, skills or MCP tools) a model that calls tools may stop and ask up to four questions (ask_user): a card in the answer shows them with their choices and a field for your own words; Answer sends them and the model goes on, Skip lets it go on without. It waits ten minutes; the answers stay under the message. In the terminal: inga run model.gguf --ask-user.
  • Branches (since 0.22.1): editing a question (it becomes a box with Send and Cancel) or regenerating an answer — any answer, not only the last — keeps the old version: arrows ‹ 2/3 › under the message switch between the versions, each with the conversation that followed it. Delete on such a message deletes the version shown and what follows it. Chats saved before 0.22.1 are read as they are.
  • File attaches text files — source code (.java, .py, .js, .php, …), Markdown, JSON, CSV, logs, up to 2 MiB each — for any model: their content goes into the message as a fenced block named after the file (File \Hello.java`:`), and the chat shows it folded under the message. Inga warns when a file is close to the context size. Files can also be dropped on the message box. PDF and Word documents go to the server, which reads them (chat-with-documents.md).
  • Where the model runs shows beside it: CPU · AVX2 (the device and its kernels), RAM, disk when weights or experts are read from the disk (slower), network when part of it runs on other machines; the Server tab lists it for each loaded model, with the sizes. inga run and inga serve print the same line (note: runs on CPU (AVX2, 8 threads) · weights 4.20 GiB in RAM ...). A GPU badge (CUDA 0 Quadro P1000) names the GPU that runs layers; without one, hovering the CPU badge says why no GPU is used.
  • Attachments wait above the message box as cards (Sent with your next message): name, kind, lines and tokens for a file, a player for audio, a close button to remove one.
  • Under the box, the chat’s model says what it is and what it reads (Language model (LLM) · reads text, Vision-language model (VLM) · reads text, vision); Image and Audio are enabled only for a model that reads them (known once it is loaded), and an attachment it cannot read is marked in red.
  • The small buttons above the message box (their tooltip names them; the box takes the whole width): Image attaches pictures (PNG, JPEG) and Audio recordings (WAV, MP3, FLAC), for a model that sees or hears them (vision / audio in the Models tab) with its projector (see chat-about-an-image.md and ask-about-audio.md). The ring at the right of those buttons closes as the chat fills the context (orange past 75 %, red past 90 %); a click on it shows what fills it: the system prompt, your messages and files, the answers (counted with the model’s tokenizer) and the rest (the chat template, images, audio and tools), with the tokens still free. There, Compact (since 0.30.0) has the model summarize the older messages; a chat whose last prompt took 80 % of the context is compacted before its next message. The summary is a message of its own, editable, with the original messages collapsed under it and Restore to bring them back (keep-long-conversations.md).
  • Beside the ring, a line says where the chat’s model runs (runs_on of GET /api/inga/status): Qwen3-8B · this PC: GPU 24 layers, CPU 16, · this PC (master): layers 0–23 · pc2: layers 24–35 on a mesh, or · only this PC: ... · satellites not used (why); a click shows each node and device with its memory, and the Models page’s header says the server’s mesh role (master of mesh home, no mesh).
  • The first page of a browser session opens on a short splash (the Inga mark, “by Matteo Baccan”); a click or a key skips it.
  • Settings (bottom left): the Model, a Preset (Balanced, Precise, Creative, Code, and the ones you save with Save preset…), the Context, the Device and GPU layers, and Chat settings… (the system prompt, sampling and output: see below). The Model menu lists the loaded models and, under On this computer, the other models of the library that can chat: choosing one loads it (the server keeps up to --models-max loaded, 1 by default, and unloads the one used least recently).
  • Thinking (since 0.20.0): model default, on, off, or effort low / medium / high (gpt-oss’s levels; for the other thinking models, since 0.30.0, a reasoning budget of 1024, 4096 or 16384 tokens); models whose template has no switch ignore on and off (see use-thinking-models.md).
  • Compare with (since 0.20.0) is an arena: every question also goes to a second model, the two answers are shown side by side (A and B), and A is better, Tie or B is better picks the answer the conversation goes on with. The votes are counted per pair of models, in the browser (votes so far: 3 – 1 – 2). Serve both models, and let both stay loaded: inga serve a.gguf b.gguf --models-max 2.

The device: CPU or a GPU

Section titled “The device: CPU or a GPU”

Since 0.22.0 (Metal: 0.25.1; HIP and several GPUs: 0.27.0).

  • Device (left panel, under the Context): Auto (the server’s default: as many layers as fit on the best GPU, CUDA first, then Metal on a Mac, never a software device, the rest on the CPU), CPU, then every GPU of the server by API, number and name — CUDA 0 · Quadro P1000, Vulkan 0 · Quadro P1000, Metal 0 · Apple M2 (a Mac’s), HIP 0 · Radeon RX 7900 XTX, Vulkan 1 · llvmpipe (software) (Vulkan emulated on the CPU, offered for tests; Auto never picks it). A GPU Inga cannot use is listed but disabled, its reason on hover with its vendor, driver, Vulkan version or compute capability and free memory.
  • GPU layers: how many layers (the last ones) run on the GPU — a number, all, or empty for the default (Auto: as many as fit; a named GPU: every layer).
  • Several GPUs: POST /api/inga/device takes a list (cuda:0,vulkan:1), as --device does (run-on-an-nvidia-gpu.md).
  • A new choice reloads the model on the next message (POST /api/inga/device); the line under the fields then says where it really runs (Runs on CUDA 0 Quadro P1000: layers 0-15, ...) or, in red, why it fell back to the CPU (Runs on the CPU only: Vulkan 0 ...: too little free memory ...). A GPU chosen by name that cannot run the model makes the next message fail with the reason: choose Auto or the CPU.
  • Trying another backend is the quickest way around a GPU bug: if an answer looks wrong on one device, pick another and ask again; inga devices --test compares every device with the CPU (see run-on-an-nvidia-gpu.md).

Chat settings and the context window

Section titled “Chat settings and the context window”
  • Context (left panel, under the model): the model’s context window in tokens — how much of the conversation it sees — with the size it was trained for on hover. A new size reloads the model on the next message (POST /api/inga/ctx); empty goes back to the server’s --ctx.
  • Chat settings… opens a window with the system prompt and every setting, by group: Sampling (temperature, max tokens, top-k, top-p, min-p, seed), Penalties (repeat penalty and window, presence, frequency, DRY with its base, allowed length and window), Advanced (typical-p, top-n-sigma, XTC, mirostat with tau and eta) and Output (stop texts, JSON output, a JSON schema for structured output, a GBNF grammar, logit bias). Every field explains itself on hover. An empty field is not sent: the server fills it with the model’s recommended value, or with its own default (inga serve’s options, then Inga’s), and the field shows that value in grey. The line under the button lists the fields you set.
  • Recommended by the model (since 0.21.0), at the top of the window, lists the sampling the chat’s model recommends (from its generation_config.json, or the general.sampling.* keys of its GGUF file) once it is loaded; Use the model’s settings writes those values into the fields. There is no need to press it for the model’s values to apply: empty fields already get them. Settings saved by earlier versions held Inga’s defaults as values; they become empty once.
  • The settings belong to the chat: switching chats brings each one’s back, and a new chat starts from the last ones used. Reset to defaults empties them, so the model’s recommendation applies again.

Web search and sources

Section titled “Web search and sources”

Since 0.22.0 the model can search the web while it answers. Web, next to Audio under the message box, turns it on for the chat (each chat remembers it, and a new chat starts with the last choice); it takes effect with the next message. The server then offers the model a web_search tool: when the model calls it, Inga searches (DuckDuckGo by default, or the search services you checked, one after the other), gives the model the first results numbered [1], [2], …, and lets it answer — up to three searches per answer. While it searches, the line under the answer says searched the web for "…", reading the results…; the answer then streams as usual, with Searched the web: … above it and a Sources list under it: the title, link and site of every result the model was given, numbered as it saw them, so its [n] citations can be followed.

  • The model must be able to call tools: its chat template must render tool definitions (Qwen 2.5 / 3, Llama 3.1+, Mistral, gpt-oss, Gemma 4 and most recent instruct models). When it cannot, Web is greyed out and says why on hover.
  • Web search is a server-wide switch, on unless the server was started with --no-web-search or --offline. When it is off, Web offers to turn it on (for everyone using the server), and a chat that wants it shows Web search is turned off on this server with a Turn web search on button. With --offline it stays off.
  • Small models search less well than they chat: ask plainly (“search the web for …”) if the model answers from memory.
  • Since 0.30.0 Web also lets the model read a page (fetch_url): one you name (“summarize https://…”) or a search result, as text, cited like the results; pages on your machine or your LAN are refused. Files, beside Memory, appears when the server has a workspace folder and lets the model list, read, search and (each write approved in a dialog) write its files (guide).
  • Each search goes from the machine running inga serve, not from the browser: it needs network access to the search services. DuckDuckGo may block many searches in a row: it then answers 202 with its anti-bot page, and Inga waits a second and asks DuckDuckGo’s lite page instead (first, for the next ten minutes). When that is blocked too, the model is told the search is blocked, not to search again and to say so; searches then fail at once for a minute. Checking another service in Search services avoids this: the search goes on to it.

The Models tab

Section titled “The Models tab”

  • Download a file into the Hugging Face cache (the same cache inga pull and huggingface_hub use): its progress, with Cancel, shows where the model does, on the file’s row and on a row of Models on this machine → Hugging Face, in the box of its kind (there is no list of downloads); a failed one shows its error with Retry and Dismiss, and a finished one becomes the library’s row, the page staying on Models. A file already in the cache, or being downloaded, is not downloaded twice. An interrupted download resumes.
  • Models on this machine: the library, sortable by name, capabilities, size and status (inside each group), Hide unsupported beside its title hiding the models Inga does not run in every group (the counts say how many, remembered in the browser), each model with what it can do (text, vision, audio, tools, reasoning, embeddings, reranker, FIM, MoE; vision? when the architecture sees images but no mmproj*.gguf sits beside it) and Info: a window with its name, licence, architecture, parameters, quantization, context, shape, experts, the memory it needs and its projector. The Quantization column says what each file is (Q4_K_M, Q8_0, F16: the file name’s, else the type of most of its matrices), Fits here where it goes on this machine (GPU, RAM, disk) and the context it leaves, and Speed how fast it generates here: the memory planner’s estimate (~4.2 tok/s (estimate)), then measured once it has run here (16.4 tok/s gen, 210 tok/s prompt and (measured, …) on three short lines since 0.30.0); both sort. Grouped by where the models are — the Hugging Face cache, Ollama’s and LM Studio’s models (found by themselves, LM Studio’s custom downloads folder included), and every model folder — each model with whether Inga runs it (as inga list says), Load (it becomes the chat’s model; while it loads its row shows the load’s phase and Cancel, which stops it at its next step and drops what was loaded (since 0.32.0 also while it waits in the queue for RAM behind an image or another load, and between two layers of a long GPU upload) — the row keeps showing the load after leaving the page and coming back, and a load started elsewhere shows too; beyond --models-max the least recently used one is unloaded), Unload, Delete (since 0.22.0 for the models of the folders too: the GGUF file with every part of a split one, after a confirmation; Ollama’s models are removed with ollama rm), and Report for a model Inga does not run: it opens the GitHub issue form with the model, the error and the version already filled in. Inside each source, since 0.30.0, the models sit in boxes by what they are for: Chat and text, Images, Embeddings, Rerankers, Voice: transcription, Voice: speech and Voice: vocoder, each with its count. A model gets the actions of its kind (a Hugging Face repository of safetensors as a GGUF file): Load for a chat model, Use for embeddings (or In use) for an embedding model, Use for voice (or In use (voice)) for a transcription model, a speech model or a vocoder, with the command that runs it (inga transcribe, inga speak). Models loaded from the page use the server’s options (--ctx, --quantize, --cache-type, …).
  • Embedding model (documents and memory), a bordered panel under the library: the model document search (RAG) and the Memory use to turn texts into vectors and find the passages the chat model needs, apart from the chat’s; without one document search does not work, and a /v1/embeddings request without model uses it too (kept in ~/.cache/inga/settings.json, so the server remembers it). Since 0.28.0 the panel shows the model in use as a card of its own (Current model: its name and facts, with Change, Measure speed and Stop using; without one, Choose), then All models: one list of the machine’s embedding models and the suggested ones, each with one state badge and one action — Not downloaded with its size and Download and use, Downloading… with its bar and Cancel, Downloaded (or In LM Studio (…) / In Ollama / the folder it was found in: Inga reads it where it is) with Use, In use — and Delete for a model here. Each model says which languages it knows (English only, multilingual, or the languages its file names), the length of its vectors, the longest passage it takes, its size on disk or to download, its licence, its speed here and what it is good for: nomic-embed-text v1.5 (Q8_0, about 140 MB, English) first for an English page, BGE-M3 (Q8_0, about 600 MB, more than 100 languages, passages up to 8,192 tokens) for the others. Measure speed embeds eight passages with the model in use and keeps its tokens per second in the browser; the other models show an estimate from it, scaled by their parameters. Download and use turns the row into Downloading… at the click, shows the progress, and makes it the embedding model when it is done (the server does, so it happens with the page closed too), with no flash of the download button in between; the page stays on Models. The API tab says on the embeddings endpoints which model answers, or how to get one.
  • Voice (speech in and out), under it: one bordered panel per voice model, Hearing: transcription model, Speaking: speech model and Speaking: vocoder, each saying what its model is for and when it is needed, with the model in use and the others to choose or download, as the embedding model’s (talk-to-a-model-by-voice.md).
  • Model folders (the gear at the top of the page, since 0.28.0): where LM Studio’s and Ollama’s models were found, the folders given with inga serve --models-dir DIR (repeatable), and the ones you Add folder on the page (kept in ~/.cache/inga/model-dirs.json, removable). Each is scanned four levels deep for GGUF files and Hugging Face model directories, or read as an Ollama store when it is one (it, or its models folder, holds manifests and blobs: add Ollama’s folder this way when OLLAMA_MODELS points elsewhere than ~/.ollama/models or is not set for Inga); a spinner and the seconds elapsed show while it runs, and each folder says how many models it holds and how many of them Inga runs (3 found, 2 supported). Its Download folder (since 0.30.0) says where downloads go (the Hugging Face cache) and why, with the machine’s disks and their free space: Use for downloads sends new downloads to another folder, Move the models here moves the downloaded ones there too, with its progress and Cancel (refused while a model of the cache is loaded, loading or downloading); HF_HUB_CACHE and HF_HOME win over it. A download that does not fit the disk is refused at once, saying how much it needs and how much is free, with Another folder…, as beside a model too big for the disk (run-a-model-from-hugging-face.md).
  • Optimize (since 0.24.0): a library row (and its Info window) opens the Optimize window, which lists the original first and then the smaller variants Inga could make of the model for this machine (each with its size and how much smaller, where it would run: GPU, RAM or disk, the speed estimate and its change from the original’s, and the expected quality) and makes the one you pick in the background, with its progress. Optimize shows only for a model it can make smaller (never for a Q1_0, Q2_K or Q3_K file); the variant Inga proposes is in its tooltip. The Version selector next to Load picks the variant (or the original) that runs, Check measures a variant against the original (perplexity ratio, KL divergence, same top token), and the Server tab’s “optimize automatically” (off by default) makes the proposed variant by itself. The Server tab

Section titled “The Server tab”

The page of this machine has no entry in the left column (since 0.28.0, so that the column’s only Server is the Developer group’s, the API server’s): click the brain logo at its top, or focus it and press Enter or Space. The logo turns briefly (it stays still with reduce motion) and stays lit while the page is open; on a phone it is the first item of the bottom bar. Its tooltip says Server: this machine.

Refreshed every second: the server’s version and settings (context, --parallel, --models-max, --idle-unload, prefix cache, context shift, API key), the loaded models and their state (since 0.21.0 with how long each has been idle and, with --idle-unload or a request’s keep_alive, when it will be unloaded: idle 3 min, unloads in 7 min), the requests (answered, running, busy sessions), and the tokens: in and out, those taken from the cache, the average speeds and, since 0.20.0, the live tokens per second with a chart of the last two minutes. Since 0.22.0 it lists the Devices — every GPU with its type, driver, free and total memory and whether it is usable (yes, Auto picks it, only when chosen for a software device, no: ... with the reason), the CPU, and the APIs without devices (CUDA: no NVIDIA driver found) — and, for each model, the Device chosen for it (auto (server), cpu, vulkan:0, all GPU layers) beside where it actually runs, with the reason when a model fell back to the CPU or a GPU was passed over.

Each row of the Settings table says how it changes (since 0.30.0): the settings that change while the server runs (Models loaded at most, Unload a model unused for, Models loadable from this page) have a Change button that opens Developer → Server, where they are set, and the embedding model’s row a Change that opens its panel on the Models page; the others say “set when the server starts”: they are options of inga serve. The table is drawn again only when a setting changed, so it no longer blinks.

The Settings table also holds the web search switch (Web search, a checkbox that applies at once) and, since 0.28.0, the Search services: one row per service Inga knows — DuckDuckGo, Wikipedia, SearXNG, Brave Search, Tavily — each with a checkbox (“use this too”). A search goes to the first one checked, and to the next when it fails, is rate-limited (DuckDuckGo’s anti-bot page, a 429) or finds nothing; the Sources under the answer say which one answered (via in inga_sources). Drag a row, or use its up and down buttons, to change the order. SearXNG takes the /search URL of an instance (https://searx.example/search, with json among its search.formats); Brave Search and Tavily take an API key, kept encrypted in ~/.cache/inga/secrets.json and never shown again (without one, BRAVE_API_KEY or TAVILY_API_KEY is read). Every change applies at once (POST /api/inga/settings). The switch and the services are kept in ~/.cache/inga/settings.json, with the embedding model, and are the values of the next start; an explicit --no-web-search or --search-backends LIST wins over them, and --offline always turns web search off.

Section titled “The Developer group: Server and API docs”

At the foot of the left column (in the bottom bar on a phone, after a thin line), a Developer group holds two pages, on the model of LM Studio’s Developer section (since 0.28.0): Server, the API server as other programs see it, and API docs (below).

Server answers “where is it, who calls it, what passes, what do I set”:

  • The top bar: a Running badge with the uptime (stop the server where it was started: Ctrl-C or inga service stop), Server settings, mcp.json (the file, its servers and their state, what runs without asking) and Load model (the Models page). Enable CORS (with the allowed origin), Just-in-time model loading (off: a request naming a model that is not loaded gets a 409 until it is loaded), Auto-unload unused models (the idle time in minutes) and Only keep last loaded model change at once and last until the server stops (POST /api/inga/settings {"server": {...}}); the command line gives their start values.
  • Loaded models, each with its id to copy and Unload; with none, “Use Inga from other apps or from your code” and a Load model button.

Copy copies the lines as text, Clear empties the view, Follow keeps the newest line in sight. The web UI’s own polling is left out. No prompt or answer text is kept. Since 0.32.0 each request’s row has Logs, which opens its lines on the Logs page (its tooltip has the request’s id, and its trace’s id when the server sends traces with --otlp-endpoint).

Logs

Section titled “Logs”

Since 0.32.0, Developer → Logs shows the server’s own log: what inga serve prints on its terminal (a model loading, the GPU it uses or passes over, an MCP server that does not start, a skill loaded, a web search, warnings and errors), which a user of the web UI or of inga service does not see otherwise.   • Filters, applied by the server to every line it keeps (not only those on screen): the level, the source (a menu of those seen), a search (any case; /regex/ for a regular expression) and Only errors.

/ and ? are never taken while you type in a box, and Ctrl+Shift+O and Esc are left alone in any box other than the message box (editing a message, the chat filter, a setting).

When the server stops (since 0.28.0)

Section titled “When the server stops (since 0.28.0)”

The page watches the server it talks to (this one, or B in remote mode): it asks GET /health every 5 seconds while the tab is shown (every 30 seconds while it is hidden), and every request it makes counts too. When the server stops, cannot be reached or answers only with errors (a 502 of a proxy before it), a bar at the top of the page says so: Inga is not responding — the server at http://127.0.0.1:8080 stopped or cannot be reached. Retrying in 4 s…, with what to do (start inga serve again, check the address; in remote mode, B’s --cors) and Retry now. It tries again after 2, 4, 8 and 16 seconds, then every 30. Meanwhile:

  • the logo turns grey and the Server tab gets a red dot;
  • Send is off (its tooltip says why) and the text you typed stays in the box;
  • an answer that was streaming keeps what came, with Connection lost: the answer stopped here under it;
  • the other tabs show their data greyed under Not live: last updated 10:42:17, and their buttons (Load, Download, Delete, …) are off with the reason; Change… and Disconnect still work.

When the server answers again the bar says Connected again. for a few seconds, and the models, the status and the tab shown are read again. If it restarted meanwhile (another start time in /health), the bar says The server restarted: loaded models were reset.: load the model again from the menu; after an upgrade it offers Reload page for the new version’s page. The conversations are never touched. The installed app opened with no server running shows the same bar instead of an empty page.

On a phone, and as an installed app

Section titled “On a phone, and as an installed app”

At phone width the tabs move to a bar at the bottom, the menu button (left of the attach buttons) opens the chats and settings as a drawer that a tap beside it, its close button or Escape closes, buttons and fields grow to finger size, the page never scrolls sideways, and while you type the on-screen keyboard takes the place of the tab bar instead of hiding the message box.

The page is also an installable app (a PWA, since 0.25.0): the browser’s Install (or Add to Home screen) puts Inga on the desktop or the home screen with its own icon and window, without the address bar. Inga serves the manifest (/manifest.webmanifest), the icons (/icons/*) and a service worker (/sw.js) that keeps only the page and its icons, so the app opens even while the server restarts; chats, answers and API calls always go to the server and are never cached. The cache is named after Inga’s version: after an upgrade the next visit loads the new page.

Browsers allow the install and the service worker only on https:// addresses and on localhost. On the computer that runs Inga, http://localhost:8080/ is enough. From a phone on the LAN:

  • Without HTTPS (inga serve --host 0.0.0.0, then http://192.168.1.20:8080/ on the phone) the page works fully in the phone’s browser, and Add to Home screen still adds a shortcut, but the browser does not install it as an app nor run the service worker.
  • As an app: put a TLS reverse proxy in front of Inga, for example Caddy with a certificate the phone trusts (caddy reverse-proxy --from inga.home.example --to 127.0.0.1:8080 for a name with a public DNS record, or Caddy’s tls internal with its root certificate installed on the phone), or Tailscale’s tailscale serve 8080, which gives the computer an https://*.ts.net address with a valid certificate on your tailnet. Keep Inga on 127.0.0.1 behind the proxy and set --api-key if the proxy is reachable by others.

Themes and languages

Section titled “Themes and languages”

Settings, the last entry of the side bar (a phone’s bottom bar), opens a menu with the theme, the language and About (the version, the build, a link to the releases); arrow keys move in it and Escape closes it. Theme: Auto follows the computer’s light or dark setting, Light and Dark fix one, Matrix is phosphor green on black in a monospace font with a faint falling code behind the conversation (still when the system asks for reduced motion), Blade Runner is neon orange, cyan and magenta on a teal night, Tron is a black grid lit in cyan with your messages in orange, and Commander has Norton Commander’s colours: cyan text on a VGA blue screen, yellow headings, the selection as a cyan bar, square double borders and a monospace font. Language picks the interface’s language: Automatic follows the browser’s languages (navigator.languages; pt-BR and pt-PT are both Português), else English, Italiano, Français, Deutsch, Español, 简体中文, Português (Brazil’s wording), Русский, 日本語 or हिन्दी. Dates and numbers follow the page’s language too. Japanese and Hindi use the system’s fonts for their scripts in every theme, the monospace ones included. Both choices stay in the browser (localStorage keys inga.theme and inga.lang). Only the page is translated: the models’ answers, model names, API paths, code samples and the OpenAPI files of the API docs stay as they are. Arabic, which needs a right-to-left page, is not there yet.

The page’s tooltips are its own (since 0.30.0): a box in the theme’s colours instead of the browser’s grey one, shown after 300 ms on hover or keyboard focus, above or below the element and inside the window, with its line breaks kept; leaving, scrolling, a click or Escape closes it (screen readers get it through aria-describedby; with reduce motion it does not fade).

Options worth knowing

Section titled “Options worth knowing”
Option Effect
--host ADDR, --port N Where the page and the APIs listen (127.0.0.1:8080).
--api-key KEY Every API call needs the key; the page asks for it once and keeps it in the browser.
--models-max N Models loaded at a time (1); needed at 2 for the arena.
--no-webui No page at /.
--no-web-search Web search starts off; the Server tab turns it on.
--search-backends LIST The search services tried in order, for this run (searxng=https://host/search,brave,duckduckgo).
--web-search Every chat request searches unless it says "web_search": false (API clients included).
--ctx N, --quantize TYPE, --cache-type q8_0 How every model is loaded, including those loaded from the page.
--device D, --gpu-layers N (or gpu.device) The device every model loads on unless the page chooses another for it (default auto).
--offline No downloads; the search and the downloads fail; no web search.

Troubleshooting

Section titled “Troubleshooting”
  • The page shows “Ollama is running”: the request did not ask for HTML (a script or curl); open the address in a browser. Ollama clients use the same GET /.
  • “invalid or missing API key”: set the server’s key in API key → Set….
  • A bar says “Inga is not responding”: inga serve stopped (closed terminal, crash, a stopped service) or the address changed; start it again, and the page reconnects by itself (or press Retry now). See When the server stops above.
  • The answer says the web search failed: the server cannot reach DuckDuckGo (no network, or a proxy it does not use: Inga reads HTTPS_PROXY), or DuckDuckGo blocks this address (“refusing automated searches”, HTTP 202, on both its HTML and lite pages); wait a few minutes, or check another service in Search services.
  • “The model asked for the tool … in a format Inga does not read”: Inga reads the call formats of Hermes / Qwen, Qwen3.5, Llama 3.1+, Mistral, GLM, Granite, DeepSeek, gpt-oss and Gemma 4 (<|tool_call>call:..., since 0.28.0); report another model’s format on GitHub with the answer as shown.
  • Search or download fails with “cannot reach …”: the server has no network access to Hugging Face, or needs HTTPS_PROXY; gated models need HF_TOKEN in the server’s environment (see run-a-model-from-hugging-face.md).
  • “not enough disk space for …”: the download folder’s disk has no room for the files; press Another folder… (or Models → Model folders → Download folder) and choose a folder on a disk with more free space, or move the models there.
  • A downloaded model says NOT SUPPORTED: the reason follows it; see supported-models.md.
  • No Install button, or “no service worker” in the browser’s console: the page was opened over plain http:// from another machine; see On a phone, and as an installed app above.
  • A shared link says “No shared chat here”: it was revoked (from the page, the Storage tab or inga data), or the home (--home) differs between the server that made it and the one that answers.
  • The chats are gone: they live in the browser’s storage for that address; another browser, a private window or another host / port starts empty. Save them with Export (Every chat) and add them back with Import.
