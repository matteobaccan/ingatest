Embeddings, reranking and classification for RAG

What you get

Section titled “What you get”

The three building blocks of retrieval-augmented generation and of text pipelines, served locally by inga serve: embeddings (a vector per text, to index documents and find the ones close to a question), reranking (the documents found, sorted by how well they answer the question) and classification (a text, one label out of a list, with probabilities). Vector databases and frameworks that speak OpenAI’s embeddings API, or llama-server’s / Jina’s / Cohere’s rerank format, use them as they are.

Requirements

Section titled “Requirements”
  • Windows, Linux or macOS; any x86-64 or ARM64 CPU.
  • An embedding model (for example Qwen3-Embedding-0.6B in GGUF), a reranker (a GGUF converted by llama.cpp with a classification head, such as Qwen3-Reranker or bge-reranker-v2-gemma), or any chat model for classification. The same server can hold several (see serve-many-users-and-models.md).

1. Get Inga

Section titled “1. Get Inga”

Download the archive for your system from the Releases page and put inga on your PATH (details); inga --version checks it.

2. Get a model

Section titled “2. Get a model”

Or let the web UI pick one: inga serve with no embedding model on the machine, the Models tab’s Embedding model (documents and memory) panel, the bordered box under the library, proposes one (nomic-embed-text v1.5 for an English page, the multilingual BGE-M3 otherwise) and Download and use downloads and chooses it. The embedding models already on the machine are also in the library’s Embeddings box, each with Use for embeddings (the rerankers have a Rerankers box). The page of the server (Inga’s logo at the top of the left column) shows the one chosen in its settings, with Change, which leads to the panel. The chosen model answers the /v1/embeddings requests that name no model, next to the chat model of the same server (it loads when the first request comes; with --models-max 1 it takes the chat model’s place until the next chat).

Any model Inga runs gives embeddings: the hidden states of its last layer, averaged over the text (--pooling mean), the first token’s (--pooling cls, BERT’s) or the last token’s (--pooling last, what Qwen3-Embedding was trained for). By default Inga pools as the file says (<arch>.pooling_type), else by the mean. The vectors have the model’s hidden size (1024 for Qwen3-Embedding-0.6B) and length 1.

Static embedding models (Model2Vec: minishlab’s potion-base-8M, potion-retrieval-32M, potion-code-16M-v2 and potion-multilingual-128M, 30 to 510 MB) have no layers to run: a text’s vector is the mean of its tokens’ vectors, so a question is embedded in well under a millisecond on the CPU and a folder is indexed in seconds rather than minutes. Give the directory (or hf://minishlab/potion-base-8M) wherever an embedding model goes; the vectors are model2vec’s own (checked within 1e-7 of cosine), always by the mean (--pooling cls and last are refused). They find less than a transformer encoder: the measured difference per set is in experiments, “Retrieval”.

4. Check that it works

Section titled “4. Check that it works”

The answers below were captured with small test models with random weights: the fields are Inga’s, the numbers are not meaningful.

Embeddings (OpenAI’s format; input is a string or a list of strings):

The same vectors come from Ollama’s POST /api/embed (input → embeddings) and /api/embeddings (prompt → embedding), and from LM Studio’s POST /api/v0/embeddings.

Reranking (/v1/rerank, also /rerank, /v1/reranking):

results come most relevant first; index points into documents. A reranker file scores each pair with its classification head and its rerank prompt template, as llama-server’s rank pooling does; with any other chat model, the model is asked whether the document meets the query and the score is the probability of “yes”. instruction replaces the default question. Documents can be strings or {"text": ...}.

Classification (/v1/classify):

The model is asked which label fits (instruction replaces “Classify the text with one of the labels.”), each label’s tokens are scored after the question, and the probabilities are normalized over the labels; label is the most likely. (A real model picks positive here; the test model’s weights are random.)

A minimal RAG loop

Section titled “A minimal RAG loop”
  1. Split your documents into passages and get their embeddings once; store them with the passages (any vector database, or a file).
  2. For a question, get its embedding and take the 20–50 passages with the highest dot product (the vectors have length 1, so it is the cosine similarity).
  3. Rerank those with /v1/rerank and keep the best few (top_n).
  4. Send them with the question to /v1/chat/completions.

Options worth knowing

Section titled “Options worth knowing”
Option / field Effect
--pooling mean|cls|last How /v1/embeddings pools a text into one vector (as the file says, else mean).
--ctx N The longest text, in tokens, that can be embedded or scored.
--parallel N Several requests at once.
model With several models in one server, which one answers; left out of /v1/embeddings, the embedding model chosen in the web UI (/api/inga/settings), else the default model.
top_n, return_documents, instruction Rerank: how many results, with their text, and the question asked to a chat model.

Troubleshooting

Section titled “Troubleshooting”
  • 400 “the prompt has N tokens, which exceeds the maximum context length of M tokens of this session”: the text is longer than --ctx; split it, or raise --ctx.
  • Embeddings that do not separate topics well: use an embedding model rather than a chat model, with the pooling it was trained for (last for Qwen3-Embedding).
  • Reranking is slow: each document is one pass of the model over query + document; rerank tens of passages, not thousands, and use a small reranker.
