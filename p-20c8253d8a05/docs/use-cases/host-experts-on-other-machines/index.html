Host MoE experts on other machines

What you get

Section titled “What you get”

A mixture-of-experts model (Qwen3-30B-A3B, Mixtral, OLMoE, Qwen MoE) keeps most of its weights in its experts, and each token uses only a few of them. With --expert-nodes, the machine you type on (the coordinator) keeps the attention, the routers and a share of the experts of every layer; inga worker processes on other machines hold the other experts. For each MoE layer, every worker receives only the tokens routed to its experts and computes them while the coordinator computes its own, and the answer is the same as on one machine.

Compared with splitting the layers, the machines work at the same time on every layer, and the coordinator does not need the memory for the experts it does not run.

Requirements

Section titled “Requirements”
  • A mixture-of-experts model (see run-a-mixture-of-experts-model.md).
  • Two or more machines with Windows, Linux or macOS, on one network: the connections are encrypted, and with the same mesh.key on every machine (inga mesh key new prints one) only the machines that hold it connect.
  • The same Inga version on every machine, and a copy of the model on every machine, reachable by the same name (an hf:// reference or the same absolute path).

3. Run the model with remote experts

Section titled “3. Run the model with remote experts”

The experts of each layer are split in proportion to the memory each machine has available. Choose the split with --node-experts, one count per machine, the coordinator first; they must add up to the experts of a layer (128 here):

--expert-nodes works the same with inga serve, inga bench and inga info. --quantize converts each machine’s own experts, and --mem-limit still streams the coordinator’s experts from disk when they do not fit.

Troubleshooting

Section titled “Troubleshooting”
  • “–expert-nodes needs a mixture-of-experts model”: dense models have no experts; split their layers with --nodes instead.
  • “–nodes, –expert-nodes and –tp-nodes cannot be combined yet”: choose one.
  • “worker …: cannot connect”, “differs”, “protocol version”: see split-a-model-across-machines.md.

Good to know

Section titled “Good to know”
  • Every MoE layer sends one message per worker and per step: on a slow network, fewer workers with more experts each are faster.
  • Workers do not stream their experts from disk: each needs the memory for its share.
  • Machines with different CPUs can produce slightly different numbers than a single machine would.
