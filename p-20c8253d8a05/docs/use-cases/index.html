Use-case guides

One file per use case, written for someone who has never used Inga. A guide is added in the release that makes its use case work, with its row in the table below (the main README links this index). Every guide describes main; its “Supported since” line names the release that brought the use case and the later ones that extended it.

Rules

Section titled “Rules”
  • Start from zero. Assume a clean machine: no Rust, no Python, no model downloaded.
  • Copy-pasteable commands for Windows (PowerShell), Linux and macOS when they differ.
  • Show the expected output of each step, so the reader knows it worked.
  • One use case per guide. Link other guides instead of repeating them.
  • Say what Inga does. No release history (no “since 0.x”: that is CHANGELOG.md from 0.46.0 on, git and its tags before) and no list of what Inga lacks (that is the backlog); requirements and what would harm or confuse a user stay (python3 tools/docs-words.py check).
  • Keep it true. Every guide is re-run before each release (see ../RELEASING.md).
