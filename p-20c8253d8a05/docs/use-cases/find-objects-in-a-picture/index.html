Find objects in a picture

What you get

Section titled “What you get”

Say what you are looking for (“person, car”, “the red mug”) and get where it is in a picture: a box (or a point) for each object, in the picture’s pixels, with its label. Inga runs NVIDIA’s LocateAnything-3B on your machine: a Qwen2.5-3B language model that reads the picture through Kimi-VL’s MoonViT encoder and answers with coordinates. inga locate prints the boxes or draws them on a copy of the picture; inga serve answers POST /api/inga/locate with JSON, and the web UI draws the boxes over the picture in the chat.

Requirements

Section titled “Requirements”
  • Windows, Linux or macOS; any x86-64 or ARM64 CPU.
  • The model: locate-anything.cpp’s GGUF file (q8_0, 6.3 GB, is what its authors recommend; q4_k, 4.7 GB, is the smallest) or the Hugging Face directory nvidia/LocateAnything-3B. About its size plus 2 GB of free RAM.
  • The model’s licence is NVIDIA’s: read its model card before you use it.
  • A PNG or JPEG picture.

1. Get Inga

Section titled “1. Get Inga”

Download the archive for your OS from the Releases page, extract it, and put the inga executable on your PATH.

2. Get the model

Section titled “2. Get the model”

The file holds everything: the language model, the vision encoder and its projector, the vocabulary. No --mmproj file is needed. The Hugging Face directory works too (the weights in BF16, about 7.5 GB): --model hf://nvidia/LocateAnything-3B.

3. Find objects

Section titled “3. Find objects”

Each line is a label and a box: the top-left and bottom-right corners, in pixels of the picture. A point is one pair. “nothing found” when there is nothing.

  • --json prints what the API returns (§4), with the model’s raw answer.
  • -o boxes.png writes a copy of the picture with the boxes drawn, a colour per label.
  • --max-tokens N: how long the answer may be (256 by default; about 6 tokens a box, so raise it for a crowded picture).

What you write is turned into the request the model was trained on: Locate all the instances that matches the following description: person</c>car. (the categories separated by </c>). A query that already starts with “Locate” is sent as it is.

The picture keeps its proportions: its sides are stretched up to whole squares of 28 pixels and, past 25 600 patches of 14 pixels (a 2240 × 2240 picture), scaled down first. Every square is one position of the prompt, so a large photo takes a few thousand positions and, on a CPU, a while: the encoder is the slow part.

4. From the server

Section titled “4. From the server”

image is a data: URL or plain base64 (an http(s) URL with --allow-image-urls); model and max_tokens are optional. The normalized coordinates are the model’s own: thousandths of the width and the height.

In the browser, open http://localhost:8080, attach a picture, write what to find and send: the answer shows the picture with the boxes drawn over it. The chat API works too (an image_url part and your text): the answer then holds the model’s tokens, and the web UI draws them all the same.

5. Good to know

Section titled “5. Good to know”
  • One picture per request.
  • Greedy decoding only (locate-anything.cpp’s slow mode, the same boxes as the official model).
  • On a GPU, the language model’s layers run there, but a picture is refused while they do (as for every vision model): use --device cpu.
