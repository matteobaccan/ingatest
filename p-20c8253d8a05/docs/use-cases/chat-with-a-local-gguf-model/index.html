Chat with a model in the terminal

Supported since: 0.1.0

What you get

Section titled “What you get”

A terminal chat (or single-prompt completion) with a model you already have as a local GGUF file (Llama, Qwen, Gemma, DeepSeek, gpt-oss and the others of supported-models.md), running entirely on the CPU with no GPU, no Python and no other runtime dependency: just the inga executable and the model file.

Requirements

Section titled “Requirements”
  • Windows, Linux or macOS; the CPU is enough. A GPU (NVIDIA through CUDA, any vendor through Vulkan; only the driver needed) is used by default for as many layers as fit (run-on-an-nvidia-gpu.md).
  • Free RAM for the whole model file (it is memory-mapped, not copied, but every page touched during generation is paged in) plus a few hundred MB for the KV cache and activations. A few hundred MB of free disk for a small model.
  • A way to download a file (a browser, curl or wget), or let Inga download it (hf:// references, since 0.3.0; see run-a-model-from-hugging-face.md).

1. Get Inga

Section titled “1. Get Inga”

Download the archive for your OS from the Releases page, extract it, and put the inga executable on your PATH (or run it with its full path). Check it runs (it prints inga followed by its version number):

Optionally, turn on tab completion of the commands and options (since 0.14.0): inga completions bash > ~/.local/share/bash-completion/completions/inga for bash, inga completions zsh (add it to ~/.zshrc), inga completions fish > ~/.config/fish/completions/inga.fish, or inga completions powershell (add it to your PowerShell $PROFILE).

2. Get a model

Section titled “2. Get a model”

Download a GGUF file for a model Inga supports (its general.architecture is one of those in supported-models.md: llama, qwen2, qwen3, gemma3, deepseek2, gpt-oss, …; the mixture-of-experts ones are in run-a-mixture-of-experts-model.md). A small, fast model to start with is SmolLM2-135M-Instruct; bartowski/SmolLM2-135M-Instruct-GGUF has ready-made GGUF conversions of it. Download the Q8_0 file with curl:

Any quantization works: since 0.12.0 Inga reads every weight type llama.cpp’s quantization mixes produce (Q2_K … Q8_0, the i-quants, MXFP4; the list is in supported-models.md). For a model this small, Q8_0 keeps the answers closest to the original. inga info (next step) tells you if any tensor is a problem.

Since 0.3.0 Inga can also download the file itself: every command below accepts hf://bartowski/SmolLM2-135M-Instruct-GGUF:Q8_0 in place of the file name, and keeps the download in the Hugging Face cache (see run-a-model-from-hugging-face.md). A model Ollama already downloaded runs as ollama://name:tag (since 0.20.0; see replace-ollama-or-lm-studio.md).

3. Check that Inga supports the file

Section titled “3. Check that Inga supports the file”

memory, plan and estimate (since 0.4.0) say how much memory the model needs, what Inga does when it does not fit (see run-a-dense-model-larger-than-ram.md) and the speed to expect; available is your machine’s free memory. inga info --json prints the same as JSON. If status is NOT SUPPORTED, the lines below it name exactly why (an unsupported architecture, tensor type, or a tokenizer Inga does not implement yet); try a different file rather than run, which would fail the same way.

To check every model on a disk at once (since 0.19.0), inga scan walks a directory tree and lists each GGUF file and Hugging Face model directory with the same verdict:

--supported keeps only the models Inga runs, --depth N limits how deep it goes (default 8), --all also enters hidden directories, and --json prints one JSON document. Only metadata is read, so a scan of large files is quick. LM Studio and GPT4All look only into their own models folder; Ollama lists only its own store.

4. Start chatting

Section titled “4. Start chatting”

With no -p, run starts an interactive chat: type a line, press enter, read the answer, repeat; /exit or closing stdin (Ctrl-D on Linux/macOS, Ctrl-Z Enter on Windows) ends it.

(Captured on a laptop CPU with 0.1.0’s single-threaded scalar backend; your tok/s will differ with your hardware, and since 0.2.0 Inga uses every core and SIMD kernels, which is several times faster. Since 0.19.0 a spinner shows while the model loads and the prompt is processed.)

Besides /exit, the chat understands commands; /help lists them (since 0.26.3):

  • /clear starts over (the system prompt and the settings stay), /undo removes the last exchange, /retry asks the last message again.
  • /system TEXT sets the system prompt (/system shows it, /system off removes it).
  • /set NAME VALUE changes temperature, top-p, top-k, min-p, repeat-penalty, presence-penalty, frequency-penalty, seed, max-tokens or ctx-shift on|off for the next answers, checked as the command-line options; /set alone lists them, /set NAME default restores the model’s recommendation or Inga’s default.
  • /show tells the model, where it runs, the settings and where each comes from, the context used; /stats the last answer’s speeds and the chat’s totals.
  • /save FILE and /load FILE (the conversation as JSON, since 0.15.0; see keep-long-conversations.md); /image FILE and /audio FILE (an image or a recording for the next message, with a model that reads them; see chat-about-an-image.md), /video FILE (since 0.23.0), and /files to see or /files clear to drop them; /think on|off (a thinking model’s reasoning, since 0.20.0; see use-thinking-models.md); /web on|off with --web-search.

A unique prefix is enough (/sa is /save); an unknown command is never sent to the model, and //text sends /text. A line made of """ starts a multi-line message ended by another """, a line ending with \ goes on to the next, and pasted text stays one message. Ctrl-C stops an answer and keeps the chat (twice at the prompt ends it). The README’s chat commands table lists everything (spec).

The bracketed line after each answer (on stderr, so it does not mix into the chat transcript) reports token counts and speed; a later turn’s cached count shows Inga reusing the previous turns from its KV cache instead of reprocessing them. A turn that fails (e.g. the prompt no longer fits, see Troubleshooting) prints error: ... on stderr and leaves the chat running, ready for the next line.

For a single answer instead of a chat, pass the prompt with -p; --temp 0 makes decoding deterministic (greedy: always the highest-probability token) instead of the default random sampling:

The speeds in the report lines of this guide were measured with 0.1.0’s single-threaded backend; 0.2.0 is several times faster (see performance.md, and measure your own machine with measure-speed.md).

Options worth knowing

Section titled “Options worth knowing”
Flag Effect
-p, --prompt TEXT Answer this one prompt instead of starting an interactive chat.
--system TEXT System message prepended to the conversation.
--chat-template T, --chat-template-file PATH Use another chat template than the model’s: chatml, llama3, or Jinja text (since 0.13.0).
--think on|off, --reasoning-effort low|medium|high A thinking model’s reasoning on or off, or gpt-oss’s effort (since 0.20.0; see use-thinking-models.md).
--raw Skip the chat template, continue the prompt as plain text (needs -p; for a model with no chat template, or for base-model-style completion).
-n, --max-tokens N Maximum tokens per answer (default 1024).
--ctx N Requested context size in tokens (default 4096), capped at the model’s trained context; run prints a note: line when the effective context differs from what you asked for.
--cache-type q8_0 Store the KV cache as 8-bit blocks instead of f16: about half the memory for long contexts, at a small cost in precision (default f16).
--prompt-cache FILE Resume the conversation saved in FILE (its tokens and KV cache, for the same model and --cache-type) instead of processing it again, and save it there after each answer.
--history FILE Start from a conversation saved with /save FILE (since 0.15.0); in the chat, /save FILE writes the conversation so far as JSON ([{"role", "content"}], OpenAI’s shape) and /load FILE replaces it with a saved one. Images are saved as [image].
--web-search, --search-backends LIST Let the model search the web (since 0.22.1): it is offered a web_search tool that Inga runs (DuckDuckGo, or the services of LIST tried in order: duckduckgo, wikipedia, searxng=URL, brave, tavily), up to three searches per answer; each search is announced on stderr ([searching the web: ...]) and the sources ([n] title - url) are printed under the answer. Needs a model whose template can call tools (Qwen3, Llama 3.1+, Mistral, gpt-oss, …); not with --offline or --raw.
--lora FILE, --lora-scaled FILE X Apply a LoRA adapter in llama.cpp’s GGUF format (convert_lora_to_gguf.py makes one from a PEFT adapter), at scale 1 or X; repeatable, the adapters add up. The base model’s weights are left as they are. Not on the embeddings or the routed experts of MoE models, and not with --nodes.
--cache-cap N A context of N tokens that never fills: when an answer reaches it, the older half of the conversation (after its first 4 tokens) is forgotten and the answer goes on; implies --ctx N --context-shift. Not for Qwen3.5 / Qwen3-Next.
--context-shift When the chat no longer fits the context, drop its oldest turns (after the system message) instead of refusing the new one.
--draft MODEL, --lookup N, --draft-n N Speculative decoding: a small model with the same vocabulary (--draft), or what followed the last N tokens earlier in the conversation (--lookup), guesses up to --draft-n tokens (default 8) that the model checks in one pass. The text is the same as without; it is faster when the guesses are often right (a draft model of the same family, answers that repeat the prompt), slower otherwise. The stats line shows how many guesses were accepted.
--json-schema JSON, --grammar-file PATH Force the answer into JSON following a schema, or into a GBNF grammar (see get-structured-output.md).
--stop TEXT End the answer before TEXT; repeat it for several stop texts.
--temp X Sampling temperature; 0 is greedy (deterministic) decoding (default: the model’s recommendation, else 0.8).
--no-model-sampling Ignore the sampling the model recommends (since 0.21.0). A GGUF file may carry it (general.sampling.temp, top_k, top_p, min_p, penalty_repeat, …, written by llama.cpp’s converter from the model’s generation_config.json), and so may a Hugging Face directory; inga info shows it on its sampling: line, and inga run uses it for every setting not given on the command line, with a note (note: sampling as the model recommends: temperature 0.6, top-p 0.95).
--top-k, --top-p, --min-p, --repeat-penalty, --seed Sampler tuning; see inga --help.
--presence-penalty X, --frequency-penalty X OpenAI’s penalties over the last 64 tokens (since 0.19.0).
--dry-multiplier X DRY: penalize tokens that would continue a sequence already repeated in the conversation (0.8 is a common value; --dry-base, --dry-allowed-length, --dry-penalty-last-n, --dry-sequence-breaker tune it as in llama.cpp).
--xtc-probability X, --xtc-threshold X XTC: now and then, exclude the most likely tokens but the least likely of them, for more varied text.
--mirostat 1|2 Mirostat instead of top-k / top-p / min-p: keeps the text’s surprise near --mirostat-tau (5.0), adapting at --mirostat-eta (0.1).
inga tokenize MODEL -p TEXT Not an option but a command: the model’s tokens for a text, one per line (--ids for a list, --json), to count tokens or check a prompt.
--typical X, --top-n-sigma X Locally typical sampling (keep the tokens whose surprise is closest to the entropy, up to X of the probability) and top-n-sigma (keep the tokens within X standard deviations of the best logit), as llama.cpp’s options.
--logit-bias T+X Adds X to the logit of token id T (T-X subtracts, T-inf bans it), as llama.cpp’s option; repeatable.
--watermark Marks the answers (TGI’s scheme): after each token, a green quarter of the vocabulary (--watermark-gamma) gets --watermark-delta (2.0) added to its logits; inga watermark MODEL -f FILE tells whether a text was marked (a z-score above 4).
--batch N Process the prompt by passes of at most N tokens (default 2048), bounding the activation memory of long prompts.
-t N, --threads N CPU threads of prompts and generation (default: every logical CPU for prompts, one per physical performance core for generation).
--threads-decode N CPU threads of generation only (at most -t).

Troubleshooting

Section titled “Troubleshooting”
  • model not found: NAME (looked in DIR): the path is wrong for the folder you are in. Since 0.30.0, when a file of that name is in the Hugging Face cache, the message gives its hf:// reference and its path: use either. Otherwise inga list shows the models on this machine.
  • status: NOT SUPPORTED in inga info: the lines under it say why (e.g. an unsupported tensor type, or an architecture Inga does not run). Download a different quantization or model.
  • this model has no chat template; use --raw: the GGUF file has no tokenizer.chat_template metadata; pass --raw with -p to complete plain text instead of chatting.
  • the prompt has N tokens, which exceeds the maximum context length of M tokens of this session; use a larger --ctx: raise --ctx (it is still capped at the model’s trained context, shown by inga info). In an interactive chat this ends only the current turn: the message is on stderr, and you can keep typing (though every further turn will fail the same way until you restart with a larger --ctx, since the conversation itself no longer fits).
  • the prompt has N tokens, which exceeds the model's maximum context length of M tokens: the conversation (or a single long prompt) is longer than the model’s own trained context (shown by inga info as context:); no --ctx is large enough to fit it, so shorten the prompt or start a new chat.
  • the context is now full; restart the chat to continue, or run again with a larger --ctx: an answer stopped early because it filled the remaining context exactly (the report line ends in context full instead of end of text or token limit); the next turn will likely hit the error above, so restart the chat (or rerun with a larger --ctx) rather than continuing.
  • It is slow: Inga uses every logical CPU and the fastest instruction set it finds (the report line after each answer shows the speed); measure your machine with inga bench (see measure-speed.md). Speed scales with the model’s size and your memory bandwidth; on a laptop, decode speed of a 1B Q4_K_M model is typically 5–20 tok/s. Generation runs on the physical cores by default (inga devices shows them); try --threads-decode with other counts to compare.
  • Piping into another command (e.g. inga run model.gguf -p ... | head -c 40): once the reader closes the pipe, run stops generating at once and exits with code 0 instead of failing or panicking; nothing further is printed.
