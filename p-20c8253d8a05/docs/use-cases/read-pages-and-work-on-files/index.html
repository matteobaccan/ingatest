Let a model read web pages and work on a folder's files

What you get

Section titled “What you get”

Two kinds of server tools for the local models that call tools:

  • fetch_url: the model reads a web page — one you name (“summarize https://…”) or a search result — as text, and cites it as a source. It comes with web search: wherever web_search is offered (the web UI’s Web button, the APIs’ web_search, inga run --web-search), fetch_url is too. Only public addresses are read: localhost, your LAN, link-local and cloud metadata addresses are refused, also when a name resolves to one or a page redirects to one.
  • A workspace: one folder on the server whose files the model may list, read, search and write (list_files, read_file, search_files, write_file). Nothing outside the folder is read or written (.., absolute paths and symbolic links that lead out are refused), and every write waits for your approval. Inga runs no program for these tools: there is no shell.

Requirements

Section titled “Requirements”
  • Windows, Linux or macOS; any x86-64 or ARM64 CPU.
  • A chat model whose chat template has tools (the Models tab’s model card says tools): Qwen3, Llama 3.1+, Mistral, gpt-oss…
  • For fetch_url, network access (not with --offline).

3. Start the server with a workspace

Section titled “3. Start the server with a workspace”

PowerShell: --workspace $HOME\projects\notes. The folder must exist; a filesystem root (/, C:\) is refused. Without --workspace, choose the folder later in the web UI’s Server tab (Workspace row: type the folder’s path, Save; empty and Save clears it); the choice is kept in ~/.cache/inga/settings.json.

4. Check that it works

Section titled “4. Check that it works”

In the browser

Section titled “In the browser”

Open http://127.0.0.1:8080/:

  1. Click Web under the message box and ask “Summarize https://www.rust-lang.org/ in three lines.” The answer cites the page as [1]; Sources lists it, and the tool’s line under the answer shows fetch_url with the start of the text it read.
  2. Click Files (shown when the server has a workspace) and ask “Which files are in my workspace? Read the README and write a short summary to summary.md.” The model lists and reads the files; before it writes, a dialog asks Write the file summary.md? with the start of the content, the size, and whether it replaces a file. Write writes it, Don’t write tells the model it was refused.

Through the API

Section titled “Through the API”

The tools are server tools: the request asks for them, the server runs them.

  • "inga_workspace": true offers list_files, read_file and search_files; write_file too when the request streams ("stream": true), because each write needs a person: the stream carries an inga_approval delta (kind: "workspace_write", the path, the size, a preview, its id), answered with POST /api/inga/approvals/{id} {"allow": true} (or false). Without an answer in 5 minutes the write is refused. {"allow": true, "always": true} (Always allow writes in this folder in the web UI) lets every later write in that workspace folder run without asking, kept in ~/.cache/inga/tool-approvals.json until inga mcp revoke --workspace DIR (or POST /api/inga/tool-approvals/revoke {"kind": "workspace_write", "folder": "DIR"}) takes it back.
  • "inga_tool_approval" sets the chat’s approval level: "ask" and "changes" ask for each write (the readers never ask); "auto" writes only in a folder allowed “always”, and refuses otherwise without asking (use-mcp-tools.md, “Approval levels and the “always” kept”).
  • "web_search": true offers web_search and fetch_url; a client that defines its own fetch_url (or file tools of the same names) runs them itself.
  • No workspace set: "inga_workspace": true is a 400 that says how to set one.

The server’s terminal logs every page read (inga: fetch_url: URL -> N characters) and every write (inga: workspace: wrote notes/summary.md (812 bytes, new)).

Options worth knowing

Section titled “Options worth knowing”
Option Effect
--workspace DIR The folder of the file tools (the web UI’s Server tab may choose another)
--no-web-search No web_search, so no fetch_url either
--offline No network: neither tool reaches the web
inga run --web-search web_search and fetch_url in the terminal chat

Limits: a page of at most 2 MiB, read in 15 s, after at most 5 redirects, given to the model as at most 8,000 characters; HTML, text, JSON and XML only. read_file gives at most 400 lines or 20,000 characters per call (the model reads on with start_line), files up to 4 MiB; search_files gives at most 100 matching lines and skips files over 1 MiB, binary files, .git, node_modules and target; write_file writes text of at most 1 MiB, making its folders.

Troubleshooting

Section titled “Troubleshooting”
  • “… is not a public address … Inga does not fetch such addresses”: the page is on your machine or your LAN (or redirects there). fetch_url only reads the public web, so a model cannot be talked into reading your router’s or your cloud’s internal pages; put the text in the chat, or in the workspace, instead.
  • “… is not a text page (application/pdf)”: PDFs and other files are not read from the web; download the file and attach it to the chat (documents are read there).
  • The Files button is not shown: the server has no workspace; set one with --workspace or in the Server tab.
  • “../x is refused: .. is not allowed” or “it leads out of the workspace”: the model tried a path outside the folder; the tool says so to the model, which goes on without it.
  • “notes.md was not written: writes need a person to approve them”: the request did not stream (or is a scheduled task); writes are only offered to streamed requests.
