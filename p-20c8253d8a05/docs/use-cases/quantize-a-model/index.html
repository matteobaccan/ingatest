Quantize a model into a GGUF file

What you get

Section titled “What you get”

A smaller copy of a model, written as a GGUF file that Inga, llama.cpp, LM Studio, Ollama and the other GGUF tools load. inga quantize writes the file llama.cpp’s llama-quantize writes, byte for byte: the same mixes (Q4_K_M keeps half of the attn_v and ffn_down matrices and the output projection in Q6_K), the same fallbacks, the same metadata. It also turns a Hugging Face model in its original format (config.json + safetensors) into a GGUF file, as llama.cpp’s converter would store it.

--quantize (on run, serve, …) does the same conversion in memory each time a model loads; inga quantize does it once and keeps the file. inga optimize writes the same file as a variant of the model, kept beside it in Inga’s cache and picked with --variant: see optimize-a-model.md.

Requirements

Section titled “Requirements”
  • Windows, Linux or macOS; any x86-64 or ARM64 CPU.
  • A model in F32, F16 or BF16: a GGUF file, a Hugging Face model directory, or an hf:// reference (see run-a-safetensors-model.md for the architectures Inga reads from safetensors).
  • Disk space for the output (about a quarter of the F16 size for Q4_K_M) and memory for the slices being converted (a few hundred MB; the model itself is memory-mapped).

3b. Smaller: the i-quants, with an importance matrix

Section titled “3b. Smaller: the i-quants, with an importance matrix”

The i-quants (IQ2_XXS … IQ4_XS) keep more of the model in 2 to 4 bits by weighing each column’s error by how much the model uses it: an importance matrix, collected over a calibration text. Any text in the model’s languages works (a few thousand words; more is better):

inga imatrix collects the matrix as llama.cpp’s llama-imatrix does (chunks of -c tokens, default 512, each starting with the BOS token; --chunks N for the first N) and writes it in its GGUF format, so llama-quantize --imatrix reads Inga’s files and inga quantize --imatrix reads llama.cpp’s. It also keeps it for the model in ~/.cache/inga/experts/ (listed by inga data), where --quantize and inga optimize find it. With --imatrix, inga quantize writes the file llama-quantize --imatrix writes, byte for byte, including the quantize.imatrix.* keys that name the matrix (quantize.imatrix.file is the path as you typed it). The k-quants take the matrix too, a little more precise than without.

3c. The output layer in a type of its own

Section titled “3c. The output layer in a type of its own”

--token-embedding-type T and --output-tensor-type T (llama-quantize’s options) give token_embd.weight and output.weight a type of their own, whatever the mix says. A model without output.weight (Llama 3.2 1B) reads its output layer from token_embd.weight, at every token: in a Q4_K_M file that matrix is Q6_K, and on a small model it is the largest one read. A smaller type for it makes each token cheaper:

The second line starts from a Q4_K_M file you already have: only that matrix is quantized again, every other tensor is copied byte for byte. The types are those of --quantize (q8_0, q2_k … q6_k, the i-quants iq2_xxs … iq4_xs, q1_0, q2_0) and q4_0, q5_0, f16.

4. Check that it works

Section titled “4. Check that it works”

The same file runs in llama.cpp (llama-cli -m ...), LM Studio (copy it into its models folder) and Ollama (FROM ./Llama-3.2-1B-Instruct-Q4_K_M.gguf in a Modelfile).

Types

Section titled “Types”

--type takes the names of llama-quantize:

Type What it is
q4_k_m (q4_k) Q4_K, with the output, half the attn_v and half the ffn_down matrices in Q6_K: the usual choice
q4_k_s Q4_K, a few early layers in Q5_K
q5_k_m (q5_k), q5_k_s Q5_K, as above with Q6_K
q6_k Q6_K, close to the original
q3_k_m (q3_k), q3_k_s, q3_k_l Q3_K mixes, smaller and less accurate
q2_k Q2_K with Q3_K / Q4_K where it matters most
q2_k_s Q2_K almost everywhere (needs --imatrix)
iq4_xs, iq4_nl 4.25 / 4.5 bits, non-linear: close to Q4_K_M, smaller
iq3_m, iq3_s, iq3_xs IQ3_S mixes, about 3.4 to 3.7 bits
iq3_xxs 3.06 bits (needs --imatrix)
iq2_m, iq2_s IQ2_S / IQ2_XS with IQ3_S where it matters most, 2.5 to 2.7 bits (need --imatrix)
iq2_xs, iq2_xxs 2.31 / 2.06 bits (need --imatrix)
q8_0 8 bits, nearly lossless
q4_0, q4_1, q5_0, q5_1 the older 32-value formats
q1_0, q2_0 1 and 2 bits (rows of 128 / 64 values)
f16, bf16, f32 no quantization: a safetensors model as one GGUF file

Vectors (norms, biases), the MoE router and the token embeddings of most types are kept as llama.cpp keeps them. A matrix whose rows are not whole blocks of its type gets the type llama.cpp falls back to (Q4_K to Q5_0, Q6_K to Q8_0, the 256-value i-quants to IQ4_NL, …). IQ1_S and IQ1_M are not written.

Options worth knowing

Section titled “Options worth knowing”
Option Effect (default)
--type T The file type (required).
--imatrix FILE The importance matrix (inga imatrix, or llama-imatrix’s GGUF file) each column’s error is weighed by; required for iq2_*, iq3_xxs and q2_k_s.
--pure Every matrix in the main type, no mix.
--leave-output-tensor Copy output.weight as it is.
--token-embedding-type T token_embd.weight in type T; the output layer of a model without output.weight.
--output-tensor-type T output.weight in type T.
--allow-requantize Quantize a model that is already quantized (loses quality: start from F16 when you can).
-t N Threads (all logical CPUs).
--offline Never download an hf:// model.

Troubleshooting

Section titled “Troubleshooting”

  • “needs an importance matrix”: the type (or a type its mix gives some matrices) needs one, as in llama.cpp: make it with inga imatrix MODEL -f TEXT and give it with --imatrix FILE.

  • “the importance matrix has N values for tensor …”: the matrix was made for another model (or another size of it).

  • “is already quantized”: the input is a quantized file. Start from the F16 / BF16 model, or add --allow-requantize.

  • “llama.cpp defines no fallback type for Q1_0”: the model’s rows are not whole 128-value blocks, and llama.cpp has no other type to put them in: choose another --type.

  • llama.cpp does not load a file made from safetensors: Inga writes the metadata it reads from config.json and tokenizer.json; a key llama.cpp’s converter adds for a particular model (a pre-tokenizer name, for example) may be missing. Report it with the repository’s name.
