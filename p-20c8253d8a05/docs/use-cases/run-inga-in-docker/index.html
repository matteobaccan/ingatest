Run Inga in Docker or Podman

What you get

Section titled “What you get”

Inga in a container, for servers and clusters that run everything that way: the image holds only the inga executable on a minimal Linux base (no shell, no package manager, running as a non-root user), for x86-64 and ARM64. Models come from a mounted folder or from Hugging Face into a volume that keeps them across restarts.

Requirements

Section titled “Requirements”
  • Docker (or Podman) on Linux, or Docker Desktop on Windows or macOS.
  • A model Inga runs (see chat-with-a-local-gguf-model.md), or network access to Hugging Face.

1. Get the image

Section titled “1. Get the image”

The image is on GitHub’s container registry, ghcr.io/matteobaccan/inga, for x86-64 and ARM64 (Docker and Podman pick the right one). While the repository is private, the registry asks who you are: log in once with your GitHub user and a personal access token that has the read:packages scope (GitHub → Settings → Developer settings → Personal access tokens):

Every release is also tagged with its version (ghcr.io/matteobaccan/inga:0.13.0). To build the image from the source instead: docker build -t inga . in a clone of the repository.

3. With Podman

Section titled “3. With Podman”

Podman reads the same registry and the same image (it is a standard OCI image), with the same commands; three differences:

  • Log in and pull with the full name, ghcr.io/... (Podman does not assume a registry):

  • On systems with SELinux (Fedora, RHEL, CentOS), add :Z to the folders you mount, or the container cannot read them:

  • Rootless Podman (the default) maps ports above 1024 as Docker does; -p 8080:8080 works unchanged. Named volumes (-v inga-models:/data) work the same way.

4. A GPU in the container

Section titled “4. A GPU in the container”

The image holds only inga; the GPU’s driver comes from the host:

  • NVIDIA through CUDA: install the NVIDIA Container Toolkit on the host, then add --gpus all (Docker) or --device nvidia.com/gpu=all (Podman, through CDI). The toolkit mounts the driver’s libcuda into the container, where Inga finds it at run time.
  • Vulkan needs the Vulkan loader (libvulkan.so.1), which the minimal image does not have: use the release archive outside the container, or build an image on a base that has it.

inga devices inside the container says what it sees. This part is unverified on a GPU host.

5. Check it works

Section titled “5. Check it works”

The APIs are those of serve-openai-and-anthropic-apis.md: OpenAI, Anthropic, Ollama, KoboldAI (and LM Studio’s); the chat page is at http://127.0.0.1:8080/ (see chat-in-the-browser.md). Models downloaded from the page’s Models tab go into the same /data volume.

Troubleshooting

Section titled “Troubleshooting”
  • connection refused from the host: the server listens on 127.0.0.1 inside the container; start it with --host 0.0.0.0.
  • The model is downloaded again on every start: mount a volume on /data (or set HF_HOME to a mounted folder).
  • Slower than outside Docker: give the container every core (--cpus) and enough memory (--memory); Inga sizes its thread pool from the CPUs it can use.
