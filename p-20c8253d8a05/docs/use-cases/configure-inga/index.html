Find every option and keep your settings in one file

What you get

Section titled “What you get”

The whole help of any command on the terminal (what it does, what Inga decides by itself, every option with its default and its key in the configuration file, examples), and your settings written once in inga.toml instead of repeated on every command line: the context size, the threads, the GPU, the server’s port and keys, the APIs.

Requirements

Section titled “Requirements”
  • Windows, Linux or macOS; any x86-64 or ARM64 CPU.
  • No model and no network: this guide only reads and writes Inga’s settings.

1. Get Inga

Section titled “1. Get Inga”

Download the archive for your system from the Releases page and put inga on your PATH (details); inga --version checks it.

2. Find the option you need

Section titled “2. Find the option you need”

inga --help lists the commands, one line each, grouped (run a model, measure, make models, images, video and speech, find and keep models, several machines, this program), then the global options:

inga help COMMAND (also inga COMMAND --help) prints one command in full, and inga help COMMAND ACTION one action of it (inga help config init, inga help mesh key). Each option says its default and its key in inga.toml:

A mistyped name gets the closest one:

inga help models explains the ways to name a model, inga help environment the environment variables Inga reads (the proxy, the Hugging Face token).

3. Write the configuration file

Section titled “3. Write the configuration file”

inga config init writes the file with every key commented out, its default and what it does:

The file is ~/.cache/inga/inga.toml (on Windows %USERPROFILE%\.cache\inga\inga.toml), else the machine’s /etc/inga/inga.toml (%ProgramData%\Inga\inga.toml on Windows); inga config path prints the one in use. Open it in any editor:

Remove the # before a key to set it. For example, a context of 8192 tokens and four CPU threads:

Every key is in docs/config.md, with its flag, default and meaning. A secret (an API key) is never written in clear: { env = "VAR" } reads a variable you name, { file = "PATH" } a file.

4. Check that it works

Section titled “4. Check that it works”

inga config check reads the file and reports each problem with its line; it exits with 1 when there is one:

A misspelt key is caught, with the closest real one:

inga config show prints each value and where it comes from (the file and its line, a flag, or the default); give it a section or a key to see only those, --json for a script, and inga config get KEY for one value alone:

5. Change a setting for one run

Section titled “5. Change a setting for one run”

A flag on the command line wins over the file, which wins over the default. Any key can be given for one run with the global option --set KEY=VALUE (repeatable, before or after the command), even the keys that have no flag of their own:

Two other global options move the files: --config FILE reads another configuration file (one per project or per machine), --home DIR moves Inga’s own folder (model variants, caches, keys, settings) and the file looked for there.

Options worth knowing

Section titled “Options worth knowing”
Command or option What it does
inga help [COMMAND] [ACTION] The overview, or a command’s or action’s whole help
inga config init [FILE] [--force] Writes the file with every key commented out
inga config show [KEY|SECTION] [--json] Each value and where it comes from
inga config get KEY One value alone, for scripts
inga config path The file in use, or where it would be
inga config check Reports every problem with its line; exits 1 on one
--set KEY=VALUE Any key for this run (repeatable; not for eval)
--config FILE Another configuration file
--home DIR Another folder for Inga’s own files

Troubleshooting

Section titled “Troubleshooting”
  • error: ... inga.toml exists: --force replaces it: inga config init never overwrites a file; --force replaces it, or give another path (inga config init ./inga.toml) and use it with --config ./inga.toml.
  • A setting seems ignored: inga config show KEY says where its value comes from; a flag or --set on the command line wins over the file.
  • not valid TOML: duplicate key: a section ([api.azure], for example) is written twice; the template has every section already, so uncomment the key under it instead of adding the section again.
  • An old INGA_* variable does nothing: every setting is a key of inga.toml; inga help environment lists the other programs’ variables Inga reads (HF_TOKEN, the proxy).
