Use Inga from LM Studio

What you get

Section titled “What you get”

You keep LM Studio’s chat window, its chats and its tools, and inga serve writes the answers: Inga’s engine, on the GPU or CPU Inga chooses (CUDA, Vulkan, HIP, Metal, a mesh of machines), with the models LM Studio already downloaded, read in place. The link is LM Studio’s own plugin lmstudio/openai-compat-endpoint (“OpenAI, Claude, or any other OpenAI compat endpoint”), pointed at Inga instead of a cloud service. Nothing is added to Inga or to LM Studio but that plugin.

In short: 5 steps, about 10 minutes to the first answer with a model LM Studio already has (an estimate: the downloads of Inga and of the plugin, the model’s load; not timed).

What was checked, and how: the plugin’s code (its src/config.ts and src/generator.ts, as LM Studio’s Hub showed them on 2026-11-18, last updated 2025-09-19) and LM Studio’s plugin documentation (plugins, generators, custom configurations, read on 2026-11-18) against what inga serve answers. The plugin sends a streamed POST /v1/chat/completions with the chat and LM Studio’s tools, and reads the answer’s text and tool calls: the same OpenAI chat completions, streamed and with tools, that Inga’s server tests send. LM Studio itself was not run for this guide: the plugin’s names (its settings, Run in LM Studio) come from its code and its Hub page, and where LM Studio’s own windows show them is described rather than quoted; the check on a real LM Studio is in the real-world checks (group B).

Requirements

Section titled “Requirements”
  • Windows, Linux or macOS; any x86-64 or ARM64 CPU, a GPU helps a lot (see run-on-an-nvidia-gpu.md, run-on-an-amd-or-intel-gpu.md, run-on-a-mac.md).
  • LM Studio, a version with plugins and the LM Studio Hub (its download page).
  • A model: one LM Studio downloaded (GGUF files, and MLX folders) or any model Inga runs. For LM Studio’s tools, a model trained for tool calls (Qwen3 / Qwen3.5, Qwen3-Coder, gpt-oss, Llama 3.1+, Mistral Small 3+; inga info MODEL shows whether its chat template has tools).

1. Get Inga

Section titled “1. Get Inga”

Download the archive for your system from the Releases page and put inga on your PATH (details); inga --version checks it.

2. Pick a model and start the server

Section titled “2. Pick a model and start the server”

List the models LM Studio already has, with whether Inga runs each one (only the metadata is read, nothing is copied):

Inga finds LM Studio’s folder by itself: the downloads folder chosen in LM Studio’s settings, else ~/.lmstudio/models (more in replace-ollama-or-lm-studio.md). Then serve one of them:

  • The server listens on http://127.0.0.1:8080: the plugin’s address is http://127.0.0.1:8080/v1. The start lines say where the model runs (GPU or CPU, how many layers).
  • One model: the plugin asks for a model by a name from its own list (step 4), and with one model Inga answers whatever name it is sent. With several models (inga serve a.gguf b.gguf) a request must name one that GET /v1/models lists, which the plugin’s list does not; serve one model for LM Studio.
  • --ctx 16384: room for LM Studio’s tools and a longer chat (4096 by default).
  • --api-key change-me: requests must carry this key; use your own random text. Leave it out only when nothing but your own user can reach the port.

No model on the machine yet? inga setup proposes one that fits it and downloads it (run-a-model-from-hugging-face.md).

3. Install the plugin in LM Studio

Section titled “3. Install the plugin in LM Studio”

Open the plugin’s page on the LM Studio Hub, lmstudio.ai/lmstudio/openai-compat-endpoint, and click Run in LM Studio: the link opens LM Studio, which installs the plugin (it brings its own dependencies; nothing else to install). From a terminal, LM Studio’s lms command does the same:

4. Point the plugin at Inga

Section titled “4. Point the plugin at Inga”

The plugin is a model source: in LM Studio it shows up in the model selector, beside the local models, rather than in the list of plugins. Choose it there, then fill in its settings (LM Studio draws them as a form; the address and the keys are global, the model is per chat):

Setting Value
(Optional) Override Base URL http://127.0.0.1:8080/v1
Anthropic API Key change-me, the --api-key given to inga serve
OpenAI API Key the same key
Model leave the default: with one model, Inga answers any name

The plugin sends the Anthropic API Key when the chosen Model’s name starts with claude- (the default) and the OpenAI API Key when it starts with gpt-: with the same key in both, either works. Without --api-key, leave both empty.

5. Chat

Section titled “5. Chat”

Write in LM Studio’s chat as usual. The answer streams in as Inga writes it. With a tool of LM Studio’s turned on (an MCP server, a plugin’s tools), the plugin passes the tools to Inga, Inga’s model asks for one, LM Studio runs it and sends the result back, and the model answers with it: the same round trip as with a local model.

6. Check that it works

Section titled “6. Check that it works”

  • Before LM Studio, Inga alone:

  • Then open Inga’s web UI at http://127.0.0.1:8080/, Developer → Logs with Only requests: each message sent from LM Studio is a row POST /v1/chat/completions, with its status, time, tokens and whether it streamed; a wrong key is a line “API key refused (401)”. Developer → Server shows the requests per minute and the tokens per second as they come (monitor-a-server.md).

LM Studio’s own clients, straight to Inga

Section titled “LM Studio’s own clients, straight to Inga”

Apps and scripts written for LM Studio’s local server (its REST API /api/v0, or its OpenAI-compatible /v1 on port 1234) do not need LM Studio or the plugin at all: Inga answers LM Studio’s REST API itself (its OpenAPI file). Stop LM Studio’s server, then start Inga on its port:

--like lmstudio adds a listener on 1234 beside Inga’s 8080 ([api] like = ["lmstudio"] in inga.toml keeps it). The details, and Ollama’s clients the same way, are in replace-ollama-or-lm-studio.md.

Options worth knowing

Section titled “Options worth knowing”
Option Effect
--api-key KEY Require a key (the plugin’s two key fields).
--ctx N Context size; LM Studio’s tools and long chats need more than the default 4096.
--host 0.0.0.0 Listen on the network, for LM Studio on another machine (then the key is a must); the plugin’s address becomes http://THAT-MACHINE:8080/v1.
--device, --gpu-layers Where the model runs, when Inga’s own choice is not the one you want.
--like lmstudio Also answer LM Studio’s REST API on port 1234.

Good to know

Section titled “Good to know”
  • Thinking models (Qwen3 Thinking, gpt-oss, Qwen3.5): Inga sends the reasoning apart from the answer (reasoning_content) and the plugin shows the answer’s text, so the chat holds the answer alone (use-thinking-models.md).
  • Pictures: the plugin sends each message’s text; for a question about a picture, use Inga’s own web UI (chat-about-an-image.md).
  • Speed: the first message of a chat evaluates the whole prompt with the tools’ definitions; later ones reuse Inga’s KV cache, so only the new messages are computed.

Troubleshooting

Section titled “Troubleshooting”
  • The plugin’s answer is an error about the connection: Inga is not running, or listens elsewhere (inga serve prints its addresses when it starts); check the Override Base URL ends with /v1, and use 127.0.0.1 rather than localhost.
  • 401 from Inga (a line “API key refused” on the Logs page): the key in the plugin differs from --api-key, or is in the other key field (step 4).
  • “no model claude-sonnet-4-20250514 here; the models are: …”: Inga serves several models, and the plugin’s name is none of them; serve one (step 2).
  • Tool calls appear as text (<tool_call>... in the answer): the model’s chat template has no tools, or the model is too small; check inga info MODEL, try a larger model.
  • The prompt exceeds the context: raise --ctx.
