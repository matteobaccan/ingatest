Supported models

What Inga runs, by what the model files declare. To check a file before running it: inga info MODEL (any file), inga list (the Hugging Face cache), inga scan DIR (a folder tree) and inga search WORDS --supported (Hugging Face) all say supported or why not; so do inga list --ollama and inga list --lmstudio for the models Ollama and LM Studio downloaded. How to use them: find-models-and-check-support.md.

Real file, in the tables below: ✅ and a date when a real, public file of that row was checked against its reference program on the maintainer’s runner (the same tokens as llama-tokenize, perplexity within 1 % of llama-perplexity, both on the CPU; real-world checks, group A, 2026-10-15); synthetic only when only synthetic files were compared with the reference so far. The nightly rotation (rotation.json, docs/maintainer-checklist.md) turns these into real checks a slot a night; its current state is the issue “Real-file checks — tracking”. Besides the rows marked here, real files checked on 2026-10-15: the Q8_0, Q4_K and Q6_K weights (inside those files), every GGUF vocabulary of llama.cpp’s models folder (BPE, SPM, WPM, UGM), every chat template of llama.cpp’s models/templates, and the expert streaming of --mem-limit (Qwen3-30B-A3B, the same text as all in RAM). Speech, embeddings, image generation and the Hugging Face formats are synthetic only so far.

A model that is not here? Ask for it: the error message, the Hugging Face link and what you want to do with it are enough.

Diffusion language models

Section titled “Diffusion language models”

The answer is denoised from masks in a few steps, many tokens at once, instead of being written token by token; their attention is not causal. inga run and inga serve use them as any chat model (the answer comes when its blocks are final, not token by token); inga list, inga scan and inga info report them as supported (diffusion). See diffusion-language-models.md.
