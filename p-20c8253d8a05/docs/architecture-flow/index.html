How Inga's core behaves, model by model

Four flowcharts follow a model from its reference to a token: how inga run and inga serve find and open the file and recognise the model, where it runs (other machines, RAM, disk, GPU), what one pass on the CPU does, and the path of a request through the server. Every branch is a decision the code takes; the box names the file and the function, and the notes below give each one with its link. The design behind them is the design spec (§3 one step, §4 the placement plan); the models each family covers are in supported-models.md.

The diagrams are SVG files kept by hand in images/diagrams/, in the light or the dark scheme of the reader’s system. A change to one of the decisions below changes its diagram in the same pull request.

1. From a model reference to a loaded model

Section titled “1. From a model reference to a loaded model”

The reference. resolve_model (with resolve_model_or_offer for run) decides by what MODEL names:

  • ollama://name: Ollama’s store (resolve_ollama); run offers to pull a missing model on a terminal.
  • hf:// or ms://: the Hugging Face or ModelScope cache, downloaded when missing and refused in offline mode (crates/inga-hub/src/cache.rs, fetch.rs).
  • A models--org--repo folder of the Hugging Face cache: resolved like hf://org/repo, with a note (inga_hub::resolve_repo_folder).
  • Any other path: the file or folder as it is. LM Studio’s folder, Ollama’s store and the saved folders are found by inga scan and the library (crates/inga-hub/src/local.rs), which then give a path.

Then pick_or_convert takes the variant --variant asks for, or makes it while the original runs.

The format. inga_formats::open_model opens a folder or a config.json as a safetensors folder (open_dir: Hugging Face’s tensor names mapped to GGUF’s, MLX’s quantized weights converted by mlx.rs), a .safetensors file alone, a whisper.cpp ggml file, and anything else as GGUF (GgufFile::open: the parts of a split model joined and checked, tensors of unknown types listed). Each gives one GgufFile, memory-mapped, which Engine::load_converting turns into a model.

What the model is. general.architecture decides, in load_engine_only, ModelSpec::read (spec.rs) and support:

  • an image model (sd1, sdxl, sd3, flux, qwen_image): inga run refuses it and names inga image; inga serve loads it in its image slot (inga-diffusion);
  • speech to text (whisper, parakeet, cohere_asr): inga transcribe;
  • clip: a vision or audio projector, loaded beside a model by --mmproj or found next to it (load_vision in src/commands/mod.rs);
  • an encoder (bert, nomic-bert, Arch::is_encoder): embeddings and rerank in inga serve; inga run refuses it;
  • an architecture Inga does not know: the error names it, and says so when it is on the roadmap (inga_formats::not_yet);
  • a language model: its spec, tokenizer and chat template (Model::load).

A language model’s layers belong to the families of Arch in spec.rs: dense, mixture of experts (is_moe), gated DeltaNet hybrids (is_hybrid), Kimi delta attention (is_kda), Mamba-2 and its hybrids (is_ssm, is_mamba_hybrid), short convolution (is_shortconv), DeepSeek’s latent attention and its sparse variant (is_deepseek, is_sparse), and the diffusion language models (DiffusionArch). Diagram 3 shows where each runs.

2. Where the model runs

Section titled “2. Where the model runs”

Other machines. --nodes, --expert-nodes and --tp-nodes split the layers, the experts or the tensors with other machines (plan_pipeline, inga-dist); a mesh loads through mesh::load (src/commands/mesh.rs), and may have the prompts read by a prefill node. GPU layers do not combine with these yet (load_engine_only refuses --gpu-layers there).

The memory plan. Engine::prepare takes the RAM available, capped by --mem-limit; the experts are first converted or striped over disks when --quantize-experts, --experts-precision or --experts-dir ask. Plan::new adds the resident weights, the KV cache for --ctx and a fixed overhead (OVERHEAD), then:

  • everything fits: the weights stay memory-mapped in RAM;
  • a mixture of experts that does not fit: the experts go to disk (ExpertTier::Disk), read by positioned reads into a cache of at least n_expert_used experts evicted by recency and frequency (experts.rs); --prerouter picks the experts read ahead (prerouter.rs) and --pin-experts keeps those earlier runs used most (hot_experts in src/commands/mod.rs);
  • otherwise (a dense model, or experts that do not fit even so): the layers are streamed from disk (stream_layers), the next layer’s mapping advised WILLNEED and the current one DONTNEED.

The device. candidates orders the GPUs. --device cpu, --gpu-layers 0, an option a GPU cannot run yet (cpu_only_why) or no GPU found leave every layer on the CPU, whose weights are then repacked in groups of eight rows (Engine::repack, repack.rs; --no-repack keeps them as stored). Under auto the order is CUDA, then Metal, then Vulkan, discrete GPUs first and the most free memory first, an integrated GPU only when there is no other, HIP only when named; --device NAME takes that device, a list splits the layers across them. fit_with puts the last layers on the GPU first, the output layer once every layer fits, and the routed experts from the last layer back (place_experts, --experts-on, --cpu-moe). An upload that runs out of memory is made again with fewer layers (upload_fitting); a GPU whose kernels lack a weight type or the architecture passes to the next one (try_each). Then Engine::plan_after_gpu gives the RAM the GPU took over to the experts the CPU runs, and the placement map (placement::of_model) is printed.

The KV cache. f16 by default, q8_0, q4_0, q5_0 or q4_K with --cache-type (inga_core::KvType), on the device of its layer. In inga serve the sessions share one prefix cache, and with --kv-pages the pages of a GPU’s caches (pool.rs); --kv-ram keeps only the newer blocks in RAM, and --kv-disk holds the prefix cache’s copies and the parked conversations (kv_disk.rs).

3. One token on the CPU

Section titled “3. One token on the CPU”

The prompt and the threads. Session::generate_with_stop reuses the prefix already in the KV cache (use_prefix_cache: in RAM or from --kv-disk), always processing at least the last prompt token. A pass of one token runs on one thread per physical performance core, a longer one on every logical CPU (topology.rs: decode_threads, prompt_threads; CpuBackend::jobs in backend.rs). A single token’s products share one encoded activation (matmuls), several tokens’ run as tiled matrix products (CpuBackend::prefill). The attention takes tiles of up to 16 tokens when the tokens are at least four times the threads (attention::prefill), else one token and KV head per task (attention::per_token, attention.rs).

Every layer. Model::run_layers sends a layer the plan put on a GPU to its stage, the hidden state copied where the device changes. On the CPU, Model::layer_forward picks the mixer: a layout of its own (DeepSeek V4, Kimi K3, Qwen4exp, GLM-5 next, Gemma 4 and 3n), a Mamba-2 mixer (ssm_layer, mamba.rs), gated DeltaNet or Kimi delta attention (delta_forward, kda.rs), LFM’s short convolution (shortconv.rs), or attention (attention_block: latent attention for DeepSeek, mla_qkv, with the sparse indexer’s positions where there is one; else grouped-query attention with RoPE or M-RoPE). Model::ffn_block then runs a dense network (plain_ffn) or the experts (moe_forward): the router’s top-k read in place from RAM, or through the expert cache from disk with the next layer’s experts read ahead (NextExperts, by the next router or the prerouter), multiplied on a CUDA or Vulkan GPU for a prompt when it pays (gpu.op_offload, offload.rs), or run by the machine of --expert-nodes that holds them.

The next token. The output layer gives the logits (Model::forward_step). When it runs on a GPU that samples, only the drawn token comes back (Step::Token); else the sampler applies the penalties, top-k, temperature, min-p, top-p, XTC or mirostat, and draws with Gumbel noise keyed by the seed and the position (Philox). Speculative decoding is on unless run.speculative = false (speculative.rs): Session::speculate_by_default drafts with the model’s multi-token prediction block, else an EAGLE-3 head, else prompt lookup, and SpecGate pauses the drafts while they do not make decoding faster; --draft MODEL and --lookup N choose a drafter by hand.

The kernels. One kernel table per instruction set, chosen at start the fastest first (Isa::best: AVX-512, AVX2, SSE4.1; NEON with i8mm, with dotprod, NEON; SIMD128; scalar). The weights repacked at load are read eight rows at a time (kernels/packed.rs). An f16 KV cache in RAM is read by blocks of 16 positions laid out straight from their f16 bits (keys_f16, values_f16, F16C on x86-64); a quantized cache is converted row by row.

4. A request to inga serve

Section titled “4. A request to inga serve”

A thread per connection reads the request (crates/inga-server/src/lib.rs, http.rs, one file per API); pictures and videos go to their slots (slots.rs). An answer in the response cache (--response-cache, response_cache.rs) is given again. State::resolve sends a request for an API node or a route to the other servers (routing.rs); for a local model the router loads it on its first request and unloads the least recently used one past models_max, --vram-evict or its idle time. Pool::acquire takes the free session holding the longest prefix of the prompt, or queues the request (admission.rs: a 503 past --max-queued-requests or --max-queued-tokens). The model’s worker thread runs the job as in diagram 3, the decode steps of several sessions in one pass (Batcher), and sends Prefill, Text and Done events; State::relay passes them on and looks every RELAY_TICK whether the client left (the job then stops, a 499). The stream is server-sent events, with a keep-alive after a silence of keepalive::EVERY (keepalive.rs).

What the diagrams leave out

Section titled “What the diagrams leave out”

The GPU backends’ own passes (CUDA, Vulkan, Metal, HIP), the WebAssembly build’s streamed layers, the tensor-parallel and pipeline protocols of the mesh, the image and video pipelines of inga-diffusion after their slot, speech, tools, documents and web search. Their designs are indexed in superpowers/specs/.
