Command-line reference

<model> is a GGUF file (the first part of a split model), a Hugging Face model directory (config.json, *.safetensors, tokenizer.json) or hf://<org>/<repo>[@<revision>][:<quant>|/<file.gguf>] (default quantization Q4_K_M), taken from the Hugging Face cache or downloaded into it, or ollama://<name>[:<tag>], a model of Ollama’s library already on this machine (inga run offers to pull a missing one on a terminal). For image (and serve of an image model) it is a Stable Diffusion or SDXL checkpoint: one .safetensors file (hf://<org>/<repo>/<file.safetensors>), a GGUF file, a diffusers folder, or a UNet alone whose VAE and text encoders come with --vae, --clip-l, --clip-g (the UNet may also be given with --diffusion-model and no <model>). inga --help lists the commands, one line each; inga help <command> [action] (also inga <command> --help and inga --help <command>) prints a command’s whole help: what it does and what Inga decides by itself, every option grouped with its default, its inga.toml key and its effect, examples from the simplest to the advanced, and the related commands and guides (inga help run, inga help mesh key; a mistyped name gets “did you mean”). The tables below are a summary; inga completions bash|zsh|fish|powershell sets up tab completion.

Commands

Section titled “Commands”
Command What it does Example
info <model> Architecture, tensors, memory needs, speed estimate, whether Inga runs it inga info model.gguf --json
run <model> Interactive chat, or one answer with -p inga run model.gguf -p "Why is the sky blue?" -n 128
serve [model]... OpenAI, Anthropic, Ollama, LM Studio and KoboldAI APIs plus the web UI; with no model, the web UI loads one inga serve a.gguf b.gguf --models-max 2, inga serve
bench <model> Prefill and decode speed, as llama-bench; -d N from N cached tokens (a long chat), --ab KEY=VALUE the default against the path a key of inga.toml selects, with the same output checked (debug.moe_grouped=false: the next token’s distribution, within 0.1 nats); --ctx-sweep 2K:32K:2K the prompt and generation speed at each context frontier (--csv in ds4-bench’s columns); --speculative generation from a code edit and a chat question with the default speculative decoding (--ab run.speculative=false: on against off); --decide Q a decision of Q questions against the state’s prefill alone inga bench model.gguf -t 1,4,8, inga bench model.gguf -d 4096 -p 512, inga bench model.gguf --ctx-sweep
perplexity <model> -f FILE Perplexity on a text, KL divergence to another run inga perplexity model.gguf -f wiki.test.raw
eval <model>... --set S How well models or their variants answer question sets: the score per category (exact answers, multiple choice, numbers, regular expressions; open answers graded by a --judge model with a rubric), the speed and the memory, kept in ~/.cache/inga/evals; built-in samples math, knowledge, code, writing or your own JSON-lines file; --results lists the evals kept, --leaderboard ranks the models of the web UI’s arena per category inga eval a.gguf b.gguf --set math --set knowledge, inga eval model-F16.gguf --variant original --variant q4_k_m --set my-questions.jsonl, inga eval --leaderboard
profile <model> --text FILE The importance matrix of a calibration text, as llama-imatrix collects it (also in its GGUF format), and the use profile of a mixture’s experts; --prerouter also trains the prerouter (the next layer’s experts from the hidden state, for --prerouter) inga profile model.gguf --text calibration.txt -o imatrix.gguf
imatrix <model> -f FILE The importance matrix of a calibration text, as llama-imatrix collects it, in its GGUF format: kept for the model (the i-quants use it) and written to -o OUT inga imatrix model-F16.gguf -f calibration.txt -o model.imatrix
tokenize <model> -p TEXT The model’s tokens for a text inga tokenize model.gguf -p "hello" --ids
finetune <model> --data FILE A LoRA adapter of a small dense model (Llama, Mistral, Qwen2, Qwen3, SmolLM, Phi-3) trained on the CPU from a JSONL dataset (text, prompt / completion or chat messages, the assistant turns learnt), written in llama.cpp’s adapter GGUF for --lora; checkpoints and --resume; --teacher M distils from the full-precision model instead (Recover-LoRA) inga finetune qwen3-0.6b.gguf --data chats.jsonl -o my-lora.gguf --epochs 3, inga run qwen3-0.6b.gguf --lora my-lora.gguf
quantize <model> OUT --type T A quantized GGUF file, byte for byte the one llama-quantize writes (also safetensors to GGUF), with --imatrix FILE too (the i-quants IQ2_XXS … IQ4_XS, and the k-quants weighed by it); --token-embedding-type T and --output-tensor-type T give those two matrices a type of their own (with --allow-requantize, only they are rewritten in a quantized file) inga quantize model-F16.gguf model-Q4_K_M.gguf --type q4_k_m, inga quantize model-F16.gguf model-IQ2_XS.gguf --type iq2_xs --imatrix model.imatrix
merge MODEL... -o OUT Fine-tunes of one base merged into one GGUF model as mergekit merges them (--method linear, task_arithmetic, ties, dare_ties, dare_linear, slerp; --weights, --density, --t), streamed tensor by tensor, quantized inputs dequantized and the result quantized to --type; mergekit’s YAML / JSON recipes (--config: gradients over the layers, filters, a mixture’s experts layer by layer); LoRA adapters merged in (MODEL+ADAPTER, --lora); --moe makes the fine-tunes the experts of a mixture (Llama, Mistral, Qwen3), its router from --prompts; --eval SET measures it against its parents inga merge base.gguf coder.gguf writer.gguf --method ties --density 0.5 -o merged.gguf, inga merge base.gguf coder.gguf writer.gguf --moe --prompts code.txt --prompts prose.txt -o 2x.gguf
optimize <model> A variant of the model (the file inga quantize writes, kept in ~/.cache/inga/cache/models, the original untouched): the one Inga proposes for this machine (planned on the GPU’s memory, the RAM and the disk), or --type T; a stopped conversion resumes from its next missing layer; --while-running makes it while the model next runs; --check measures a variant against the original (perplexity ratio, KL divergence, same top token); --variant T on run, serve, bench and info runs it, remembered per model inga optimize model-F16.gguf, inga optimize model-F16.gguf --check --variant q4_k_m, inga run model-F16.gguf --variant q8_0
image <model> -p TEXT An image from a prompt with Stable Diffusion 1.x / 2.x, SDXL, SD-Turbo, SDXL-Turbo, SD 3.x, Flux.1 or Qwen-Image, as a PNG file; a picture edited with --init-image FILE (--strength X: how much is redrawn) and only where --mask FILE is white (inpainting) inga image sd_turbo.safetensors -p "a red fox" -o fox.png, inga image sd_turbo.safetensors --init-image photo.jpg --mask sky.png -p "a stormy sky"
video <model> -p TEXT A clip from a prompt with Wan 2.1 text to video (with --vae, --t5xxl; or a diffusers folder), as an animated GIF, APNG or Y4M file; impractical on a CPU beyond tiny sizes inga video wan2.1_t2v_1.3B_fp16.safetensors --vae wan_2.1_vae.safetensors --t5xxl umt5-xxl-encoder-Q8_0.gguf -p "a cat on the grass" --width 256 --height 256 --frames 17 --steps 8 -o cat.gif
locate IMAGE QUERY --model M Objects found in a picture by LocateAnything-3B (locate-anything.cpp’s GGUF file or the Hugging Face directory): a box per object in pixels, as text or --json, drawn on a PNG copy with -o inga locate street.jpg "person, car" --model locate-anything-q8_0.gguf -o boxes.png
transcribe FILE --model M Speech to text with Whisper, Parakeet or Cohere Transcribe (picked by the file): text, SRT / VTT subtitles or JSON, the language detected or given, --translate to English (Whisper), --stream the text as it is said (-: a microphone’s PCM on the standard input) inga transcribe talk.mp3 --model ggml-large-v3-turbo.bin --output srt
speak <model> [TEXT] Text to speech with an OuteTTS model and the WavTokenizer vocoder (llama.cpp’s llama-tts files) into a WAV file or raw PCM; --voice / --save-voice keep a voice, --language it reads numbers in Italian inga speak OuteTTS-0.3-500M-Q8_0.gguf "Hello" -o hello.wav
watermark <model> -p TEXT Whether a text carries Inga’s watermark inga watermark model.gguf -f answer.txt
decide <model> --state FILE --questions FILE Typed answers read from the logits, as TypeSafe AI’s Jev: a choice, a score or a yes / no per question, with each answer’s probability and a confidence (--json: Jev’s response; --permute N against order bias); decide calibrate --data FILE fits a temperature per question on labelled examples, kept in ~/.cache/inga/decide inga decide model.gguf --state ticket.txt --questions q.json, inga decide calibrate model.gguf --questions q.json --data examples.jsonl
worker Run layers, experts or tensor slices of a model for a coordinator on another machine inga worker --host 0.0.0.0
satellite A node of the Inga mesh: found by the master (mDNS or --peers), it runs the layers the master sends it, no model needed inga satellite --mesh home
mesh show The nodes of an Inga mesh: the master and why, resources, what each runs, the links, then the API nodes saved on this machine (--json) inga mesh show --mesh home
mesh handover The master hands its place to another inga serve --mesh node (the suggested master), which then splits its models across the mesh inga mesh handover DESKTOP-1VFB0M9 --mesh home
mcp <action> list, test, tools, approve, revoke, login, logout: the MCP servers of ~/.cache/inga/mcp.json (or --mcp FILE): listed without starting anything, connected and tested, their tools, resources and prompts; a stdio server’s command approved once (shown in full) or the approval taken back; a server that wants OAuth signed in (the address to open is shown, the browser comes back to a port on 127.0.0.1) or out (--json) inga mcp tools, inga mcp approve files, inga mcp login notion
mcp serve Inga’s memory (remember, recall, forget) as a stdio MCP server for Codex, Claude Desktop and other agents, through a running inga serve’s /mcp (--url, --api-key; also client.url, client.api_key) codex mcp add inga -- inga mcp serve
setup A first model that fits this machine (the six Qwen3 sizes, checked here before the download), downloaded, loaded and asked a first question; --voice, --embeddings add those models, --json lists the choices; inga alone runs it on a terminal of a machine with no model (run.setup = false turns it off) inga setup
pull <hf://...> Download a model into the Hugging Face cache (--offline refuses) inga pull hf://Qwen/Qwen3-0.6B-GGUF:Q8_0
pull <ollama://...> Download a model of Ollama’s library (ollama://[registry/][namespace/]name[:tag]) into Inga’s Ollama store, ~/.cache/inga/ollama (--ollama-store: into Ollama’s), each blob’s SHA-256 checked; prints its licence’s first line inga pull ollama://qwen3:0.6b
pull [words] On a terminal, a picker: the Hub’s models filtered while typing, a repository’s files with whether each fits this machine, the marked ones downloaded inga pull qwen coder
list The models in the Hugging Face cache (--lmstudio: LM Studio’s; --ollama: Ollama’s), whether Inga runs them, and where each goes here and how fast (measured once run) inga list --ollama
rm <hf://org/repo> Delete a model from the Hugging Face cache (short for data rm) inga rm hf://Qwen/Qwen3-0.6B-GGUF
download-dir [PATH] The download folder (the Hugging Face cache pull, the web UI and hf:// use): where it is and why, its free disk and the other disks (--json); with PATH, kept as the download folder in settings.json (HF_HUB_CACHE and HF_HOME win); --move moves the models there first (copied, checked, then removed; renamed on one disk; --repo ORG/REPO for some); --reset inga download-dir D:\HF --move
data What Inga keeps on disk — models, model variants, converted experts, expert profiles, saved prompts, settings, memories, collections of documents, shared chats, evals and arena votes, the results of scheduled tasks — with sizes and the free disk, and the variants not run for 30 days; data list [kind], data rm ID..., data clear KIND|--all [--yes] (asks first unless --yes); --json for the summary and list inga data list experts
scan [dir] The models under a folder tree, and whether Inga runs them inga scan D:\LLM --supported
search <words> GGUF models on Hugging Face with their architecture, support and whether they fit this machine (--fits, --sort fit, --no-fit; -i: the picker of pull [words]) inga search qwen3 --sort fit --supported
devices The GPUs CUDA, Vulkan, (on a Mac) Metal and (with ROCm’s runtime) HIP report, whether Inga can use them and which one --device auto picks; --test runs a tiny model (or --model FILE) on each one and on the CPU and compares their logits and speed; --json inga devices --test

Chat commands (typed in inga run's chat)
Command What it does
/help [COMMAND] (/?) The commands, one line each; /help set shows one with an example
/clear Start a new conversation; the system prompt and the settings are kept, the attached files dropped
/compact [show] Summarize the older turns into the system message to free the context, the last exchange kept; show prints the summary
/undo Remove the last exchange (your message and its answer); again to go further back
/retry Ask the last message again with the current settings (a new seed when sampling, unless /set seed fixed one)
/system [TEXT|off] Set the system prompt for the rest of the chat; alone, show it; off, remove it
/set NAME VALUE Change a setting for the next answers: temperature, top-p, top-k, min-p, repeat-penalty, presence-penalty, frequency-penalty, seed, max-tokens, ctx-shift on|off, checked as their command-line options; /set alone lists them with their values and sources; /set NAME default restores the model’s recommendation or Inga’s default
/show The model (architecture, quantization, parameters, size), where it runs, the settings and where each comes from (option, model, /set, default), thinking, web search, the system prompt, the context used, the files waiting
/stats The last answer’s prompt and answer tokens, time to the first token, speeds and the context used; the same summed over the chat
/think on|off Turn a thinking model’s reasoning on or off for the next answers (over --think)
/web on|off Web search for the next answers, when the chat started with --web-search
/image FILE Add an image (PNG, JPEG) to the next message; a path may hold spaces or be quoted
/audio FILE Add a recording (WAV, MP3, FLAC) to the next message
/video FILE Add a video (animated GIF, MJPEG, a directory of frames) to the next message
/files [clear] The files attached to the next message; clear drops them
/save FILE Save the conversation’s messages as JSON
/load FILE Replace the conversation with messages saved by /save (--history FILE at start)
/exit (/quit, /bye) End the chat (so does the end of the input, Ctrl-D / Ctrl-Z, or Ctrl-C twice at the prompt)

A command may be shortened to any unambiguous prefix (/sa is /save) and is matched whatever its case; an unknown or ambiguous one is never sent to the model (it says so and points to /help). //text sends /text to the model. A line made of """ starts a multi-line message, ended by another """ line; a line ending with \ goes on to the next; text pasted in a terminal stays one message. Ctrl-C while an answer is written stops it and keeps what was written in the chat; at the prompt it clears the line. The commands answer on stderr, so stdout keeps only the answers. They work only in the chat, not with -p. Spec: the terminal chat’s commands.

Speed and memory
Option Meaning
-t, --threads N CPU threads of prompts and generation (prompts: every logical CPU; generation: one per physical performance core)
--threads-decode N CPU threads of generation only, at most -t
--ctx N Context size in tokens (4096, capped at the model’s)
--batch N Process prompts in passes of at most N tokens (2048)
--cache-type f16|q8_0|q5_0|q4_0|q4_k KV cache storage (q8_0 halves it; the 4-bit types, rotated by a Hadamard transform, take a quarter to a third)
--cache-cap N A KV cache of N tokens that never fills
--kv-ram SIZE Keep at most SIZE of a context’s KV cache in RAM, the older blocks on disk in --kv-disk (same output, at the disk’s speed)
--kv-disk DIR Where KV caches go on disk (auto: ~/.cache/inga/kv); with serve, the conversations that leave the RAM too
--mem-limit SIZE Use at most SIZE of RAM (e.g. 8G); the rest is read from disk
--quantize TYPE Convert F32/F16/BF16 weights while loading: q8_0, q2_k … q6_k, iq2_xxs … iq4_xs, q1_0, q2_0; an MLX model’s quantized weights are converted straight to TYPE
--imatrix FILE The importance matrix --quantize and --quantize-experts weigh each column’s error with (inga imatrix); the i-quants take the one kept for the model by default
--variant T|original Run a variant made by inga optimize (q8_0, q4_k_m, …) or the original; remembered per model in ~/.cache/inga/settings.json (also serve, bench, info). A variant not made yet of a model larger than the RAM is made while it runs, each layer converted as it is read. serve: --variant MODEL=T picks per model (repeatable)
--quantize-experts TYPE, --quantize-down TYPE Re-quantize an MoE model’s experts, once: kept in ~/.cache/inga/cache/experts for the next loads
--experts-precision auto|off, --experts-warm TYPE, --experts-cold TYPE An MoE model whose experts do not fit in RAM: the most used experts stay at the model’s precision (hot), the next are converted to the warm type (q4_k, or q3_k / q2_k for a source of fewer bits: the first that saves a bit per weight; none, nothing converted) in RAM, the rest to the cold type (the warm one) on disk, sized to the free memory; off by default, as it changes the output
--pin-experts N Keep the N most used experts in memory (each mixture’s use profile, uses and router weights per expert, is kept in ~/.cache/inga/experts)
--collect-imatrix While running, add the importance matrix (the squared inputs of every matrix column, as llama-imatrix) to the one kept in ~/.cache/inga/experts; off by default
--mirror DIR Copies of the model on other disks, read in parallel
--prerouter Experts read from disk: the experts read ahead are picked by the prerouter inga profile --prerouter trained for the model, not only by the next layer’s router (also serve, bench); the output does not change
--experts-dir DIR Stripe the routed experts over the disks of these directories (repeatable): each holds a share, written once (converted with --quantize-experts), each expert read from its own disk
--no-repack Keep the weights as stored: Q4_K, Q8_0, Q4_0, Q4_1, Q5_0, Q5_1 and IQ4_NL matrices are otherwise rearranged by groups of eight rows when loading (x86-64 with AVX2 or AVX-512), for faster products in the same memory
--lora FILE, --lora-scaled FILE X Apply LoRA adapters
--control-vector FILE[:X], --control-vector-scaled FILE X, --control-vector-layers A-B Steer the answers with control vectors (llama.cpp’s GGUF format): each direction, times X, added to the residual stream after its layer; only layers A to B with --control-vector-layers (on the CPU)
--max-gpu-load PCT Let the device (GPU or CPU) work at most PCT % of the time, resting after each pass: cooler and quieter, at about PCT % of the speed (also bench; gpu.max_load)
--draft MODEL, --lookup N, --draft-n N Speculative decoding with a draft model or prompt lookup
--draft-eagle FILE Speculative decoding with an EAGLE-3 draft head of the model (llama.cpp’s eagle3 GGUF or a Hugging Face directory; one beside the model is found without it; also serve)
--no-speculative No speculative decoding by default (otherwise the model’s MTP block, an EAGLE-3 head, or prompt lookup guesses tokens while that makes decoding faster; also run.speculative=false)
--offline Never use the network
GPU (run, serve, bench, info, perplexity)
Option Meaning (default)
--device auto|cpu|cuda[:N]|vulkan[:N]|metal[:N]|hip[:N] Where the layers run (auto: the best usable GPU, CUDA first, then Metal on a Mac, then a Vulkan GPU that is not software; a discrete GPU, an integrated one only when there is no other; never HIP, which is named; with as many layers as its free memory holds, the rest on the CPU; the CPU alone, with the reason, when no GPU can run the model); cuda[:N] / vulkan[:N] / metal[:N] / hip[:N]: that GPU or an error; a list such as cuda:0,vulkan:1 splits a dense model’s layers between those GPUs of this machine (any mix of CUDA, Vulkan, Metal and HIP), the first taking the earliest, the hidden state copied from one to the next; a mixture of experts, a hybrid model (DeltaNet: Qwen3.5 and later) or a Mamba-2 model runs on one GPU, named alone. gpu.device does the same

--experts-on auto|gpu|cpu A mixture of experts’ routed experts: auto puts whole layers’ experts on the GPU from the last layer back, as many as the memory left after the attention, the shared experts and the output layer holds; gpu: all of them or an error; cpu: none (auto)

Configuration file

Section titled “Configuration file”

Settings you want every time go in inga.toml, a TOML file: --config FILE, else ~/.cache/inga/inga.toml (in the --home DIR folder when one is given), else /etc/inga/inga.toml (%ProgramData%\Inga\inga.toml on Windows). inga config init writes it with every key commented out; uncomment what you need:

A flag wins over the file, which wins over the default; --set KEY=VALUE sets any key for one run (inga serve model.gguf --set gpu.device=cpu) and --home DIR moves Inga’s files. inga config show lists every key with its value and where it comes from. Every key, its flag and its default are in docs/config.md.

No environment variable sets Inga’s settings: every one is a key of the file or a flag (device in [gpu] or --device, vk_tiles in [debug], …; the home is --home DIR or home). The INGA_* variables of earlier versions are gone, and Inga ignores them.

Environment variables (other programs')

Inga honours the standard variables of the tools it shares files and networks with:

Variable Meaning

HF_HUB_CACHE, HF_HOME The Hugging Face cache (~/.cache/huggingface/hub); they win over inga download-dir
HF_ENDPOINT A Hugging Face mirror
